# 10. UX 재설계: 매일 하는 일 먼저, 예외는 그 안의 표시로 (2026-11-10)

사용자 지적: 화면이 드물게 일어나는 예외 위주라서 이상하다. 근거 조사(`docs/검토/화면재설계/08_업무용UI_가이드.md`, `09_의료사용성.md`)를 바탕으로 다시 설계한다. 아래 인용은 원문을 직접 확인했다.

## 원칙 (근거)

1. **첫 화면은 가장 자주 하는 일로 연다.**
   - NN/g Progressive Disclosure: "You have to disclose everything that users frequently need up front."
   - NISTIR 7804: "Dialogues should not contain information that is irrelevant or rarely needed."
2. **예외는 평소 목록 안의 표시로 둔다.** 예외는 해당 행에 배지로 붙이고 위로 정렬한다. 예외만 보는 것은 필터로 둔다.
   - Stephen Few: "high-level summaries, including exceptions", "When everything is visually prominent, nothing stands out."
3. **화면을 막는 경보는 안전에만 쓴다.**
   - AHRQ PSNet: "Make only high-level (severe) alerts interruptive."
   - NISTIR 7804: 경보 피로는 안전 문제다.
4. **같은 종류의 항목은 표로 보인다.** 카드는 종류가 다른 항목에만 쓴다.
   - NN/g: "Card layouts are less scannable than lists."
5. **전체 상황은 한 줄로 늘 보이게 하고, 비교 기준을 붙인다.**
   - Endsley의 "Support Global SA".
   - Few의 "Compared to what?"
   - 큰 숫자 카드 여러 개 대신 한 줄 요약으로 둔다.
6. **상세와 처리는 같은 화면의 옆 패널에서 한다.** 공개 깊이는 2단계까지만 둔다(NN/g 복잡한 업무 앱 지침, 비모달 옆 패널).
7. **정상인 날(확인할 것 0건)을 정상 화면으로 설계한다.** 그날 자동으로 처리된 것을 보여 준다(NN/g empty state "Communicate system status").
8. **시연은 실제 화면에서 과업 하나를 직접 해 보는 안내로 만든다.** 슬라이드처럼 읽어 주는 방식은 쓰지 않는다.
   - NN/g: "Tutorials interrupt users, don't necessarily improve task performance, and are quickly forgotten."

## 역할별 첫 화면

| 역할 | 첫 화면 (매일 하는 일) | 예외가 있는 곳 |
|---|---|---|
| 원무팀 | **오늘 입원**: 오늘 들어올 환자 전부. 열은 수속 시각, 환자, 진료과, 배정 병상과 병상 상태, 누가 배정했는지, 연락 상태, 입실 | 행 배지(병상 없음, 재연락 승인, 1인실 동의, 병동 의견)와 위쪽 정렬, '확인 필요만' 필터. 처리는 옆 패널 |
| 병동 책임간호사 | **우리 병동**: 병상 현황과 오늘 입실·퇴실 예정 | 병상과 행의 표시, 위쪽에는 건수만 |
| 감염관리실 | **격리 환자 명단**: 입원 예정, 재원, 퇴원 진행으로 묶음. 옆에 격리 가능 병상 요약 | 해당 환자 행의 '병상 결정' 배지와 마감, 위쪽 정렬. 결정은 옆 패널. 종말소독은 병상 상태로, 밤사이 기록과 인계는 보조 탭으로 |
| 관리자 | **오늘 흐름**: 수용과 수요, 구간별 시간, 안전 검사 | 되돌림, 사람 확인 횟수 같은 추세. 개별 건은 드릴다운 |
| 시연 | 실제 원무 화면에서 과업 하나(예: 에이전트 확정 확인, 입원 안내 기록)를 직접 해 본다 | |
