# 평가표

재생 평가 하네스가 재는 지표와 합격 기준이다. 근거와 검수 의견은 `docs/평가체계_검수.md`, 채택 이유는 `docs/DECISIONS.md`(2026-11-08 평가 골격 앞당김)에 있다. 모든 수치는 합성 데이터 기준 추정이며 병원 발표 수치와 비교하지 않는다.

## 원칙
1. **지킬 선과 보고 지표를 나눈다.** 지킬 선(0건, 100%)은 넘으면 자동 경로를 멈춘다. 보고 지표는 추세만 본다.
2. **안전 지표는 분모와 신뢰 상한을 함께 적는다.** 시드 0~199 스윕. 0건이면 3의 규칙으로 95% 상한 = 3/분모.
3. **가정에서 나온 효과는 성공 기준이 아니다.** 운영 지표(O1)는 개입 가정 ID와 0.5배·2배 민감도와 함께 보고한다.
4. **정답 라벨은 생성기와 독립이다.** 생성기는 입력만 만들고, 라벨은 설계 문서 규칙에서 도출한다. Claude가 초안을 쓰고 사용자가 검토해 승인한다(`status: approved`). 판정 검사기는 평가 대상 코드와 다른 구현이다.
5. **가짜 LLM은 파이프라인 검증용이다.** 반복 일관성(C1)과 모델 비교(M1)는 실제 모델에만 보고한다. 가짜 LLM은 관찰값만 보고, `src/`에 시나리오 ID가 있으면 테스트가 실패한다.
6. **비교 기준선은 둘이다.** 에이전트 없음(생성기의 기존 방식 시각)과 규칙 모드(LLM 없이 결정적 규칙만).

## 데이터 분리
- **개발용**: 시드 0~199, `evals/scenarios/dev/` 30개.
- **홀드아웃**: 시드 10000 이후, 분포를 바꾼 설정(P90 +30%, 보호자 지연 비율 변화), 예외가 겹치는 변형. 마일스톤(4단계, 7단계 끝)에 만들고 그때만 돌린다. 실행 횟수를 RESULTS.md에 남긴다.

## 결과 기록
실행마다 `evals/results/<날짜>_<커밋>.json`을 만든다. RESULTS.md에는 요약 한 줄(날짜, 커밋, 시나리오 세트 해시, 데이터 분리, LLM, 정책 버전, 안전 지표 건수/분모, 통과 수/30, 운영 지표와 가정 ID)을 스크립트로 추가하고 손으로 고치지 않는다.
