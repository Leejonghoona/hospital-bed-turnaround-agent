# 문제 정의서 (기회 진단)

- 작성일: 2026-11-09. 상태: 초안. 형식 근거: Cagan 기회 평가(문제, 대상, 크기, 대안, 왜 지금, 권고), Torres 기회 나무(00 문서 2절, 검색 요약 수준).
- 근거 문서: `docs/병상턴어라운드_설계.html` "진단" 절, `docs/DECISIONS.md`(엔드픽처, 사용자 결정), `docs/검토/업무현실검증.md`, `docs/RESULTS.md`.
- 수치는 합성 데이터 기준 추정이다. 병원 발표 수치와 비교하지 않는다.

## 결론 먼저

- **문제**: 환자가 퇴원해도 침대는 바로 비지 않는다. 퇴원약, 수납, 보호자 도착, 퇴실, 청소, 병동 수용, 원무 확정이 서로 다른 부서와 화면에서 따로 돈다. 단계 사이의 "다음 사람에게 넘기기"를 아무도 한 사례로 묶어 보지 않는다. 그 사이 다음 환자는 기다리고, 병상관리 담당은 전화로 조율한다.
- **누구의 문제인가**: 1차로 병상관리 담당(주간 원무 입원 파트, 야간은 당직 원무. 설계 가정 A1·A2)과 병동 책임간호사. 결과로 다음 입원 환자와 보호자.
- **기회**: 배정 자체는 이미 여러 병원이 자동화했다. 남은 기회는 **배정 앞뒤의 조율 노동**이다. 퇴원 확정부터 다음 환자 입실까지 단계 사이 지연을 이벤트로 추적하고, 안전 검사를 코드로 통과한 제안만 실행하며, 사람은 책임질 순간(공식 확정, 환자 연락, 안전 예외)에만 부른다.
- **권고**: 진행(1단계 합성 MVP는 완료). 다음 결정 전에 **현직자 검증**(05 문서 가정 A1~A7)이 먼저다. 역할 가정이 틀리면 주 사용자와 화면 수신자가 바뀐다.

## 1. 문제 진술

> 병상관리 담당은 퇴원 예정 병상이 **언제 실제로 쓸 수 있게 되는지** 모른 채 다음 환자를 배정하고 연락한다. 단계별 진행은 약제, 원무, 병동, 환경이 각자 알고, 지연은 누군가 전화할 때 드러난다. 그래서 병상은 준비됐는데 비어 있거나, 환자는 연락을 받았는데 병상이 준비되지 않는다.

### 1.1 근거 (설계 문서 "진단"에서 가져옴, 출처 수준은 원 문서 표기를 따름)

| 관찰 | 출처 | 이 문제와의 관계 |
|---|---|---|
| 정규 퇴원은 전날 주치의가 결정한다. 퇴원약, 진료비 심사, 수납, 퇴실, 정리를 거쳐야 병상이 다시 쓰인다 | 서울아산·한양대 입퇴원 안내(1차) | 단계가 여러 부서에 걸쳐 있다 |
| 병실이 부족하면 입원 당일 정오경 환자에게 입원일 변경을 연락한다 | 서울아산병원 입원진료절차안내(1차, DECISIONS에서 원문 확인) | 병상 준비 시각을 모르는 비용이 환자에게 간다 |
| 퇴원 처방 수정이 재조제와 퇴원 지연을 부른다. 수정률 15~16%에서 9%로 줄인 사례 | 데일리팜 2021, 서울성모 약제부(2차) | 퇴실 전 구간 지연의 한 원인 |
| 배정 담당자가 퇴원 환자 목록, 병동 현황, 입원 예정자, 응급실 목록을 일일이 파악했다(자동화 전) | 전자신문 2020(2차) | 조율 노동이 크다 |
| 자동 배정 완료율 90.8%(인천세종, 88일) | 라포르시안 2026(DECISIONS에서 원문 확인) | "첫 배정" 한 단계의 수치. 사이클 전체 조율은 여전히 사람이 한다 |
| 퇴원 예정 미등록 알림, 청소 요청·완료 전산 관리, 단계별 지연 추적을 공개한 국내 자료는 찾지 못했다 | `docs/검토/업무현실검증.md` Q2 | 빈칸이거나, 공개되지 않았거나. 현직자 확인 필요(가정 B3, A4) |

### 1.2 문제가 아닌 것 (오해 방지)
- **배정 알고리즘이 나쁘다는 것이 아니다.** 서울아산, 세종, 가천대 길, 분당서울대가 이미 자동 배정을 운영한다(SPEC POS-5). 배정 규칙은 재사용한다.
- **청소가 느리다는 것이 아니다.** 청소와 소독 인력 배치는 환경 부서 권한이다(CLAUDE.md 4번). 이 제품은 요청 시점과 완료 신호만 다룬다.
- **HIS가 부족하다는 것이 아니다.** 병상 원장과 확정은 HIS에 있다(SPEC POS-1).

## 3. 기회 크기 (합성 데이터 기준 추정)

실데이터가 없으므로 "병원에서 얼마를 아낀다"는 쓰지 않는다. 대신 **합성 병원의 기존 방식 기준선**(에이전트 없음)으로 문제의 모양을 보인다. 출처는 `docs/RESULTS.md`(시드 0~199, 퇴원 6,000건)와 `docs/DECISIONS.md` MA-14다.

| 기존 방식 지표 (합성) | 값 | 읽는 법 |
|---|---|---|
| 퇴실 시각 P50 / P90 | 13:03 / 15:07 | 대부분 오후에 나간다 |
| 정오 전 퇴실 비율 | 18.6% | 오전 입원 수요와 어긋난다 |
| 퇴실부터 병상 준비 완료 P50 / P90 | 109분 / 178분 | 비어 있지만 못 쓰는 시간 |
| 정오까지 준비 완료되는 퇴원 병상 | 0.6% | 그래서 의미 있는 비교 기준 시각을 15:00으로 따로 둠(MA-14, 설계 가정) |

규모 감각을 위한 산수(효과 주장이 아님, 설계 가정 조합):
- 설계 문서의 토큰 비용 가정은 "1,000병상급, 하루 퇴원 200건"이다. 이 가정에 합성 P50 109분을 곱하면 하루 약 363 병상·시간이 "퇴실 뒤 준비 전" 상태다. 하루 내내 약 15병상이 이 상태로 있는 것과 같다.
- 이 숫자는 **합성 분포와 가정 규모의 곱**일 뿐이다. 실제 병원의 값도, 이 제품이 줄일 수 있는 양도 아니다. 이 제품은 청소 인력을 배치하지 않으므로 이 구간을 직접 줄이지 못한다. 줄일 수 있는 것은 요청 지연, 준비 뒤 입실까지의 공백, 잘못된 연락이다(04 문서 지표 절).

## 5. 왜 지금인가

| 이유 | 근거 |
|---|---|
| 배정 자동화가 퍼져 "다음 병목"이 배정 앞뒤로 옮겨 갔다 | DECISIONS 엔드픽처 근거(90.8%는 첫 배정 수치) |

| 그러나 의료 현장은 LLM 단독 판단을 믿지 않는다. "판단은 에이전트, 실행은 결정적 코드" 구조가 지금 필요한 신뢰 장치다 | CLAUDE.md 2번, 설계 문서 게이트웨이 절 |
| 개인 프로젝트로서: 합성 데이터만으로 사이클 전체와 평가 체계를 증명할 수 있는 크기다 | CLAUDE.md 1번, RESULTS |

## 6. 성공과 중단의 판단 기준 (요약, 상세는 04)
- 진행 조건: 안전 가드레일 0건 유지(배정 기준 위반 0/6000, 종말소독 누락 0/600, 미래 정보 누수 0/3000, 합성), 회귀 30/30, 사람 판단 개입이 자율화 단계가 오를수록 줄어듦.
- 중단 조건(설계 문서 PoC): 배정 기준 위반 1건이면 자동 경로를 멈추고 1단계로. DB에 없는 사실을 답하면 질의 응답을 끔.
- 방향 전환 조건(이 문서가 더함, 설계 가정): 현직자 답에서 "청소 완료 신호가 전산에 없다"(A4)와 "병동 수용 회신 단계가 없다"(A5)가 함께 나오면, 병상 준비·입실 구간 자동화의 가치가 크게 줄어든다. 그때는 퇴실 전 구간(퇴원약·보호자·미등록)에 집중하는 축소안을 검토한다.

## 7. 열린 질문
1. 진짜 구매자는 누구인가(원무팀장, 간호부, 적정진료·QI팀, 정보전략실). 사업성 문서를 생략했으므로 답하지 않았다(05 P-05).
2. 북극성 측정 구간(퇴실 → 준비 완료)을 이 제품이 직접 움직이지 못한다. 북극성을 "준비 완료 → 입실 공백"까지 포함한 "병상 공백 시간"으로 넓힐지(04 열린 질문 Q1).
