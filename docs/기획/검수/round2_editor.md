# 2라운드 검수: 편집자 관점 (C5 명료성, C6 용어·표기 일관 중심)

- 검수일: 2026-11-09. 대상: `docs/기획/00~06` v0.2(커밋 eef7301 기준 작업 트리).
- 검수자 관점: 한국어 기술 문서 편집자(공공·의료 문서를 쉬운 말로 다듬은 경험). 독자는 프로젝트 책임자 한 사람이고, 그가 용어 풀이 없이 읽을 수 있는지를 기준으로 봤다.
- 사실 대조: `docs/RESULTS.md`(2026-11-09 절 포함), `docs/SPEC.md`(AGT-3·EVL-4 개정 뒤), `docs/DECISIONS.md`, `config/policy.yaml`, 설계 HTML.
- 1라운드 검수 문서는 지적이 실제로 고쳐졌는지만 확인했다. 점수는 새로 매겼다.

## 결론 먼저

1. 1라운드의 큰 문제(ID 충돌, 낡은 기준선, 세 순간 정의, 코드 식별자, 확인 수준 척도)는 **대부분 실제로 고쳐졌다**. 모든 문서가 결론으로 시작한다. 단, 03은 예외다.
2. 새로 생긴 가장 큰 결함은 **같은 커밋 안의 시차**다. 마지막 커밋(eef7301)에서 RESULTS에 측정값을 쓰고 SPEC AGT-3을 고쳤다. 그런데 01·03·04의 일부 문장은 아직 "RESULTS에 기록하지 않았다", "SPEC AGT-3을 고쳐야 한다"고 말한다(지적 1~4).
3. 용어 쪽에서 남은 문제는 세 가지다.
   - **야간 담당 이름이 다섯 가지로 쓰인다**(지적 6).
   - **"확산 단계"가 00 0.1의 "단계" 목록에 없다**(지적 7).
   - **0.3 용어 상자에 자주 나오는 말 몇 개가 빠졌다**: 인지 시각, 확인 등급, 사전 매칭, 시드, 하네스, 블라인드, 아포 소독(지적 8).
4. 표 읽기 문제는 05의 8열 표에 몰려 있다. "하·상 → 중", "완화·완화 중"처럼 가운뎃점 하나에 두 값을 넣었다(지적 19).
5. 점수: 만점(10) 칸 22/42. 지적 26건(사실 5, 일관 9, 명료 12).

### A. 사실 정합성 (C1)

**1. 01 3절, RESULTS 기록 여부가 낡음 (C1, C6)**
- 원문: "**이 값은 아직 `docs/RESULTS.md`에 기록되지 않았다.**"
- 사실: RESULTS에 "2026-11-09 기준선 재측정, 사람 부담, 긴 테스트" 절이 생겼다(커밋 eef7301). 02 5절과 04 1·6.1절은 이미 "RESULTS 2026-11-09 절에 기록"이라고 쓴다.
- 고친 문장: "이 값은 `docs/RESULTS.md` "2026-11-09 기준선 재측정" 절에 기록했다."

**2. 03 INT-Q4, 같은 문제 (C1)**
- 원문: "출처는 긴 테스트 기록(`evals/results/slow_tests/test_forecast.py.txt`)이며 RESULTS에는 아직 기록하지 않았다."
- 고친 문장: "출처는 RESULTS "2026-11-09 … 긴 테스트" 절이다(원 기록 `evals/results/slow_tests/`)."

**3. 04 6.2 머리말, 같은 문서 안에서 모순 (C1, C6)**
- 원문: "긴 테스트(`evals/results/slow_tests/`)는 RESULTS에 아직 기록하지 않았다."
- 같은 문서 PRD-Q12는 "해결(2026-11-09)"이라고 적었다.
- 고친 문장: "긴 테스트 값은 RESULTS 2026-11-09 절에 기록했다."
- 04 7절 "1.1 측정 보완" 행도 고친다. 원문 "① 기준선 재측정과 사람 부담·홀드아웃 추정·안전 스윕을 RESULTS에 기록 ② 엔드픽처 증명 숫자 … 기록"은 이렇게 바꾼다. "①② 완료(RESULTS 2026-11-09 절). 남은 것: ③ 실제 모델 비교 ④ 원내 장비 추정 ⑤ 규칙 모드 대비 에이전트 비교(EVL-4, 긴 테스트 `rule_mode_vs_agent` 결과 파일이 비어 있음, RESULTS "실행 중")."

**4. 03 INT-Q6, SPEC AGT-3이 이미 고쳐짐 (C1)**
- 원문: "SPEC AGT-3 문구는 아직 "선택"을 포함해 고쳐야 한다(04 PRD-Q8)."

- 고친 문장: "SPEC AGT-3도 같은 내용으로 고쳤다(2026-11-09, 04 PRD-Q8 해결)."

**5. 00 0.1과 01 6.1, PRD 열린 질문의 절 번호가 틀림 (C1, C6)**

### B. 문서 간 일관성과 용어 (C6)

**6. 야간 담당 이름이 다섯 가지 (C6, C5)**
같은 역할을 이렇게 쓴다.
- "간호부 당직 감독": 00 5절, 02 결론 1·PS-2, 03 EXT-Q15, 04 US-17
- "간호부 당직": 01 결론
- "간호부 야간 당직": 02 4.4
- "간호부(야간 당직)": 05 0절 담당표, R-08, R-35
- "야간 간호부 당직": 05 R-35 원인

고칠 것:
- 정본을 "**간호부 당직 감독**"으로 정해 00 0.3에 한 줄 넣는다. 예: "간호부 당직 감독 = 야간·휴일에 간호부를 대표해 병상과 인력을 조정하는 간호 관리자(병원별 명칭 다름, 현직자 확인 필요)".
- 01 결론: "야간·휴일은 당직 원무 또는 간호부 당직" → "야간·휴일은 당직 원무 또는 간호부 당직 감독"
- 02 4.4 응급 입원 행: "응급실, 간호부 야간 당직, 병상관리" → "응급실, 간호부 당직 감독, 병상관리"
- 05 0절 담당표, R-08, R-35: "간호부(야간 당직)" → "간호부 당직 감독"
- 05 R-35 원인: "(응급실, 야간 간호부 당직)" → "(응급실, 간호부 당직 감독)"

**7. "확산 단계"가 00 0.1의 "단계" 목록에 없음 (C6)**
- 00 0.1은 "'단계'도 뜻이 여럿이라 늘 수식어를 붙인다"고 하고 네 가지(프로젝트·구현·자율화·출시)만 정의했다.
- 그런데 01 1.2, 02 4.4, 03 EXT-Q11, 04 2.2는 "확산 2단계", "확산 2·3단계"를 쓴다. 06 IF-13은 "확산 단계"를 쓴다. 설계 문서는 "현장 AX 5·6단계"도 쓴다.
- 00 0.1에 넣을 항목: "- **확산 단계(확산 2·3단계)**: 설계 문서 "확산과 운영" 절이 프로젝트 1단계 밖으로 미룬 대상. 확산 2단계 = 응급실 입원 대기, 확산 3단계 = 수술 일정 연동. 이 폴더에서는 모두 범위 밖이다."

**8. 수식어 없이 쓴 "단계"가 남음 (C6, C5)**
00 0.1의 규칙을 어긴 문장들이다.
- 03 EXT-Q11: "응급 입원 조정은 이 단계의 범위 밖입니다" → "응급 입원 조정은 프로젝트 1단계의 범위 밖입니다"
- 03 EXT-Q8: "섀도 모드는 설계 단계입니다." → "섀도 모드는 아직 설계 항목입니다(구현 안 됨)."
- 03 INT-Q7: "표본 감사와 자동 강등은 설계 단계다" → "… 설계 항목이다"
- 05 머리: "단계마다 갱신한다(4절)." → "현직자 답이 오거나 출시 단계 관문을 지날 때 갱신한다(4절)."
- 05 R-30: "(DECISIONS 8단계, AI-DD 6절)" → "(DECISIONS "8단계 몬테카를로 가용 병상 추정", AI-DD 6절)"
- 06 IF-09: "DECISIONS 7단계" → "DECISIONS "7단계 계획 에이전트 구현""
- 04 7.1 표의 첫 열 머리 "단계"(ADKAR 요소) → "ADKAR 요소"
- 04 6.3 읽는 법: "2단계 행은 …" → "자율화 2단계 행은 …"

**9. 05 R-06, "U05"가 DECISIONS의 U 번호와 겹침 (C6)**
- 원문: "(예측못한상황 U05)"
- 00 0.1과 05 머리는 "U = DECISIONS 2026-11-09 결정"이라고 정했다. 그런데 `docs/검토/예측못한상황.md`의 U05는 다른 목록(점검 항목)이다. 읽는 사람은 U5 결정으로 오해한다.
- 고친 문장: "(`docs/검토/예측못한상황.md` 점검 항목 U05)". 00 0.1의 "LP-, MA-, U" 행에도 덧붙인다. "예측못한상황 문서의 U01~ 번호는 별개이며 늘 문서 이름을 붙인다".

**10. 02 3.2, 청소 유형 정의와 행 이름이 어긋남 (C6)**
- 02 PS-7은 "청소 유형은 **일반·종말소독** 두 가지이고, 추가 조건으로 환기 대기와 아포 소독이 붙는다"고 정의했다.
- 그런데 같은 문서 3.2 표 행 이름은 "청소 유형 규칙(종말소독, 환기 대기, 아포 소독)"이다. 환기 대기와 아포 소독이 다시 유형처럼 읽힌다.
- 고친 행 이름: "청소 유형(일반·종말소독)과 추가 조건(환기 대기, 아포 소독) 규칙"

**11. 03 보도자료 부제, "만 맡는다"가 EXT-Q3과 어긋남 (C6, C4)**
- 원문: "사람은 확정, 환자 연락, 안전 예외만 맡는다."
- EXT-Q3과 04 결론·6.3은 병동 수용 회신도 사람의 책임으로 남긴다고 한다. 또 "확정"은 정본 이름 "공식 확정"과 다르다. 병동 간호사가 읽으면 "우리 회신은?" 하고 묻게 된다.
- 고친 부제: "…한 화면에서 본다. 공식 확정, 환자 연락, 안전 예외, 병동의 수용 회신은 사람이 맡는다."

**12. 06 IF-07, "아포 소독"과 화면 표기 "아포 대응"을 그냥 둠 (C6, C5)**
- 원문: "아포 소독. 화면 표기는 "아포 대응""
- 문서는 "아포 소독"으로, 화면(`ui/demo.py`)과 코드 주석은 "아포 대응(소독)"으로 쓴다. 차이는 적어 두었지만, 어느 쪽이 정본인지 정하지 않았다.
- 고칠 것: 00 0.3에 "아포 소독 = 세균 포자(아포)까지 죽이는 소독. C. difficile 퇴실 병실에 쓴다. 화면에는 "아포 대응"으로 나온다(화면 문구 정리 대상)" 한 줄을 넣는다. IF-07은 "아포 소독(0.3 참조)"으로 줄인다.

**13. 03 INT-Q9, "DECISIONS EVT-7" (C6)**
- 원문: "(DECISIONS EVT-7)"
- EVT-7은 SPEC ID다. DECISIONS에는 "FHIR R4 입력 어댑터 (EVT-7)"라는 제목의 결정이 있다.
- 고친 문장: "(DECISIONS "FHIR R4 입력 어댑터" 결정, SPEC EVT-7)"

**14. 04 7절, "출시 단계 2"와 "프로젝트 2단계"가 같은 것인지 표에 없음 (C6, C5)**
- 표의 "2. 온보딩 에이전트" 행은 프로젝트 2단계와 같은 것이다. 하지만 그 사실이 적혀 있지 않다. 00 0.1도 "출시 단계 0~2"로만 적었다.
- 고친 행 이름: "2. 온보딩 에이전트(= 프로젝트 2단계)". 00 0.1의 출시 단계 항목에도 덧붙인다. "출시 단계 1 = 프로젝트 1단계(1.1~1.3은 그 안의 관문), 출시 단계 2 = 프로젝트 2단계".

### C. 명료성 (C5)

**15. 00 0.3 용어 상자에 자주 쓰는 말이 빠짐 (C5)**
아래 말이 01~06에 풀이 없이 여러 번 나온다. 책임자가 개발 세부를 모르면 막히는 말들이다.

| 넣을 용어 | 쉬운 풀이(제안) |
|---|---|
| 인지 시각 | 시스템이 그 사실을 알게 된 시각. 실제로 일어난 시각(현실 시각)과 따로 기록한다 |
| 확인 등급(자동, 병동 확인, 담당 검토) | 제안마다 사람이 얼마나 확인할지 정한 세 등급. 정책 파일로 정한다 |
| 사전 매칭, 재매칭 | 퇴원 예정 병상에 다음 환자를 미리 짝지어 두는 것, 사정이 바뀌어 다시 짝짓는 것 |
| 보상 단계 | 취소가 생겼을 때 이미 한 일(예정표 항목, 매칭)을 되돌리는 절차 |
| 시드 | 합성 데이터를 같은 모양으로 다시 만들기 위한 번호. 시드 0~199 = 서로 다른 합성 병원·날 200개 |

**19. 05 1절 표, 한 칸에 두 값을 가운뎃점으로 넣음 (C5)**
- 원문 열 머리와 칸 예: "가능성·영향 → 남은 위험" 칸에 "하·상 → 중", "대응·상태" 칸에 "완화·완화 중", "담당·검토" 칸에 "감염관리실, 환경관리·1.2 뒤".
- 문제: 가운뎃점이 칸 안에서 "와"(감염관리실·수간호사)의 뜻으로도, 두 열을 합친 경계로도 쓰인다. "완화·완화 중"은 같은 말이 겹쳐 오타처럼 보인다. 8열이라 화면에서 칸이 좁다.
- 고칠 방법(둘 중 하나):
  - (가) 칸 안의 경계 기호를 "/"로 바꾼다. "하 / 상 → 중", "완화 / 완화 중", "감염관리실, 환경관리 / 1.2 뒤".
  - (나) 표를 둘로 나눈다. 1표 = ID, 리스크와 원인, 징후, 지금의 통제. 2표 = ID, 측정, 가능성, 영향, 남은 위험, 대응, 상태, 담당, 검토 시점(짧은 값만).
- 열 설명 문장(1절 머리)도 나눈다.
  - 원문: "열: 리스크와 원인 / 징후(이것이 보이면 리스크가 커지는 중) / … / 담당·검토 시점(출시 단계 관문. "1.2 뒤" = 현직자 검증 뒤)."
  - 고친 문장: "표의 열은 여덟 개다. 징후는 '이것이 보이면 리스크가 커지는 중'이라는 뜻이다. 남은 위험은 0절 표로 읽는다. 검토 시점은 출시 단계 관문이다. "1.2 뒤"는 현직자 검증 뒤라는 뜻이다."
