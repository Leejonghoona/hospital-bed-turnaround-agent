# 기획 산출물 분석: 무엇이 필요했고, 무엇이 이미 있고, 무엇을 새로 썼나

- 작성일: 2026-11-09. 상태: 초안(사용자 검토 전).
- 관점: 병원 업무 시스템을 기획하는 B2B 헬스케어 PM·PO.
- 이 폴더의 문서는 개발이 거의 끝난 뒤 "개발 전에 있었어야 할 기획 문서"를 갖추려고 쓴 것이다. 그래서 **새로 지어내지 않는다**. 이미 있는 결정(설계 문서, SPEC, DECISIONS)을 기획 문서의 형식으로 다시 묶고, 빈 곳만 채운다.
- 상위 문서: `docs/병상턴어라운드_설계.html`(설계 정본), `CLAUDE.md`(원칙), `docs/SPEC.md`(요구 v1.0 동결). 이 폴더와 상위 문서가 다르면 상위 문서가 이긴다.
- 모든 수치는 합성 데이터 기준 추정이다. 병원 발표 수치와 비교하지 않는다. 근거를 찾지 못한 값은 "설계 가정"으로 쓴다.

## 결론 먼저

1. 기획 산출물 18종을 검토했다. **필수 8종, 권장 6종, 생략 4종**으로 판정했다.
2. 필수 8종 중 5종은 기존 문서가 이미 대부분 덮는다(설계 문서, SPEC, 평가표, DECISIONS, 현직자 질문지). 새로 쓴 것은 **문제 정의서, 사용자·이해관계자, PR/FAQ, PRD, 리스크·가정 등록부, 요구사항 보완절** 여섯 개다.
3. 가장 큰 빈칸은 세 가지였다.
   - **사람 쪽 문서**: 직무별 페르소나, 책임 배정(RACI), 여정이 흩어져 있었다(SPEC POS-4 한 줄, 현직자 질문지 A1~A7).
   - **리스크 등록부**: 위험이 설계 문서 보안 절, DECISIONS, 검토 문서에 나뉘어 있고 담당·대응·남은 위험을 한 표로 본 적이 없다.
   - **규제 분류 검토**: 이 서비스가 의료기기 소프트웨어에 해당하는지 따져 본 기록이 없다. 05 문서에 "검토 필요" 항목으로 넣었다(결론 아님).
4. 원문을 직접 열지 못한 출처가 많다. 이 세션은 외부 사이트 대부분이 차단돼 웹 검색 요약으로만 확인했다. 아래 표의 "확인 수준" 열에 표시했다.

## 2. 근거로 삼은 표준과 공개 예시

확인 수준: **원문** = 작업자가 원문을 열어 확인 / **요약** = 웹 검색 결과 요약으로만 확인(원문 미대조) / **지식** = 일반 지식, 이번에 출처를 찾지 못함. 이번 세션에서는 해당 사이트(industrialempathy.com, atlassian.com, england.nhs.uk, fda.gov) 직접 열기가 네트워크 정책으로 막혀 **원문 확인 0건**이다.

## 5. PM으로서 본 기획 공백의 교훈 (짧게)

- **잘된 점**: 비목표가 처음부터 강했다(CLAUDE.md 4·5번, 설계 문서 "제외"). 성공 기준에 가드레일(안전 0건)이 먼저 있었다. 가정을 "설계 가정"으로 표시하는 습관이 있었다.
- **늦게 온 것**: 사용자 정의. 주 사용자 "병상관리 담당"이 누구인지(원무인가 간호부인가)가 스펙 동결 뒤 현실 조사(LP-25)에서야 시간대별 역할로 바뀌었다. 기획 단계에서 RACI를 먼저 그렸다면 질문이 더 일찍 나왔을 것이다.
- **아직 없는 것**: 실제 현직자 검증. 이 폴더의 페르소나와 RACI는 공개 자료와 설계 가정으로 만든 **가설**이다. 현직자 설문(`docs/검토/현직자_설문.html`) 답이 오면 05 가정 등록부의 판정 규칙대로 고친다.
