# 기획 산출물 분석: 무엇이 필요했고, 무엇이 이미 있고, 무엇을 새로 썼나

- 작성일: 2026-11-09. 상태: 초안 v0.3(2라운드 검수 반영, 사용자 검토 전). 검수 조치 기록: `docs/기획/검수/round1_조치.md`, `docs/기획/검수/round2_조치.md`.
- 관점: 병원 업무 시스템을 기획하는 B2B 헬스케어 PM·PO.
- 이 폴더의 문서는 개발이 거의 끝난 뒤 "개발 전에 있었어야 할 기획 문서"를 갖추려고 쓴 것이다. 그래서 **새로 지어내지 않는다**. 이미 있는 결정(설계 문서, SPEC, DECISIONS)을 기획 문서의 형식으로 다시 묶고, 빈 곳만 채운다.
- 상위 문서: `docs/병상턴어라운드_설계.html`(설계 정본), `CLAUDE.md`(원칙), `docs/SPEC.md`(요구 v1.0 동결), `docs/DECISIONS.md`(결정), `docs/RESULTS.md`(측정). 이 폴더와 상위 문서가 다르면 상위 문서가 이긴다.
- 모든 수치는 합성 데이터 기준 추정이다. 병원 발표 수치와 비교하지 않는다. 근거를 찾지 못한 값과 절차는 "설계 가정"으로 쓴다.

## 결론 먼저

1. 기획 산출물 23종을 검토했다. **필수 12종, 권장 7종, 생략 4종**으로 판정했다(1절 표의 "판정" 열을 센 값).
2. 처리 방식으로 나누면 **기존 문서가 그대로 대체 2종, 기존 문서 + 보완 4종, 새로 씀 5종, 다른 문서의 절로 흡수 8종, 생략 4종**이다(1절 표의 "처리" 열을 센 값).
3. 새로 만든 문서는 여섯 개다. 01 문제 정의서, 02 사용자·이해관계자, 04 PRD, 05 리스크·가정 등록부는 필수 산출물을 새로 쓴 것이고, 06 요구사항 보완절은 필수인 SRS(SPEC이 대부분 대체)의 빈 절을 채운 것이며, 03 PR/FAQ는 권장 산출물이다.
4. 가장 큰 빈칸은 세 가지였다.
   - **사람 쪽 문서**: 직무별 페르소나, 책임 배정(RACI), 여정, 그리고 퇴원이 아닌 이유로 병상이 비는 경로(사망, 급변 전동, 자의퇴원 등)가 흩어져 있었다.
   - **리스크 등록부**: 위험이 설계 문서 보안 절, DECISIONS, 검토 문서에 나뉘어 있었고 담당·대응·남은 위험을 한 표로 본 적이 없다.
   - **규제 분류 검토**: 이 서비스가 의료기기 소프트웨어에 해당하는지 따져 본 기록이 없다. 05 문서에 "검토 필요" 항목으로 넣었다(결론 아님).
5. 형식 표준(2절)은 작성 시점(2026-11-09)에 원문 사이트를 열지 못해 웹 검색 요약으로만 확인했다. 원문 대조는 남은 과제다. 현장 근거(병원 안내, 감염 지침)는 `docs/검토/` 문서에서 일부 원문을 확인했다(2.3절).
6. 지금 상태(2026-11-09): 프로젝트 1단계 구현 완료, 검증 미완. 현직자 설문은 **발송됨, 답 대기**다(DECISIONS "현직자 설문 발송"). 응급실발 입원은 입원 대기의 유입 경로로 얇게 넣기로 했고(작업자 권고안, 사용자가 바꿀 수 있음), 시점은 설문·후속 질문 답 뒤다(DECISIONS "응급실 범위").

## 0. 이 폴더를 읽는 법

### 0.1 ID 읽는 법
같은 글자와 번호가 다른 문서에서 다른 뜻으로 쓰이지 않도록, 기획 폴더가 새로 만든 ID에는 접두어를 붙인다. 다른 문서의 ID를 인용할 때는 출처 이름을 앞에 붙인다(예: "지표 S1", "시나리오 A04", "설문 문항 7").

"단계"도 뜻이 여럿이라 늘 수식어를 붙인다.
- **프로젝트 1단계·2단계**: 엔드픽처의 큰 단계. 1단계 = 한 합성 병원에서 사이클 전체 에이전트화, 2단계 = 병원 데이터로 설정을 만드는 온보딩 에이전트.
- **구현 1~9단계**: CLAUDE.md 구현 우선순위(생성기, 저장소, 사가, 게이트웨이, 평가, 온톨로지, 에이전트, 추정, 화면). RESULTS의 "1.5단계"는 평가 골격이다.
- **자율화 1~3단계**: 사람 확인 범위. 1단계 = 모든 매칭안을 담당이 확인, 2단계 = 승격 유형만 담당 확인 생략, 3단계 = 사람은 감독만(설계).
- **출시 단계 0~2**: 04 PRD 7절의 출시 계획. 출시 단계 1 = 프로젝트 1단계이고, 1.1 측정 보완, 1.2 현직자 검증, 1.3 MVP 가정 검토, 1.4 응급실발 입원 최소판은 그 안의 관문이다. 출시 단계 2 = 프로젝트 2단계(온보딩).
- **확산 단계(확산 2·3단계)**: 설계 문서 "단계적 확산" 절의 "인접 공정"이 프로젝트 1단계 밖으로 미룬 대상. 확산 2단계 = 응급실 입원 대기와 정규 입원 연기 판단, 확산 3단계 = 수술 일정 연동. 이 폴더에서는 범위 밖이다. 응급실에서 병동으로 오는 입원을 입원 대기의 한 경로로 받는 일(출시 단계 1.4)은 확산 2단계와 다르다.

### 0.2 사람이 남는 세 순간 (모든 문서 공통)
엔드픽처의 세 순간은 **공식 확정, 환자 연락, 안전 예외**다(CLAUDE.md, SPEC 비전, DECISIONS 엔드픽처). 최종 책임자(A)는 공식 확정 = 원무, 환자 연락 = 원무, 안전 예외 = 감염관리실이다. 병동 수용 회신(책임간호사)은 세 순간 밖에 있는 **다른 책임 개입**이다. 측정 코드가 무엇을 세는지는 04 PRD 6.3에 따로 적었다.

## 1. 산출물 목록과 판정

판정 기준: **필수** = 이것이 없으면 범위·책임·성공 기준을 합의할 수 없다. **권장** = 있으면 이해관계자 정렬과 포트폴리오 설명이 크게 좋아진다. **생략** = 개인 프로젝트·합성 데이터 단계에서는 비용이 효익보다 크다.
처리: **기존 대체** = 기존 문서가 그대로 맡는다. **기존 + 보완** = 기존 문서가 대부분 맡고 이 폴더가 빈 곳을 채운다. **새로 씀** = 이 폴더에 독립 문서를 새로 썼다. **절로 흡수** = 다른 문서의 한 절로 넣었다. **생략**.

## 2. 근거로 삼은 표준과 공개 예시

### 2.1 근거 표시 규칙 (모든 문서 공통)
근거마다 두 가지를 따로 적는다.
- **출처 종류**: **1차** = 표준 원문, 법령, 정부·공공기관 발표, 병원 공식 안내, 공급사 자료 / **2차** = 기사, 블로그, 해설, 위키, 논문 요약.
- **확인 수준**: **원문** = 작업자가 원문을 열어 확인 / **요약** = 웹 검색 결과 요약으로만 확인(원문 미대조) / **지식** = 일반 지식, 이번에 출처를 찾지 못함.
- 근거를 찾지 못한 값과 절차는 **설계 가정**, 현직자에게만 확인할 수 있는 것은 **현직자 확인 필요**로 쓴다.

병원 절차와 감염 규칙의 근거는 이 폴더가 아니라 `docs/검토/`에 있다. 확인 수준은 그 문서의 표기를 따른다.
- `docs/검토/업무현실검증.md`, `docs/검토/스펙현실검증.md`: 입퇴원 절차, 배정 주체, 기존 HIS 기능.
- `docs/검토/병동사망_급변전동_조사.md`: 병동 내 사망과 급변 전동(검색 요약 수준).
- DECISIONS LP-23·LP-24: 질병관리청 「의료관련감염 표준예방지침」 조항과 환기 표(제3자 사본으로 원문 확인, 공식본 대조는 남은 과제).
- 서울아산병원 입원진료절차안내(정오경 입원일 변경 연락): 스펙현실검증에서 원문 확인.
- `docs/검토/응급실범위/종합.md`(2026-11-09, 3인 검토): 응급실 내부 배치도 제외, 응급실발 입원은 입원 대기의 유입 경로로 얇게 포함. 근거 법령·표준(응급의료법 시행규칙 별표, KTAS, FHIR `admitSource`)은 원문을 열지 못해 검색 요약 수준이다. 결정은 DECISIONS "응급실 범위".
- `docs/검토/현직자_후속질문_응급실.txt`: 설문 답을 받은 뒤 보낼 응급실 후속 질문 4개.

## 5. PM으로서 본 기획 공백의 교훈 (짧게)

- **잘된 점**: 비목표가 처음부터 강했다(CLAUDE.md 4·5번, 설계 문서 "제외"). 성공 기준에 가드레일(안전 0건)이 먼저 있었다. 가정을 "설계 가정"으로 표시하는 습관이 있었다.
- **늦게 온 것 ①, 사용자 정의**: 주 사용자 "병상관리 담당"이 누구인지가 스펙 동결 뒤 현실 조사(LP-25)에서야 시간대별 역할로 바뀌었다. 지금도 **원무인가 간호부인가, 야간은 당직 원무인가 간호부 당직 감독인가**가 열려 있다(가정 AS-A1·A2). 기획 단계에서 RACI를 먼저 그렸다면 이 질문이 더 일찍 나왔을 것이다.
- **늦게 온 것 ②, 비정규 경로**: 병상이 퇴원이 아닌 이유(병동 내 사망, 급변 전동)로 비는 경로가 사용자 지적 뒤에야 들어왔다(MA-15, SAG-10). 현행 업무 흐름도(#19)를 정규·비정규 경로로 먼저 그렸다면 먼저 잡혔을 것이다.
- **아직 없는 것**: 실제 현직자 검증. 이 폴더의 페르소나와 RACI는 공개 자료와 설계 가정으로 만든 **가설**이다. 현직자 설문(`docs/검토/현직자_설문.html`)은 발송됐고 답을 기다린다. 답이 오면 05 가정 등록부의 판정 규칙대로 고친다. 설문 1회로 확인할 수 없는 것(야간 운영, 사망 경로, 청소 완료 확인 주체)은 05 3.6의 후속 인터뷰로 확인한다.
