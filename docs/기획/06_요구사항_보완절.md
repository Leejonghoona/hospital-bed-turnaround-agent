# 요구사항 보완절: SPEC과 표준 목차의 대응, 빠진 절

- 작성일: 2026-11-09. 상태: 초안.
- **SRS는 `docs/SPEC.md`(v1.0 동결)가 대신한다.** 이 문서는 SRS를 새로 쓰지 않는다. 표준 목차에 SPEC을 대 보고, 비어 있는 절만 채운다.
- 이 문서의 새 ID(IF-, DA-, CO-, OP-)는 **기획 보완이며 SPEC에 반영되지 않았다.** 대부분은 이미 구현된 것을 요구 형식으로 적은 것이다. 새 요구(상태 "공백")를 SPEC에 넣으려면 SPEC 동결 뒤 변경 절차(DECISIONS에 이유를 먼저, 버전 올림, 추적표 갱신)를 따른다.
- 설계 문서에서 "설계"·"제외"로 둔 것은 구현 범위로 쓰지 않았다. 상태 열에 그대로 표시했다.

## 결론 먼저
1. SPEC은 기능(POL, DAT, EVT, SAG, GW, ONT, AGT, EVL, SEC), 비기능(NFR 6개), 목표 함수, 추적표를 갖췄다. 29148 SRS 목차 기준으로 **기능·성능·보안·검증은 충분**하다.
2. 비어 있는 절은 넷이다. **외부 인터페이스, 논리 데이터(데이터 사전·보존), 설계 제약, 운영·지원**. 이 문서 2~5절이 채운다.
3. 새로 찾은 실제 공백은 셋이다(구현 안 됨, 설계 문서에도 없음): 감사 기록 보존·파기 규칙(CO-04), 정책 파일 변경 승인 절차(OP-03), 사용자 교육·도입 준비(OP-05). 모두 실제 도입 단계의 일이라 1단계 범위에 넣지 않는다.

## 1. 대응표

### 1.1 ISO/IEC/IEEE 29148 SRS 예시 목차 ↔ SPEC
목차는 검색 요약(8.5절 예시 목차가 있다는 것)과 일반 지식으로 재구성했다. **표준 원문과 대조하지 않았다.**

| 29148 SRS 예시 목차 (재구성) | SPEC의 대응 | 판정 | 보완 |
|---|---|---|---|
| 1.1 목적 | SPEC 머리말, 비전 | 충분 | - |
| 1.2 범위 | 비전 표, CLAUDE.md 4·5번, 설계 문서 "구현 범위" | 충분(흩어짐) | 04 PRD 비목표 |
