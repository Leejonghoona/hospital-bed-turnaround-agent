# 리스크·가정 등록부

- 작성일: 2026-11-09. 상태: 초안. 단계마다 갱신한다.
- 형식 근거: NIST AI RMF 1.0의 Map(맥락)·Measure(측정)·Manage(대응)·Govern(책임), NHS DTAC 평가 영역과 DCB0129·DCB0160의 위험 로그(위해, 영향, 통제, 남은 위험), Torres의 가정 검증(00 문서 2절, 모두 검색 요약 수준).
- 원 자료: 설계 문서 "보안"·"모델"·"PoC", SPEC 1.5, DECISIONS(MA-01~14, LP-23~29), `docs/검토/예측못한상황.md`, `docs/검토/스펙현실검증.md`, `docs/검토/현직자_질문지_검수.md`, `docs/AI-DD.md` 6절, `docs/모델_성능점검표.md`.
- 가능성·영향 등급(상·중·하)은 작업자 판단이다(설계 가정). 실제 병원 도입 시 임상 안전 책임자가 다시 매긴다.
- 수치는 합성 데이터 기준 추정이다.

## 결론 먼저

1. 리스크 34건. **남은 위험이 "상"인 것은 6건**이다: 자동화 편향·형식적 승인(R-04), 시스템 밖 결정과의 불일치(R-06), 추적 신호 부재(R-25), 주 사용자 오인(R-22), 의료기기 해당 여부 미판단(R-33), 평가의 블라인드 한계(R-31). 여섯 모두 **코드로는 더 줄일 수 없고 현장 검증이 필요**하다.
2. 안전 가드레일(배정 기준 위반, 종말소독 누락, 미래 정보 누수)은 합성 기준으로 통제와 측정이 갖춰졌다. 남은 위험은 "입력 자체가 틀리거나 늦는 경우"다. 정답 값의 원천은 HIS와 사람이다.
3. 가정 25건(현직자 질문지의 영향 큰 가정 17건 + 제품 수준 가정 8건)을 한 곳에 모았다. 가장 먼저 확인할 것은 **역할과 신호 가정 7개(A1~A7)**다. 하나라도 틀리면 페르소나, RACI, 사가 흐름이 바뀐다. 현직자 설문 문항과 판정 규칙을 붙였다.
4. 규제: 이 제품이 의료기기 소프트웨어인지 **판단하지 않았다**. 행정 지원 성격이 강해 보이지만 임상 정보를 쓴다. 실제 도입 전 확인 질문 6개를 2절에 적었다.

### 2.1 참고한 기준 (모두 검색 요약, 원문 미대조)
- 식약처: 소프트웨어의 의료기기 해당 여부는 **사용 목적과 위해도**로 판단한다. 질병의 진단·치료·예방 목적이면 의료기기로 본다(2017 빅데이터·AI 가이드라인 보도). 생성형 AI 가이드라인(2025)은 전자의무기록의 단순 기록·검색·조회·요약을 맞춤 치료계획 생성과 구분했다는 보도가 있다. **병원 행정·병상 운영 소프트웨어에 대한 식약처 예시는 찾지 못했다.**
- 미국 FDA: FD&C법 520(o)(1)은 소프트웨어 기능 다섯 범주를 의료기기 정의에서 뺀다. (A)가 의료기관의 행정 지원이다(FDA 발표 자료 요약). CDS 지침은 2026년 1월 최종판이 2022년판을 대체했다.
- IMDRF SaMD(N12, 2014): 정보의 중요도와 환자 상황의 심각도로 위험 범주 I~IV.

### 2.3 도입 전 확인 질문
1. 식약처 기준에서 "병상 배정 보조, 운영 지연 추적"이 의료기기 사용 목적에 해당하는가(식약처 사전 상담 또는 공무원지침서·민원인안내서 원문).
2. 격리 오더 값을 규칙에 대 보는 기능이 "진단·치료 보조"로 해석될 여지가 있는가.
3. 낙상·섬망 고위험 가점과 중증도 기반 검토 분류를 빼거나 "표시만"으로 바꾸면 판단이 달라지는가.
4. 병원 내부 개발·운영(자체 사용)과 공급사 판매 시 판단이 다른가.
5. 개인정보 처리: 의료법 제21조(기록 열람 제한), 개인정보보호법 제23조(민감정보)·제28조의8(국외 이전)에 대한 병원 정보보호 책임자 검토(설계 문서 보안 절이 쟁점을 이미 정리함).
6. 실제 도입 시 임상 안전 기록(위험 로그와 안전 사례, NHS DCB0129·DCB0160 같은 형식)을 공급자와 병원 중 누가, 어떤 양식으로 남기는가. 국내 대응 제도는 찾지 못했다.
