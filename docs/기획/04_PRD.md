## 결론 먼저
- **무엇을**: 퇴원 확정부터 다음 환자 입실까지(퇴실 전, 병상 준비, 입실)를 이벤트로 추적하고, 늦어지는 단계를 먼저 찾고, 안전 검사를 통과한 제안만 실행한다. 사망·급변 전동처럼 퇴원이 아닌 이유로 병상이 비는 경로도 다룬다.
- **누구를 위해**: 병상관리 담당(시간대별 역할), 병동 책임간호사·수간호사, 감염관리실. 결과는 다음 입원 환자.
- **성공이란**: 안전 가드레일 0건을 지키면서, 사람의 판단 개입은 줄이고 책임질 순간(환자 연락, 안전 예외, 시스템이 "확인 필요"로 올린 판단)은 남긴다. 검토 사유가 없는 사례의 공식 확정은 에이전트가 하고, 원무와 병동은 통보받아 시한 안에 되돌리거나 이의를 낸다(DECISIONS 2026-11-09). 병상 공백 시간은 북극성으로 보고만 한다(이 제품이 직접 줄이지 못하는 구간이 있어서, 6.1).
- **지금 어디**: 프로젝트 1단계 구현 완료(08 데모 계획 1~5단계 포함), 검증 미완. **다음 관문은 현직자 검증**이다(설문 발송, 답 대기). 온보딩은 사용자 결정으로 1단계 안에서 구현했다(4.6).
  - 최종 설정(현장 프로필 기본, 현실 가동률) 결과: 사람 손 없이 에이전트가 확정 72.4%(확정 203건 중 147건. 입원 304건 대비로는 48%)(시드 최저 50%, RESULTS "5단계 최종 M1 재측정"). 50시드와 수정 때 보지 않은 시드 50~99의 실행 S1~S4 위반 0. 수속 → 입실 평균 대기 −13%, 48시드(가정한 효과 크기의 결과).
  - 합성 결과: 회귀 시나리오 30/30, 홀드아웃 4회차 누적 13/13, 지표 G4 14/14(H13 추가, 6.2). 실행된 배정·청소 요청의 안전 위반 0건(시나리오, 게이트웨이 퍼징 20/20, 하루 재생 50 시드 실행 S1 0/410·실행 S2 0/58. 결핵 60분 하한 검사를 넣고 다시 재도 같음). 실행 S2는 분모가 아직 크지 않다(95% 상한 5.2%, 6.2).
  - 단서: 홀드아웃은 모두 작업자가 써서 블라인드가 아니다. 그중 H02·H11은 결과를 보고 고쳤고, H13은 지표 G4의 빈틈을 보고 겨냥해 썼다. H06~H13은 사용자 검토 전 초안 라벨이다. 예전 점수판의 S1·S2 0건은 생성기 자료 점검이라 근거에서 뺐고, 평가표 지표 S4는 미측정이다(6.2).
  - 미달: 지표 O3는 포함률이 92%대로 합격 범위(70~90%)를 넘었다. 추정 구간이 필요보다 넓다는 뜻이다(6.1).

## 1. 배경과 문제
요약만 둔다. 상세는 `01_문제정의서.md`.
- 퇴원 뒤 병상이 다시 쓰이기까지 여러 부서를 거친다. 단계 사이 지연을 한 사례로 묶어 보는 사람이 없다.
- 첫 배정은 이미 여러 병원이 자동화했다. 기회는 배정 앞뒤의 조율이다(SPEC POS-5).
- 합성 기준선(2026-11-09 재측정, 커밋 a07b6e3, 시드 0~199, RESULTS 2026-11-09 절에 기록): 정오 전 퇴실 17.1%, 퇴실 → 청소 요청 P50 20분·P90 50분, 퇴실 → 준비 완료 P50 109분·P90 182분.

## 3. 사용자
`02_사용자_이해관계자.md`의 페르소나 PS-1~PS-10. 주 사용자는 PS-1·PS-2(병상관리 담당, 시간대별), PS-3(책임간호사), PS-9(수간호사). 담당 검토 중 임상 사유는 PS-8(감염관리실)과 PS-9가 최종 책임을 진다는 것이 이 문서의 제안이다(02 결론 3, PRD-Q9). 역할 가정 AS-A1·A2가 틀리면 이 절부터 고친다.

## 4. 사용자 스토리

형식: "[역할]으로서 [하고 싶은 것], 그래서 [얻는 것]". 수용 기준은 검증 가능한 문장으로, SPEC ID와 시나리오(`evals/scenarios/`)에 잇는다. 상태는 SPEC 표기를 따른다.
우선: **필수** = 없으면 프로젝트 1단계 목표(PG-1~5)를 못 지킴 / **권장** = 사람 부담과 신뢰를 크게 바꿈 / **선택** = 있으면 좋음. 판단은 작업자(설계 가정).
홀드아웃은 모두 작업자가 써서 블라인드가 아니다. 그중 H02·H11은 결과를 보고 고쳤고, H13은 지표 G4의 빈틈을 보고 겨냥해 썼다. 라벨은 H01~H05가 승인, H06~H13은 사용자 검토 전 초안이다.
**비목표가 아닌 것**: 응급실발 입원을 입원 대기의 유입 경로로 받는 최소판(입원 경로·입원 결정 시각, 처리 순서 규칙 `admission_priority`에 응급 경로 추가, 응급 입원 검토 사유(예정 이름 `ed_admission`, DECISIONS "응급실 범위"), 준비 예상 시각 공유)은 설계 문서 담당 검토 표와 SPEC 3절 목표 함수 3항이 약속한 범위다. 아직 구현하지 않았고 스토리도 쓰지 않았다. 시점은 PRD-Q13, 출시 단계 1.4.

읽는 법:
- 자율화 1단계는 설계상 모든 매칭안을 담당이 확인하므로 완전 자동 0%가 맞다.
- 자율화 2단계 행은 "모든 진료과를 승격했다면"의 상한 시험이다. 실제 승격은 정책 변경 승인 사항이다.
- 자율화 2단계로 올려도 사례당 판단 개입은 조금만 줄어든다(1.21 → 1.14, 1.33 → 1.08). 합성 입원 대기 15건 중 10건이 일부러 넣은 검토 사례(DAT-6)다. 검토 사례는 승격과 관계없이 사람에게 간다.
- 그래서 완전 자동 비율의 상한이 낮다. 현실의 검토 사례 비율은 근거가 없다(PRD-Q7).
- 하네스는 환자 연락을 흉내 내지 않는다. 그래서 책임 개입에는 병동 회신과 사람이 한 공식 확정만 들어 있다. 이 표는 모든 확정을 사람이 한 옛 판이라 확정이 모두 책임 개입으로 잡혔다. 현장 프로필에서는 검토 사유 있는 사례의 담당 검토 확정만 책임 개입으로 세고, 에이전트 확정은 세지 않는다.
- 승인 대기 시간은 하네스가 흉내 낸 값이라 지표로 쓰지 않는다. 형식적 승인 의심(30초 미만, 설계 가정)은 모든 행에서 0건이다. 하네스 응답이 30초보다 느려서이므로 의미 없다.
