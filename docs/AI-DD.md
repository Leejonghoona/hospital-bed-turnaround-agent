# AI-DD 기록: AI가 만들고, 장치가 통제하고, 사람이 결정한다

이 프로젝트의 코드와 문서 초안은 거의 전부 AI 코딩 에이전트가 썼다. 이 문서는 "AI가 만든 것을 어떻게 믿을 수 있게 했는가"를 기록한다. 수치는 모두 합성 데이터 기준이다.

## 1. 한 줄 요약
- **AI가 한 일**: 설계 구체화, 조사, 코드, 테스트, 평가 하네스, 문서 초안.
- **장치가 한 일**: AI가 만든 결과를 AI와 독립된 방법으로 검사했다(독립 검사기, 정답 라벨, 홀드아웃, 뮤턴트, 누수 검사, 계약 테스트, 실제 모델 점검).
- **사람이 한 일**: 방향과 원칙 결정(엔드픽처, 현업 공감 원칙, 범위), 라벨 승인, MVP 뒤 가정 검토.

## 2. 작업 방식 (CLAUDE.md 규칙을 실제로 지킨 방법)

| 규칙 | 실제 장치 | 어디에 |
|---|---|---|
| 테스트 먼저, 작게 커밋 | 기능마다 실패하는 테스트를 먼저 쓰고 통과하면 커밋. 커밋 365개, 테스트 함수 755개(매개변수 전개 전, 2026-11-12 main 기준) | `tests/` |
| 설계와 다르면 이유를 먼저 | 코드보다 DECISIONS.md를 먼저 고친다. 설계 가정은 "MA-" 번호로 모아 MVP 뒤 검토 | `docs/DECISIONS.md` |
| 배정과 계산은 결정적 코드 | LLM은 도구가 거른 후보 중 선택, 설명, 추출, 질문 해석만. 실행은 게이트웨이 | `agent/`, `gateway/` |
| LLM 교체 가능, 기본은 가짜 | 키 없이 전 테스트 통과(NFR-1). 실제 모델은 환경 변수와 합성 데이터 확인이 모두 있을 때만 | `agent/llm.py` |
| 현업 공감 원칙 | 1차 출처 조사 기록, 조사 에이전트 결론도 원문 재확인, 근거 없으면 "설계 가정" 표시 | `docs/검토/` |

## 3. 통제 장치와 잡아낸 결함

AI가 쓴 코드가 "그럴듯하지만 틀린" 경우를 장치가 잡았다. 아래는 실제로 잡힌 것만 적는다.

| 장치 | 무엇을 독립적으로 보나 | 잡아낸 결함 |
|---|---|---|
| 독립 파이썬 검사기 ↔ SHACL 교차 확인 | 같은 규칙을 다른 두 구현으로 | 생성기가 공기감염 환자를 1인실에 배치(600건 중 242건), SHACL 결과에서 URI 콜론 분리로 격리 위반 누락, 동명이인 집계 단위 차이 |
| 회귀 시나리오 30개 (사람 승인 라벨, 다중 에이전트 토론으로 기초부터 재검토) | 결과 수준 정답 | 중단 중 만료된 타이머가 재개 뒤 발화하지 않음(C01), B02가 엉뚱한 이유로 통과(라벨 보강) |
| 홀드아웃 (마일스톤에만, 횟수 기록) | 개발 중 보지 않은 상황 | "병상 없음" 뒤 상황이 바뀌어도 에이전트가 다시 찾지 않음(H02). 실행기가 에이전트 대신 손으로 쓴 제안을 넣던 하네스 결함 |
| 뮤턴트 민감도 (G4) | 안전 장치를 하나씩 끄면 시나리오가 실패하는가 | 평가 세트의 빈틈(수용 회신 없이 확정)을 표에 기록 |
| 미래 정보 누수 검사 (S4) | 판단 시점 뒤 이벤트를 썼는가 | 0/3000. 몬테카를로 추정도 같은 원칙으로 테스트 |
| 시나리오 ID 누수 검사 | 평가 대상 코드가 정답을 아는가 | 주석에 시나리오 ID를 쓴 2건(E02, D05)을 테스트가 막음 |
| 계약 테스트 (FHIR 이중 실행) | 경계 어댑터가 의미를 바꾸는가 | 시드 200개에서 이벤트 해시 동일. 잡음(중복, 순서, 누락) 보존 |
| 화면 스크린샷 확인 | 실제로 그려지는가 | SQLite 스레드 오류, Streamlit 자동 출력이 코드 설명을 화면에 뿌림 |
| 실제 모델 성능점검 (P1 지표) | 대체 경로가 결과를 가리는가 | 계획 프롬프트에 "json" 단어가 없어 OpenAI JSON 모드가 모든 호출을 거부. 에이전트는 매번 규칙 모드로 내려갔고 회귀 통과율은 그대로라 통과율만 봤다면 놓쳤다. 질의 해석 형식 불일치(인자를 중첩, 한국어 값) |
| 조사 원문 재확인 | 조사 에이전트의 결론 | 에이전트가 "틀린 링크"라 한 두 출처가 원문 확인 결과 맞았다. 반대로 작업자 자신의 오류("지침에 환기 수치 없음")를 원문 부록 3으로 정정 |
| 사람의 원칙 질문 | AI가 놓친 현실 | "FM과 현장 운영이 다를 수 있다"는 질문이 규칙 출처 계층(POL-1~3)과 지침 대비 표시로 이어짐 |

## 4. 사람이 결정한 것 (AI가 대신하지 않은 것)
- 엔드픽처: "퇴원부터 다음 입원까지 사람은 책임질 순간에만, 어느 병원이든 데이터만 넣으면 스스로 세팅" → 1단계/2단계 로드맵.
- 현업 공감 원칙을 CLAUDE.md에 추가.
- 회귀 30개 유지, 새 상황은 홀드아웃(A안), 관리자 직접 수정 허용 범위, 안전 예외 3단계의 방향.
- 라벨 승인(회귀 30, 홀드아웃 H01~H05). H06~H10과 추출 문장 200은 초안이며 MVP 뒤 검토.

## 5. 숫자로 본 현재 상태 (합성 데이터 기준 추정)
- 회귀 30/30, 홀드아웃 10/10(2회차, 블라인드 한계는 RESULTS.md에 기록).
- 안전(점검 대상이 서로 다르다): 기존 방식 기준선 배정 기준 위반 0/6000(퇴원 6,000건), 종말소독 누락 0/600, 미래 정보 누수 0/3000. 에이전트가 실제로 실행한 배정·청소·입실 호출의 사후 점검은 0/761(README 핵심 결과).
- 가용 병상 추정(15:00 기준): MAE 0.59, 약한 기준선 1.44, 강한 기준선 1.33. 분포 이동 홀드아웃에서도 기준선보다 작다.
  - 다만 명목 80% 구간(P10~P90)의 실제 포함률이 96.3%(95% 구간 89.6~98.7%, 시드 0~7)로 **구간이 과대**하다. 보정 전이며, 시험은 하한(0.7)과 상한(0.99, 퇴화 방지)을 함께 건다.
- 모델 점검 결과는 `docs/모델_성능점검표.md`.

## 6. 한계 (정직 표기)
- 정답 라벨 초안, 홀드아웃, 추출 문장을 모두 작업자(AI)가 썼다. 사람 승인이 있어도 작업자에게 블라인드가 아니다. 진짜 블라인드 평가는 병원 현직자가 만든 사례로 해야 한다.
- 합성 생성기와 추정기의 과정 모형이 같은 구조라 dev 수치는 낙관적이다. 그래서 분포 이동 홀드아웃을 따로 잰다.
- 현직자 인터뷰가 없다. 근거를 찾지 못한 값은 "설계 가정"으로 표시했고 목록은 SPEC 1.5절과 DECISIONS의 MA 항목에 있다.
