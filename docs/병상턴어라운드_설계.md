## 이 에이전트가 하는 일
병원은 환자가 퇴원해도 침대가 바로 비지 않습니다. 퇴원약, 수납, 이송, 청소를 거치는 몇 시간 동안 다음 환자는 기다립니다.
이 에이전트는 전날 퇴원, 청소, 다음 환자 입실까지 계획을 세워 각 부서에 공유하고, 당일 실제 진행이 계획과 어긋날 때만 계획을 고치거나 꼭 필요한 한 사람에게 요청합니다. 확인이 필요한 결정만 사람에게 넘기기 때문에 병상관리 담당은 예외 사례만 보면 됩니다.

### 미리 계획하기
전날 퇴원 예정, 퇴실 예상 구간, 청소 예정표, 사전 매칭을 만들어 각 부서에 공유

### 어긋나면 고치기
당일 실제 진행을 계획과 비교해 어긋난 곳만 계획을 갱신하고 대기 정보를 공유

### 사람은 예외만
격리, 중환자, 소아처럼 확인이 필요한 사례만 병상관리 담당이 검토

## 병목과 자동화 후보

### 배정 자동화 현황
서울아산병원은 진료과, 성별, 중증도, 수술, 격리 등 50여 개 기준으로 배정을 자동화했습니다. 세종병원은 5분 간격으로 입원 대상과 빈 병상을 확인하고 예외는 담당자에게 알립니다.
서울아산병원 소식지, 라포르시안

### 퇴원 후 공백
정규 퇴원은 하루 전 주치의가 결정합니다. 퇴원약, 진료비 심사, 수납, 퇴실, 정리를 거쳐야 병상이 다시 쓰입니다. 국내 개선 사례는 협진, 검사와 시술 예약, 퇴원 결정, 퇴원 수속 지연을 재원일수 요인으로 꼽았습니다.
서울아산·한양대병원 입퇴원 안내, 정경숙 외 2008

### 정오 병상 부족
병실이 부족하면 입원 당일 정오경 환자에게 입원일 변경을 연락합니다. 해외 소아 병동 연구는 정오 전 퇴원을 늘려 병상 가용성을 높였습니다(아래 수치).

### 자동화 후보 비교

### 1. 퇴실 전
퇴원 확정에서 퇴실까지
- 계획: 퇴원 예정 확인, 퇴실 예상 구간 공유
- 편차 시: 미등록과 변경은 병동에 확인 요청, 퇴원약, 수납, 교육, 보호자 지연은 계획 갱신과 사유 코드 기록
사람: 퇴원약 조제 순서(약제), 보호자 연락과 퇴원 교육(병동)

### 2. 병상 준비
퇴실에서 병상 준비 완료까지
- 계획: 청소 예정표를 환경과 병동에 공유
- 편차 시: 실제 퇴실 시 예정표 항목을 청소 요청으로 확정, 완료가 늦으면 준비 시각 재추정
사람: 청소와 소독 인력 배치(환경), 침상 정리(간호조무사나 병동지원인력, 병원별 설정)

### 3. 입실
병상 준비에서 다음 환자 입실까지
- 계획: 사전 매칭과 입실 예상 구간
- 편차 시: 입원 취소와 매칭 깨짐은 재매칭안을 만들어 병동에 수용 가능 여부 문의, 입실 부하 표시
사람: 수용 가능 회신(책임간호사), HIS 확정과 입실 안내(원무), 담당 검토(병상관리 담당)
현장 AX 3단계, 사람 개입

### 확인 등급별 경로
- 자동: 대기 정보 공유, 준비 시각 재추정, 청소 예정표 갱신과 청소 요청 발송은 사람 없이 실행
- 병동 확인: 1단계는 병상관리 담당 확인 뒤, 2단계로 승격된 유형만 담당 확인 없이 병동에 수용 가능 여부 문의. 수용 가능 회신이면 원무가 HIS 확정, 수용 불가 회신이면 사유와 재매칭 후보 2개를 병상관리 담당에게 전달
- 담당 검토: 병상관리 담당 검토 뒤 병동에 수용 가능 여부 문의
- 환자 연락이 되돌릴 수 없는 분기점. 연락 전 취소는 보상 단계(퇴실 전이면 청소 예정표 항목과 사전 매칭, 퇴실 후면 확정된 청소 요청을 되돌리는 절차)가 자동 해제, 연락 후 취소는 담당 검토로 바꾸고 재연락을 사람 작업으로 생성

### 담당 검토로 분류하는 사례
- 격리 오더 환자, 감염 선별검사 결과 대기 (선제 격리)
- 중환자실 하향 전동, 응급실 입원 대기 (우선순위 상위)
- 소아, 낙상과 섬망 위험이 높은 환자
- 1인실과 상급병실 희망 (병실료 차액 동의)
- 동명이인, 조건에 맞는 병상 없음, 1·2순위 점수 차가 정책 파일 기준값 미만인 매칭
- 간호·간병통합서비스 병동 배정 (환자 동의 필요)
- 격리 퇴실 병실에 다음 환자를 매칭하는 건 (청소 요청은 종말소독 유형으로 자동 발송, 소독 확인 전 매칭 확정과 빈 병상 전환 금지)
- 성별, 진료과, 격리 여부 입력 누락

## DB와 온톨로지

### DB
원천 데이터와 상태 변화를 저장합니다. 이벤트는 고치지 않고 추가만 하는 기록으로 SQLite에 두고, 현재 상태는 이 기록을 다시 계산해 만듭니다.

### 온톨로지
개념 사이의 관계를 정리한 지도입니다. 관계를 한 번 적어 두면 규칙을 하나하나 코드로 쓰지 않아도 프로그램이 연결합니다.

### 개념 계층 예시
결핵 의심 → 공기감염 격리 필요 → 격리 필요
음압격리실 → 1인실 → 병실
"공기감염 격리 필요 환자는 음압격리실만"을 한 번 적으면, 새 질환은 "공기감염 격리 필요"의 하위 개념으로 한 줄만 추가합니다. 하위 개념 연결은 SHACL이 rdfs:subClassOf 사슬을 직접 따라가 처리하고, 속성 계층 같은 추가 추론이 필요할 때만 pySHACL의 RDFS 추론 옵션을 켭니다.

|---|---|---|
| 환자, 입원 | Patient, Encounter |  |
| 병동, 병실, 병상 | Location | physicalType으로 구분, partOf로 계층 연결 |

## 내부망 보안

### 병원 내부망
서버, DB, 온톨로지, LLM을 병원 서버실에 둡니다. 병원 안 프로그램끼리 쓰는 API는 내부망 밖으로 나가지 않습니다. 외부 환경 업체에는 병상 번호, 예상 시각, 청소 유형만 보내고 환자 정보는 보내지 않습니다.

### 로컬 LLM
에이전트는 병원 서버의 작은 LLM을 씁니다. 운영에서는 외부 AI API를 쓰지 않고, 외부 모델 비교는 개발 단계에서 가상 데이터로만 합니다.

### 권한과 기록
도구 권한은 사례와 행동 단위로 짧게 발급하고, 매칭, 회신, 취소는 모두 감사 로그에 남깁니다.

### 성공 기준
- 배정 기준 위반 0건, 종말소독 누락 0건, 인젝션 문장에 판단이 바뀐 사례 0건
- 재시작과 퇴원 취소 후에도 사례 상태 유실 없음
- 담당 검토 사례가 모두 병상관리 담당에게 전달됨

### 중단 기준
- 배정 기준 위반 1건 발생 시 자동 경로를 멈추고 1단계로 복귀
- DB에 없는 사실을 답하면 질의 응답 기능을 끔
회귀 시나리오는 격리 오더 추가, 동명이인, 퇴원 취소, 입원 취소, 퇴원 예정 미등록, 보호자 도착 지연, 청소 완료 지연, 격리 퇴실의 종말소독 누락, 동시 매칭, 권한 없는 조회, 인젝션 문장처럼 규칙이 막아야 하는 사례입니다. 결과는 합성 데이터 기준 추정으로 쓰고 병원 발표 수치와 비교하지 않습니다.
현장 AX 5·6단계, 확산과 운영

## 단계적 확산

### 자동 범위 넓히기
유형별로 섀도 일치율(PoC에서는 회귀 정답 일치율), 사후 취소율, 검토 담당 피로를 함께 보고, 2단계 기준을 넘은 유형만 정책 변경 승인을 거쳐 넘깁니다. 지표가 나빠지면 1단계로 되돌립니다. 기준값은 가상 데이터로 조정한 설계값입니다.

### 인접 공정
- 2단계: 응급실 입원 대기와 정규 입원 연기 판단
- 3단계: 수술 일정 변경과 입원 예약 연동
- 분리 지점: 응급실 대기와 수술 연동은 사례 단위와 목표가 달라져, 공정별 도메인 에이전트와 병상 자원을 중재하는 조정 에이전트가 필요
- 환자 이송: 이송 요청 상태를 지연 단계로 추적 (배차는 이송팀 체계 유지)
- 입실 안내: 원무 승인 후 자동 발송 (되돌릴 수 없는 환자 연락이라 담당 검토 등급)
- 피지컬 AI: 청소 완료 신호를 사람(환경 앱, 버튼)과 장비(향후 소독 장비 완료 이벤트)가 같은 형식으로 보내, 장비가 붙어도 이후 흐름은 바뀌지 않음. 장비 운용은 감염관리와 환경 소관
기록 취소, 수정 이유와 사후 결과(재배정, 감염 사건)로 라벨 보정, 병상관리 담당 검토 후 사례 기억에 반영
→
분석 반복되는 이유를 규칙 개선 후보로
→
검증 회귀 세트와 섀도 모드로 기존보다 나은지 확인
→
반영 병원 규칙이라 반영은 사람이 결정
