## 2. 이미 지적됐지만 코드에 아직 반영되지 않은 것(다시 확인만 함)
- **간호 확정 단계(심사 요청)**: 서울성모 원문은 "주치의 퇴원확정 → 간호사 확정 → …"이다(위 PDF). 대구가톨릭 원문은 "퇴원통보(의사) → 간호확정(간호사데스크) → 심사완료(심사평가팀) → 계산(원무부)"이다(직접 확인). 2단계 검수 M3(전북대 "간호사가 진료기록부를 정리한 후 … 퇴원심사를 요청")과 같은 지적이다. 사건 타입 `BILLING_REVIEW_REQUESTED`는 `events/models.py:95`에 정의만 있고 내는 곳이 없다. 생성기는 심사 시각을 `order + 20~60분`으로 뽑는다(`sim/generator.py:261`). 병동이 바빠서 생기는 심사 지연은 아직 병동 몫으로 잡히지 않는다.
- **야간·휴일 가퇴원**: 건국대 원문 "공휴일 및 야간 (평일 : 17:30 이후, 토요일 : 12:30 이후) 에는 진료비 심사가 불가하여 부득이 가퇴원"과 대구가톨릭 원문 "정상 근무시간(평일 17:30 이후, 토요일 12:30 이후) 외 또는 휴일 … 가퇴원"을 직접 확인했다. 코드에는 가퇴원 경로가 없다(`grep 가퇴원` 0건). 2단계 검수 "빠진 예외"에 있다.
- 교대 시각이 병원마다 다른 점, "올려주세요"를 병동의 행동으로 둘 점, 병동 준비를 침상 쪽과 기록 쪽으로 나눌 점, 13:30 일괄 침상 정리, 이의 기한 검사는 1단계 검수 M-5·M-6·M-8과 원무 M-8에 있다.

## 3. 확인했고 현실과 맞는 것
- 기본 확인 방식이 통보형인 것(`config/profiles/field_default.yaml` `ward_confirmation.mode: notify`): 판결 원문 "원무팀으로부터 환자 입원을 통보받은 간호사는 환자가 입원할 수 있도록 병상을 준비한 후 …"와 맞는다.
- 연락 뒤 이의는 담당 검토와 재연락 작업으로 간다(`gateway.py:898-902`). 환자에게 다시 연락하는 일은 원무 몫이라는 점과 맞는다.
- 현장 프로필의 입실 시간창 14:00~17:00, 퇴실 마감 11:00, 보호자 대기 라운지: 서울성모 PDF 원문 "입실 14:00 ~ 17:00 · 퇴실 09:00 ~ 11:00", "부득이하게 … 중앙휴게실을 사용"과 맞는다.
- 퇴원약을 수납 뒤 간호사실에서 주는 흐름(현장형 기본): 건국대 "퇴원심사 완료 후 병동 간호사 확인 후 … 수납", "퇴원수납 완료 후 간호사실에서 퇴원약", 대구가톨릭 "퇴원계산 후 병동간호사에게 약을 받아 귀가"와 맞는다(W-3의 교육 시점만 다름).
- 병동 화면은 자기 병동 환자만 본다(`api/app.py:203` 근처 `may_view`). 병상이 없으면 진료과 담당 병동을 기준으로 본다. 원무 배정·병동 통보 구조와 어긋나지 않는다.
- 통합병동 동의 미확인을 자동 승격 금지 목록에 둔 것(`gateway/profile.py:120-123`): 환자 동의 사안이라 맞다. 다만 W-2처럼 병동 속성이 빠져 있다.
