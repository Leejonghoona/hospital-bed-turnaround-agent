# 차별점 비평: 이 프로젝트는 왜 "있는 제품 다시 만들기"로 보이는가

- 작성일: 2026-11-09. 관점: 냉정한 비평가(병원 CIO 출신 투자 심사역). 상태: 검토 의견. 설계 변경이 아니다. 방향을 바꾸려면 `docs/DECISIONS.md`에 먼저 적고 사용자가 결정한다.
- 읽은 것: CLAUDE.md, `docs/기획/01_문제정의서.md`, `docs/기획/03_PRFAQ.md`, `docs/검토/조사범위/제품전략.md`, `docs/검토/조사범위/종합_결정안.md`, `docs/검토/현장조사/종합.md`, `docs/검토/현장조사/국내EMR_시스템.md`. 사실 확인용으로 `docs/모델_성능점검표.md` 결과 표, `docs/2단계_온보딩_스펙.md`, 저장소 구조(코드 줄 수, 테스트 수, 문서 수)를 봤다.
- 확인 수준 표시
  - **원문**: 이 세션에서 curl로 페이지를 받아 해당 문장을 직접 읽었다.
  - **검색 요약**: 검색 엔진 요약만 봤다. 원문과 다를 수 있다.
  - **저장소 기록**: 이 저장소의 다른 문서가 원문을 확인했다고 적은 것을 옮겼다.
- 숫자는 합성 데이터 기준 추정이거나 공급사·병원 발표다. 병원 발표 수치는 이 프로젝트 결과와 비교하지 않는다(CLAUDE.md 6번).

## 결론 먼저

1. **지금의 한 줄 설명("퇴원부터 입실까지 추적하고 빈 병상을 먼저 알리는 에이전트")은 병원 CIO에게 "Epic 병상관리 + 분당서울대 스누워드가이드 + 우리 원무팀 RPA"로 들린다.** 보는 기능, 청소 요청 자동 생성, 첫 배정 자동화는 이미 팔리거나 병원이 직접 만들었다.
2. **채용 담당자·검토자에게는 "규칙 엔진에 LLM 설명을 붙이고 '에이전트'라 부른 것"으로 보일 위험이 크다.** 회귀 30개를 가짜 LLM도, CPU에서 도는 2.4B 모델도 30/30 통과한다. 평가 체계가 LLM의 차이를 못 가려낸다는 뜻이고, 동시에 LLM이 하는 일이 거의 없다는 뜻이다.
3. **진짜 드문 것은 기능이 아니라 "증명 방식"과 "나쁜 날"이다.** 시스템이 실제로 실행한 것을 독립 검사기로 재생 검사하는 체계(실행 S1 0/410, S2 0/58, 장치 끄기 검사 14/14), 사망·급변 전동·격리 등록 누락 같은 비정규 경로, 한국 원무 절차의 세부(심사 → 수납 → 영수증 → 퇴원약, 가퇴원)다.
4. **추천: "나쁜 날 안전 증명"으로 좁힌다(아래 방향 2).** 정상적인 날의 효율은 남들이 이미 판다. 규칙이 깨지는 날에 운영 AI가 사고를 내지 않는다는 것을 재생으로 증명하는 프로젝트는 찾지 못했다. 첫 주는 방향 1(포장 다시 하기)을 같이 한다.
5. **중단 기준**: 허수아비가 아닌 비교 대상(상용 제품의 공개된 기본 동작을 흉내 낸 단순 규칙 시스템)도 같은 나쁜 날을 무사히 넘기면, 이 차별점은 가짜다. 그때는 방향 1의 "평가 체계 포트폴리오"로 물러난다.

### 1.1 병원 CIO가 보면

| 이 프로젝트가 내세우는 것 | CIO 머릿속에 바로 떠오르는 것 | 근거(확인 수준) |
|---|---|---|

| 병상 상태를 실시간으로 본다 | 분당서울대 스누워드가이드(2026-06): "병상별 가용 전환 여부와 입·퇴원 현황, 전실·전동 현황" 한 화면 | `제품전략.md` 2.1(저장소 기록, 원문 확인됨) |
| 배정을 자동화한다(규칙이 고르고 AI가 설명) | 서울아산(IBM, 50여 개 기준), 길병원(하루 17시간 → 10분), 세종병원(90.8%, 병원 발표), **중앙대광명병원 원무팀장이 직접 만든 RPA 병실 자동 배정** | 중앙대광명: 데일리메디 기사(원문, 이 세션). 나머지 저장소 기록 |
| 규칙 코어 + AI 보조 + 감사 로그 | 이지케어텍 "Agentic HIS → Medical OS", 상급종합병원 HIS 점유율 약 26%, 2026 IR에서 "메디칼 OS" 확장 선언 | 메디칼타임즈 2026-08-12(원문, 제목·도입부), 점유율은 증권사 보고서 검색 요약, Medical OS 세부는 `제품전략.md`(저장소 기록) |

CIO가 할 말을 그대로 적으면 이렇다.

- "그건 우리 HIS 공급사가 내년 로드맵에 넣었다. 별도 제품을 왜 들이나." 국내 경쟁자는 해외 제품이 아니라 **HIS 공급사와 병원 자체 개발**이다. 원무팀장이 RPA로 배정을 만드는 나라다.
- "HIS 연동이 '제외'면 이건 아직 아무것도 연결 안 된 화면이다." 실제 연동은 설계 문서가 제외했다. 병원 쪽에서 보면 이중 입력이 생긴다.
- "추적한다는 청소 완료 신호가 우리 전산에 없다." 국내 HIS에 청소 상태가 있다는 공개 근거는 네 번 조사해서 0건이다(`국내EMR_시스템.md` 1절 4번). 추적할 신호가 없으면 추적 제품도 없다.
- "하루 장면이 우리와 다르다." 공개 안내 14곳이 모두 당일 오전 배정이고 병동은 통보를 받는다. 설계의 "전날 17:40 사전 매칭"과 "병동 회신이 있어야 확정"은 근거가 없다(`종합_결정안.md` 1절).
- "누가 돈을 내나." 구매자가 정해지지 않았다(01 7절 1번).

## 3. 더 날카로운 방향 다섯 가지

모두 CLAUDE.md 안에서 움직인다. 합성 데이터만, 실행은 결정적 코드, LLM은 판단·설명·추출만, 청소·이송 인력 배정은 하지 않는다. "설계"·"제외" 항목(섀도 모드, 실제 HIS 연동, 알림톡 자동 발송, 연쇄 이동 최적화)은 건드리지 않는다.

노력: **S** = 1주 안, **M** = 2~3주, **L** = 4주 이상(작업자 추정, 설계 가정).

### 방향 1. 최소 피벗: "증명 키트"로 다시 포장한다

- **한 줄**: 기능은 그대로 두고, 이 저장소를 "병원 운영 에이전트가 안전하다는 것을 재생으로 증명하는 방법"의 실례로 다시 보여 준다.
- **누가 관심을 갖나**: 채용 담당자(평가·안전·신뢰성 직무), AI 평가 엔지니어, 의료정보학회 발표 심사자.
- **3분 데모**
  1. 0:00 한 문장: "판단은 에이전트, 실행은 게이트웨이. 그런데 그게 진짜인지 어떻게 아나?"
  2. 0:30 명령 하나로 50개 합성 날 재생 → 실행 S1 0/410, S2 0/58과 95% 상한을 보인다.
  3. 1:30 게이트웨이의 재확인 장치를 하나 끄고 다시 재생 → 어떤 시나리오가 빨갛게 되는지 보인다(뮤턴트).
  4. 2:30 "0/6,000은 자료 점검이었다"는 정정 기록을 보인다. 무엇을 증명했고 무엇을 못 했는지 한 표로 끝낸다.
- **잘라낼 것**: PRFAQ 보도자료와 가상 인용을 첫 화면에서 뺀다. README 첫 화면은 그림 한 장, 명령 세 줄, 결과 표 하나로. 기획 문서 00~06은 "깊이 읽기" 폴더로 내린다(이동은 사용자 결정).
- **만들 것**: 한 명령 데모 스크립트, 뮤턴트 결과 한 장 보고서, 3분 화면 녹화.
- **노력**: S.
- **위험**: CIO에게는 여전히 "기능은 남들 것"이다. 포트폴리오에는 효과적이지만 제품 차별은 생기지 않는다. 그리고 계획 평가가 LLM 차이를 못 가른다는 질문에 답이 없다.

### 방향 2. "나쁜 날" 전문: 규칙이 깨지는 날에 사고를 내지 않는 운영 AI (추천)

- **한 줄**: 정상적인 날의 효율은 버리고, 병상 운영이 위험해지는 날만 다룬다. 사망, 급변 전동, 격리 등록이 늦게 붙는 환자, 승인 대기 중 바뀐 정보, 가퇴원 야간, 서버 재시작, 메모 속 지시문.
- **누가 관심을 갖나**: 감염관리실(종말소독 누락, 격리 등록 누락), 간호부(사망 후 "빨리 비워 달라" 압력), QI·환자안전팀, CIO(사고 책임). 채용 쪽에서는 안전·신뢰성 직무.
- **3분 데모**: 같은 합성 하루를 두 시스템으로 나란히 재생한다.
  - 비교 대상: "상용 제품의 공개된 기본 동작" 흉내. 퇴원 처리 시 병상을 청소 대기로 바꾸고, 청소 완료면 빈 병상, 격리 정보는 차트 값을 그대로 믿음(Epic 공개 문구 기준). **허수아비로 만들지 않는다.** 공개 자료가 말하는 동작만 넣고, 출처를 화면에 같이 띄운다.
  - 0:00 장면 1, 격리 등록 지연: 감염 정보는 있는데 격리 등록이 2시간 늦게 붙는 환자. 비교 대상은 다인실에 배정해 확정한다. 이 시스템은 확정 직전 재확인에서 막고 감염관리실 검토로 돌린다.
  - 1:00 장면 2, 병동 사망: 비교 대상은 퇴원 예정 병상으로 보고 "퇴원약 지연" 작업을 띄운다. 이 시스템은 안치실 이송까지 배정을 막고 독촉 작업을 만들지 않는다.
  - 2:00 장면 3, 승인 대기 중 정보 변경 + 서버 재시작: 재시작 뒤 같은 청소 요청이 두 번 나가지 않고, 바뀐 정보로 배정이 다시 걸러진다.
  - 2:40 표 한 장: 나쁜 날 N개에서 두 시스템의 실행 위반 수, 각 장면의 현장 근거 출처(판결, QI, 지침 쪽수).
- **잘라낼 것**: 정상 날 효율 지표(북극성 퇴실 → 준비 시간)를 보고 지표로 내린다. 가용 병상 추정 다듬기(O3 개선)를 멈춘다. 화면은 나란히 재생 하나만. 온톨로지 확장 중단.
- **만들 것**
  - 생성기에 "나쁜 날" 사건 묶음: 격리 등록 지연(53% 근거, 별도 난수 흐름으로 기존 시드 결과 보존), 가퇴원 야간, 정보 변경, 사망·급변 전동(이미 있음)을 섞은 날.
  - 비교 대상 시스템(결정적, 공개 문구 기반, 200~400줄 예상).
  - 나쁜 날 점수판: 실행 위반, 사람 확인 횟수, 퇴원 독촉 작업 오발생 수.
  - 각 장면에 근거 표(출처, 확인 수준). 이미 `docs/검토/`에 대부분 있다.
- **노력**: M.
- **위험**
  - 비교 대상이 허수아비라는 비판. 막는 법: 공개 문구만 쓰고, 비교 대상이 이기는 장면도 숨기지 않는다.
  - 상용 제품이 실제로는 이런 경우를 이미 처리할 수 있다(내부 규칙은 공개되지 않음). 그래서 주장은 "상용 제품보다 낫다"가 아니라 "이런 날을 재생으로 증명할 수 있다"로 한정한다.
  - 현직자가 "그런 일은 거의 없다"고 하면 의미가 줄어든다. 설문 답으로 확인한다.
  - 격리 등록 지연은 설계 변경이므로 DECISIONS에 먼저 적어야 한다(`종합_결정안.md` 3.1 G항과 같은 일).

### 방향 3. 대담: "병원 병상 운영 에이전트 시험장" (Korean inpatient ops agent arena)

- **한 줄**: 이 저장소를 제품이 아니라 **누구의 에이전트든 꽂아서 안전과 판단력을 재는 공개 시험장**으로 바꾼다. 에이전트는 제안만 하고, 게이트웨이와 독립 검사기가 채점한다.
- **누가 관심을 갖나**: HIS 공급사의 AI 팀(이지케어텍처럼 "에이전틱 HIS"를 선언한 곳은 자기 에이전트를 시험할 판이 필요하다), 원내 LLM을 고르는 병원 정보전략실, 의료 AI 연구자, LLM 평가 직무 채용 담당자.
- **3분 데모**: 모델 셋(외부 API 하나, 원내 7B 하나, 원내 2.4B 하나)을 같은 나쁜 날 20개에 꽂는다. 각 모델이 낸 제안 중 위험한 것, 게이트웨이가 막은 것, 막지 못했으면 실행됐을 위반을 순위표로 보인다. "게이트웨이 없이 실행했다면" 열과 "게이트웨이 뒤" 열을 나란히 둔다.
- **잘라낼 것**: 제품 서사(PRFAQ, 사용자 페르소나, 출시 단계), 화면, 가용 병상 추정.
- **만들 것**
  - 에이전트 꽂는 인터페이스: 관측(이벤트, 도구 조회) → 제안(구조화된 행동) 형식 공개. LLM은 여기서 **판단(무엇을 제안할지)**만 하고, 실행은 게이트웨이가 한다. CLAUDE.md 2번과 맞는다. 단 지금은 규칙이 후보를 고르고 LLM은 설명만 하므로(DECISIONS U8), 시험장 모드에서 LLM에게 "후보 중 선택, 보류, 사람에게 올림" 권한을 주는 것은 DECISIONS에 먼저 적어야 한다. 기존 `select` 모드가 출발점이다.
  - LLM 차이가 드러나는 시나리오: 지금 회귀 30개는 모든 모델이 통과한다. 판단이 필요한 회색 사례(보호자 메모가 모호함, 두 안전 후보 중 사람에게 올려야 하는 경우, 메모 속 지시문)를 늘려야 순위가 생긴다.
  - 공개 순위표와 재현 명령.
- **노력**: L.
- **위험**
  - 사용자 없는 벤치마크가 될 수 있다. H-AdminSim(외래 행정, KAIST)과 비교당한다. 차별점은 입원 병상, 실행 관문, 실행 상태 안전 채점이어야 한다.
  - 모델들이 위험한 제안을 거의 안 하면 게이트웨이의 존재 이유가 데모에서 안 보인다. 이 경우 오히려 "게이트웨이가 필요 없는 수준"이라는 정직한 결과가 된다.
  - 범위가 커서 1단계 완료(CLAUDE.md 엔드픽처)가 늦어진다.

### 방향 4. "같은 하루, 다른 병원": 병원 규정 프로필로 재생 차이 보이기

- **한 줄**: 공개 병원 안내에서 확인한 운영 값(배정 시각, 입실 창, 퇴실 목표, 퇴원 단계 순서, 가퇴원 시각, 병동 확인 방식)으로 가상 병원 프로필 3개를 만들고, 같은 합성 퇴원·입원 수요를 각 프로필로 재생해 어디서 막히는지 비교한다. 실제 병원 이름은 쓰지 않고 "프로필 A·B·C"로 둔다.
- **누가 관심을 갖나**: 원무팀장·QI(우리 규정이 어디서 병목을 만드나), HIS 공급사 구축 PM(병원마다 설정이 다르다), 온보딩에 관심 있는 채용 담당자.
- **3분 데모**: 프로필 A(당일 08:30 배정, 14~17 입실, 통보형 병동), B(가배정 있음, 회신형 병동), C(심사 → 수납 → 약 순서, 휴게실 대기 있음)를 같은 날로 재생. "입실 창 안 준비율", "연기 연락 수", "사람 확인 횟수"가 프로필별로 어떻게 다른지 한 표. 그다음 "규정 문서는 X인데 재생상 실제는 Y" 차이 한 줄.
- **잘라낼 것**: 기본값 장면(전날 사전 매칭)을 주인공에서 내린다. 화면 다듬기.
- **만들 것**: `제품전략.md` 3.2의 1단계 수정 #1~#5(당일 배정 모드, 입실 창·연기 마감, 병동 확인 방식, 퇴실 전 단계 순서, 야간·휴일 모드)를 프로필 설정으로. 이는 이미 권고된 "1단계 수정"이라 새 범위가 아니다. 자동 생성(온보딩 에이전트 본체)은 하지 않는다. 손으로 쓴 프로필 3개까지만 한다. 자동 생성은 CLAUDE.md상 2단계다.
- **노력**: M(설정화 리팩터링이 크다).
- **위험**: 차이가 운영 규칙에서 기계적으로 나오는 것뿐이라 "당연한 결과"로 보일 수 있다. 공개 안내의 값이 실제 운영과 다를 수 있다(설계 가정 표시 필요). 그래도 현직자 공감에는 가장 직접적인 방향이다.

### 방향 5. "원내 LLM 선정 실험실": 병원이 모델을 고르는 방법을 판다

- **한 줄**: 병상 업무는 무대로만 쓰고, 주인공을 "내부망 병원이 어떤 LLM을, 어떤 장비로, 어떤 일에 써도 되는지 같은 하네스로 정하는 방법"으로 옮긴다.
- **누가 관심을 갖나**: 병원 정보전략실, 정보보호 담당, 원내 LLM을 도입하려는 HIS 공급사, MLOps·평가 직무 채용 담당자.
- **3분 데모**: 추출 홀드아웃에서 외부 API 약 97%, 원내 7B 92%, 2.4B 84%(합성 기준, 저장소 기록). 인젝션 짝 변화, 지연 P95, CPU 장비 조건. 그리고 "이 모델이면 LLM에게 맡겨도 되는 일 / 규칙으로 돌려야 하는 일" 결정표.
- **잘라낼 것**: 사가 확장, 화면, 추정기.
- **만들 것**: 계획 평가에 판단이 필요한 회색 사례 추가(방향 3과 공유), GPU 하나 기준 실측 한 줄, 결정표.
- **노력**: S~M.
- **위험**: 가장 흔한 주제다. 모델 비교표는 금방 낡는다. 병상이라는 도메인 강점이 묻힌다. 단독 방향보다는 방향 2·3의 부록이 맞다.

## 4. 추천: 방향 2 "나쁜 날 안전 증명" (첫 주는 방향 1을 같이)

### 이유
1. **이미 가진 드문 자산 셋을 한 장면에 묶는다.** 재생 증명(실행 S1·S2, 뮤턴트), 비정규 경로(사망·급변 전동, 구현됨), 1차 출처 현장 근거(판결, QI 53%, 지침 쪽수). 새로 만드는 양이 가장 적은데 차별이 가장 크다.
2. **"다시 만들기" 비판을 정면으로 피한다.** 정상 날 효율은 Epic·Qventus·분당서울대와 경쟁하는 싸움이고, 합성 데이터로는 이길 수도 없다(효과 수치를 쓸 수 없다, CLAUDE.md 6번). 나쁜 날의 안전은 합성 데이터로도 **증명 가능한** 유일한 주장이다. 안전은 0건과 상한으로 말할 수 있고, 병원 발표 수치와 비교할 필요가 없다.
3. **CIO 언어와 맞는다.** CIO가 AI 운영 도구를 거절하는 첫째 이유는 효율 부족이 아니라 사고 책임이다. "이 AI가 언제 멈추는지 보여 달라"에 답하는 데모다.
4. **채용 언어와 맞는다.** "에이전트가 무엇을 하나"가 아니라 "에이전트가 틀릴 때 무엇이 막나, 그걸 어떻게 아나"는 지금 AI 안전·신뢰성 직무가 가장 보고 싶어 하는 질문이다.
5. **현장 조사와 충돌이 적다.** 하루 장면이 현장과 다르다는 지적(당일 배정, 통보형 병동)은 정상 날의 이야기다. 나쁜 날 장면(격리 등록 누락, 사망 후 압력)은 현장 조사가 오히려 근거를 강화했다(`제품전략.md` 1.2).
6. **방향 3으로 자라날 수 있다.** 나쁜 날 묶음과 점수판은 그대로 시험장의 문제집이 된다. 방향 4의 프로필 작업도 나중에 나쁜 날 재생 위에 얹을 수 있다.

### 순서 제안(작업자 권고, 사용자가 바꿀 수 있음)
1. 1주: 방향 1 포장(README 첫 화면, 한 명령 데모, 뮤턴트 보고서). 동시에 DECISIONS에 "나쁜 날 사건 묶음(격리 등록 지연 포함)과 비교 대상 시스템" 결정을 먼저 적는다.
2. 2~3주: 비교 대상 시스템(공개 문구 기반), 나쁜 날 생성기 묶음, 나쁜 날 점수판, 나란히 재생 화면.
3. 설문 답이 오면: 장면 셋이 현직자 눈에 "있는 일"인지 확인하고, 아니면 장면을 바꾼다.

### 중단 기준 (하나라도 걸리면 방향 1로 물러난다)
- **K1. 차이가 없다**: 공개 문구 기반 비교 대상이 나쁜 날 묶음(최소 20개 날)에서도 실행 위반 0건이면, 이 시스템만의 안전 차이는 없다. 이때 비교 대상을 일부러 약하게 고쳐 차이를 만들면 안 된다.
- **K2. 현장이 아니라고 한다**: 현직자 설문·후속 질문에서 장면 셋 중 둘 이상이 "현장에서 거의 없다" 또는 "HIS가 이미 막는다"로 나온다.
- **K3. 3주 안에 3분 데모가 안 나온다**: 3주 끝에 장면 셋을 근거 표와 함께 3분 안에 재생하지 못하면 범위가 너무 크다는 신호다.
- 걸리지 않으면 다음 단계로 방향 3(시험장)을 검토한다. 그 전에 계획 평가에 LLM 차이가 드러나는 회색 사례가 있어야 한다.

### 하지 말 것(이 추천을 따를 때)
- 정상 날 효율 수치를 효과처럼 쓰지 않는다. 합성 데이터 기준 추정이고 병원 발표와 비교하지 않는다.
- 비교 대상에 특정 회사 이름을 붙여 "Epic보다 안전하다"고 말하지 않는다. "공개 문구가 말하는 기본 동작"으로만 부른다. 실제 제품의 내부 규칙은 모른다.
- 섀도 모드, 실제 HIS 연동, 알림톡 자동 발송, 청소·이송 인력 배정은 계속 범위 밖이다.

## 5. 이 비평의 한계
- 상용 제품의 실제 내부 동작은 모른다. 공급사 페이지와 기사만 봤다. "나쁜 날을 이미 처리한다"는 반례가 있을 수 있다.
- Qventus 페이지는 이 세션에서 403이라 검색 요약과 저장소 기록에 기댔다. 세종병원 기사도 저장소 기록이다.
- 채용 시장 반응은 작업자 판단이다(설계 가정). 근거 자료는 없다.
- 노력 추정(S/M/L)은 작업자 추정이다.
