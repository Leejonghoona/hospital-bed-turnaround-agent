# 차별점 검토: 현장에 남은 문제에서 찾기 (2026-11-09)

- 작성: 헬스케어 서비스 디자이너·현장 문제 발굴 관점의 검토 에이전트. 상태: **검토 의견(설계 변경 아님)**. 바꾸려면 `docs/DECISIONS.md`에 먼저 적고 사용자가 정한다.
- 출발점: 이미 있는 서비스를 다시 만드는 것은 차별점이 없다는 판단. 제품전략 검토(`docs/검토/조사범위/제품전략.md` 2.3절)가 이미 정리했듯 **상태판, 청소 요청·앱, 퇴원 예측, 첫 배정 추천, 자유 서술 추출은 상품화돼 있다.** 그래서 이 문서는 기능 목록이 아니라 **사람이 아직 전화·종이·기억·반복 설명·기다림으로 메우는 일**을 현장 자료에서 캐내고, 그중 기존 제품이 손대지 않은 것을 고른다.
- 읽은 것: `CLAUDE.md`, `docs/검토/조사범위/종합_결정안.md`·`제품전략.md`·`현장전문가.md`, `docs/검토/현장조사/` 전부(원무_병상배정_실무, 병동간호_실무, 감염관리_청소_실무, 유튜브_요약_A·B, 국내EMR_시스템, 사용자제공_원문·EMR요약, 종합), `docs/검토/응급실범위/종합.md`, 코드 구조(`src/turnaround/`의 `agent/qa.py`, `agent/extract.py`, `forecast/noon.py`, `saga/worklist.py`, `events/models.py`).
- 이 문서는 새 조사를 하지 않았다. 인용은 위 파일에 적힌 원문 인용을 옮긴 것이고, 확인 수준(원문, 검색 요약, 블로그·영상 = 존재 증거)은 원 파일 표시를 따른다. **블로그·영상은 "그런 일이 있다"는 증거일 뿐 빈도 근거가 아니다.** 수치는 출처의 값이며 이 프로젝트 결과와 비교하지 않는다(CLAUDE.md 6번).

## 결론 먼저

1. **기존 제품은 "보이게 하기"와 "첫 배정"을 풀었다. 남은 고통은 "약속"이다.** 누가 언제까지 무엇을 해 주기로 했는지(“11시까지 비워 드릴게요”, “2시에 올려 주세요”, “자리 나면 다인실로 옮겨 드릴게요”)가 전화와 기억에만 있고, 어긋나면 사람이 다시 전화해 다시 설명한다. 현장 자료에서 반복되는 장면은 거의 모두 이 모양이다: 하루 250건 배정 요청 전화·메시지, 연락 뒤 재배정, 퇴원 당일 부서마다 따로 거는 전화, 인계 누락, "계속 간호사 찾아가서 바꿔 달라고 요구", 격리 요청 전화 누락.
2. **그래서 차별점의 축을 "병상 상태 추적"에서 "조율 약속 추적과 번복 줄이기"로 옮길 것을 제안한다.** 이 프로젝트의 구조(추가만 하는 이벤트 저장소, 사례 사가, 실행 직전 재확인 게이트웨이, 재생 평가)는 상태판보다 약속 원장에 더 잘 맞는다. 약속은 시각·당사자·근거가 있는 이벤트이고, 깨지면 보상 단계가 필요하다. 사가가 원래 하는 일이다.
3. **제안 개념 8개 중 먼저 할 3개**: ① 연락 전 "지킬 수 있는 약속인가" 판단과 번복 최소화(A), ② 전화 대신 사례 원장: 문의 응답과 약속 추적(B), ③ 늦게 도착하는 안전 정보(격리 등) 뒤처리(D). 셋 다 근거가 원문 수준이고, 지금 코드(질의응답, 추출, 몬테카를로, 사가, 재확인 게이트웨이, 잡음 주입)를 그대로 쓰며, 합성 데이터로 시연할 수 있다. 크기 M, M, S~M.
4. **새 지표를 같이 판다.** 기존 제품의 성과 문구는 "배정 시간 17시간 → 10분", "안내 30분 앞당김"처럼 **속도**다. 이 프로젝트는 **신뢰도**를 잰다: 연락 뒤 번복 건수, 사람이 직접 답해야 했던 문의 수, 교대 때 사라진 약속 수, 늦은 격리 정보로 다시 짠 사례 수. 재생 평가 하네스가 이미 있어 이 지표들을 합성 데이터로 증명할 수 있다(수치는 "합성 데이터 기준 추정").
5. **하지 않을 것은 그대로다.** 청소·이송 인력 배정, 원내 전동 실행(GW-15 "설계"), 퇴원 예측 ML, 자체 현황판, 알림톡 자동 발송. 아래 개념 중 병실 변경 대기(F)는 "표시만"이고 이동을 짜거나 실행하지 않는다.

## 1. 현장에 남은 문제 (근거 모음)

열 설명
- **누가 겪나**: 직접 고통받는 사람.
- **근거**: 파일과 인용. [1차]/[QI]/[보도]/[블로그]/[영상] 표시는 원 파일의 등급.
- **얼마나 자주·얼마나 비싼가**: 출처에 있는 값만. 없으면 "빈도 모름".
- **기존 제품이 다루나**: 제품전략 2절 표와 현장조사에 인용된 공급사·병원 자료 기준.
- **차별화된 에이전트 해법**: 이 프로젝트 구조(에이전트 판단, 결정적 게이트웨이 실행, 이벤트 저장소, 사가, 합성 데이터)와 범위 규칙 안에서.

### P1. 배정 요청·문의가 전화와 메신저로 쏟아진다
| 항목 | 내용 |
|---|---|
| 누가 겪나 | 원무 배정 담당, 진료과, 응급실, 병동 책임간호사, 환자·보호자 |
| 근거 | 서울아산 자동화 전: 담당자가 퇴원 환자 목록, 병동 현황, 병상 변경 환자, 입원 예정자, 응급실 목록을 "일일이 파악", 진료과 요청이 "전화, 내부 그룹웨어 메시지"로 하루 약 250건 [1차 소식지, `현장조사/국내EMR_시스템.md` 1절 3번]. 병동: "ER에서 오는 전화 … 전화가 멈추지 않고 끊임없이 옴. 차지쌤이 … ER 니네들 좀 기다리라" [블로그, `병동간호_실무.md` 2.3]. 환자: "문의전화를 했는데 전화연결이 정말정말 너무 힘들었음", 아산 어린이 "원무과 대기가 길었다 … 78명 대기" [블로그, `원무_병상배정_실무.md` 1.2]. 사용자 제공 요약: "전산 반영이 늦으면 원무·응급실·외래가 병동에 전화해 준비 여부를 확인" [검증 전, `사용자제공_EMR요약.md` 4번] |
| 얼마나 | 한 병원 하루 약 250건(자동화 전). 다른 병원은 빈도 모름 |
| 기존 제품 | 아산·길·세종·분당서울대는 **배정 자체**를 자동화했다. Epic은 "without calling a unit"을 내세우지만 그 수단은 상태판이다(`제품전략.md` 2.2). 국내 보도 어디에도 진료과·응급실의 **요청과 문의를 받아 처리하는 창구**는 없다. 세종병원은 원무 자유 서술을 배정 조건 추출에 쓴다(같은 표) |
| 에이전트 해법 | 자유 서술 요청을 받아 "상태 문의 / 우선 요청 / 약속 / 이의"로 분류하고, 상태 문의는 이벤트 원장에서 근거 레코드를 붙여 답한다(없으면 "기록 없음"). 진짜 판단이 필요한 것만 사람 큐로. → 개념 B |

### P2. 퇴원 당일 사슬(심사 → 수납 → 영수증 → 퇴원약 → 교육)이 부서마다 따로 돈다
| 항목 | 내용 |
|---|---|
| 누가 겪나 | 병동 간호사, 원무 심사·수납, 약제부, 퇴원 환자·보호자, **그 병상을 기다리는 다음 환자** |
| 근거 | "퇴원 처방이 난 환자의 챠트를 진료비계산부서에 접수한 후 수납까지 소요시간은 평균 252.5분"(2008) [QI, `병동간호_실무.md` 3.3]. "오더 바껴서 심사 풀고 다시 심사 넣는다고 늦게 가게 되고" [블로그, 같은 곳]. 해운대백: 수납 연락은 "전화 통보가 가장 많았고", "퇴실이 늦은 요인으로는 서류발급, 점심식사 후 보호자 도착" [QI, 같은 곳]. 양산부산대 원인: "퇴원 약 조제 지연, 심사 지연, 인력 부족" [QI, 같은 곳 3.1]. "퇴원약 드렸다, 원무과·영양과 알렸다" [영상, `유튜브_요약_B.md` 13.1-6]. "퇴원약을 하나 빠뜨림" [블로그, `병동간호_실무.md` 3.3]. 순서가 병원마다 반대(서울성모 교육 → 납부, 강북삼성 영수증 → 약) [1차, `원무_병상배정_실무.md` 4.3] |
| 얼마나 | 지연 사유 분포: 갑작스런 통보 27%, 수술 지연 24%, day care 20% 등(한 병동, 학생 보고서 미리보기). 퇴원 지연 "대략 20%" 관찰. 일반화 금지 |
| 기존 제품 | Qventus "care gap orchestrations"(PT, MRI, 사례관리 상담), LeanTaaS 퇴원 장벽은 **미국 장벽**이다(`제품전략.md` 2.2). 제품전략 2.3: "한국형 장벽(심사→수납→영수증→약, 가퇴원, 보호자 1인 상주)은 해외 제품이 모름. 차별 여지 있음." 국내는 울산대 "하이패스 퇴원"(절차 개선), 알림톡 수납 안내뿐 |
| 에이전트 해법 | 사례마다 "지금 어느 고리가 다음 환자의 입실 창을 막는가"를 판단하고, 그 고리의 주인에게 **한 가지** 행동만 제안(심사 우선 요청, 휴게실 대기 안내, 처방 수정 → 심사 재시작 예상 시각 공유). 계산(남은 시간, 입실 창 위험)은 도구가, 어느 고리를 누구에게 먼저 짚을지와 설명은 에이전트가. → 개념 C |

### P3. 보호자 사정이 "몇 시간 지연"이 아니라 "퇴원일 변경"이 된다
| 항목 | 내용 |
|---|---|
| 누가 겪나 | 병동 간호사(보호자·의사 사이 연결고리), 간호·간병통합 병동, 원무(다음 날 배정), 다음 입원 환자 |
| 근거 | 보호자가 내일 못 와 "토요일날 퇴원하겠다는 내용을 보호자분께 연락" [영상, 아주대 통합서비스 병동, `유튜브_요약_A.md` 14.1-5]. "보호자는 병실 내에서 상주할 수 없으나" [1차, 일산병원, `사용자제공_원문.md` 3절]. "퇴원하는 날 아침에도 병동에 올라갈 수 있는 사람은 그 한 명입니다" [블로그, `원무_병상배정_실무.md` 7절]. 서울성모 "부득이하게 11시에 퇴실이 어려울 경우에는 중앙휴게실을 사용" [1차, 같은 곳] |
| 얼마나 | 빈도 모름(현직자 질문 대상) |
| 기존 제품 | 국내 없음. LeanTaaS가 디스차지 라운지 연계를 말한다(미국) |
| 에이전트 해법 | 보호자 통화 메모를 "당일 지연 / 일자 변경 / 귀가 수단 없음 / 연락 두절"로 가르고, 일자 변경이면 사가가 퇴원 보류 경로로 가며 내일 배정 초안을 다시 계산하게 한다. 당일 지연이면 휴게실 대기(정책 스위치)로 병상을 먼저 비우는 안을 제안. → 개념 C에 포함 |

### P4. 연락한 뒤에 배정이 바뀌거나, 연기 연락이 늦다
| 항목 | 내용 |
|---|---|
| 누가 겪나 | 환자·보호자(출발·휴가·수술 일정), 원무(재연락), 진료과(수술 일정 조정), 병동(엉뚱한 침상 준비) |
| 근거 | "입원 당일 오전에도 2인실 배정으로 안내받았다 / 그런데 한 시간쯤 뒤 2인실 환자분의 퇴원이 / 갑자기 다음 날로 밀렸다고 해서 / 다시 4인실로 배정받았다 / 병실 배정은 변수의 연속이다" [블로그, 신촌세브란스, `원무_병상배정_실무.md` 1.2]. 강남세브란스 "입원 당일 병실 배정 문자를 받으신 이후에도 입실 전까지 배정 병실의 종류와 등급이 변경될 수 있습니다" [1차, 같은 곳 1.1]. 분당서울대 "업무 종료 시까지 연락을 받지 못한 경우 해당일에는 입원이 불가능", "수술 등 일정 조정이 필요한 환자분께는 진료과에서 별도 연락" [1차, 같은 곳]. 연기 연락 마감이 10시(세브란스, 아산 어린이)와 정오(아산 본원)로 다르다 [1차] |
| 얼마나 | 빈도 모름. 비용은 크다: 수술·시술 연기, 헛걸음, 재연락 |
| 기존 제품 | 분당서울대 스누워드가이드는 "안내 시점 30분 이상 앞당김"(병원 발표)을 성과로 든다(`제품전략.md` 2.1). **빠르게 알리기**이지 **틀리지 않게 알리기**가 아니다. 알림톡 자동 발송은 흔하다. 번복을 재거나 줄이는 기능을 내세운 제품은 찾지 못했다 |
| 에이전트 해법 | 연락 직전에 "이 병상이 입실 창 안에 실제로 준비될 확률"을 도구가 계산하고(몬테카를로), 에이전트가 근거(퇴원 처방 상태, 보호자 메모, 청소 일괄 시각)를 엮어 "지금 확정 연락 / 등급만 안내 / 마감까지 보류 / 대안 병상과 함께 안내"를 권한다. 게이트웨이는 위험이 높으면 확인 등급을 올린다. 번복이 생기면 영향받는 환자를 한 번에 모아 재연락 초안을 만든다. → 개념 A |

### P5. 원무는 통보하고 병동은 전화로 이의를 건다, 그리고 부하를 게임한다
| 항목 | 내용 |

- 자유 서술에서 배정 조건 추출: 세종병원.

## 2. 차별화 개념 8개

공통 원칙
- 숫자와 배정은 도구(결정적 코드)가, 판단·설명·자유 서술 해석은 에이전트가, 실행은 게이트웨이가 한다(CLAUDE.md 2번).
- 각 개념의 "진짜 에이전트다운 부분"은 규칙만으로는 잘 안 되는 것만 적는다. 규칙으로 되는 부분은 규칙으로 하라고 따로 적는다.
- 크기: S(며칠, 기존 모듈 확장), M(1~2주, 새 이벤트·시나리오·테스트), L(새 하위 시스템). 이 코드베이스 기준 추정.
- 모든 수치는 "합성 데이터 기준 추정"으로 보고하고 병원 발표와 비교하지 않는다.

### 개념 A. 약속 지키기: 연락 전 "지킬 수 있나" 판단과 번복 최소화

| 항목 | 내용 |
|---|---|
| 한 줄 | "빨리 알리는" 배정이 아니라 **"다시 연락할 일 없게 알리는"** 배정. |
| 사용자 | 원무 입원 파트(당일 오전 배정·연락 담당) |
| 푸는 고통 | P4(연락 뒤 번복, 연기 연락 마감), P2·P3의 영향이 다음 환자에게 번지는 것 |
| 기존 제품이 안 하는 이유 | 기존 성과 지표가 속도(17시간 → 10분, 안내 30분 앞당김)다. 번복률은 재지 않는다. 배정 추천은 "지금 빈 병상"이나 "퇴원 예정 병상"을 고르고, 그 퇴원이 실제로 입실 창 안에 끝날지를 단계별로 추적하지 않는다(길병원·분당 보도에 단계 지연 추적 없음, `제품전략.md` 1.2) |
| 진짜 에이전트다운 부분 | (1) 숫자로 안 잡히는 신호를 엮는 판단: 보호자 통화 메모("내일 오후에나 갈 수 있어요"), 처방 수정 기록, 병동 전달사항, 청소 일괄 시각을 보고 "이 확률 숫자를 믿어도 되는가"를 판단한다. (2) 행동 선택: 확정 연락 / 등급만 안내 / 마감까지 보류 / 대안 병상과 함께 안내 중 무엇을 권할지, 왜인지 설명. (3) 번복이 생기면 영향받는 환자들을 묶고, 각 환자에게 이미 무엇을 말했는지(이벤트)를 보고 재연락 초안을 쓴다. 확률 계산 자체는 `forecast/noon.py`의 몬테카를로(결정적 코드)가 한다 |
| 게이트웨이가 하는 일 | 연락(`PATIENT_CONTACTED`) 직전 재확인. 준비 확률이 정책 임계값 아래면 확인 등급을 "담당 검토"로 올림. 연락 뒤 변경은 이미 "담당 검토와 재연락"(SAG-4) |
| 합성 데이터 시연 | 쉽다. 생성기에 이미 보호자 지연·처방 수정·청소 지연·입원 취소가 있다. 연락 시각(10시/정오 설정)을 기준으로 "기존 방식(퇴원 예정이면 연락)" 대 "약속 판단"의 번복 건수와 연기 연락 마감 전 판단 비율을 재생으로 비교 |
| 위험 | 보수적으로 굴면 연락이 늦어진다(번복은 줄고 대기는 늘 수 있음). 두 지표를 함께 보고해야 한다. 확률 보정이 합성 분포에 묶인다. "연락 내용 확정 = 원무, 발송 = 기존 알림톡"(종합 (b) 20번)과 맞춰야 한다 |
| 크기 | **M**. 기존: 몬테카를로, `PATIENT_CONTACTED`, 사가 보상, 확인 등급. 새로: 연락 판단 도구, 번복 지표, 시나리오 4~6개, 당일 오전 배정 모드(종합_결정안 3.1 B)와 함께 |
| 확인할 증거 | 현직자: "배정 연락 뒤 바뀌는 일이 한 주에 몇 번인가", "연기 연락은 무엇을 보고 정하나"(종합 (d) 질문 1·5와 함께). 공개: QI 초록집의 "입원 연기·번복" 주제 검색. 반증 조건: 번복이 드물고 비용이 작다는 답이 많으면 A를 낮춘다 |

### 개념 B. 전화 대신 사례 원장: 문의 응답과 조율 약속 추적

| 항목 | 내용 |
|---|---|
| 한 줄 | "그 환자 언제 올라와요?"에 사람이 아니라 **근거가 붙은 원장**이 답하고, 전화로 한 약속은 기한과 주인이 있는 기록이 된다. |
| 사용자 | 원무 배정 담당, 병동 책임간호사, 응급실, 진료과(요청자) |
| 푸는 고통 | P1(하루 250건 요청·문의), P8(인계 누락, 퇴근 뒤 전화), P11(응급실 반복 문의), P12(부서별 전화, 부산물) |
| 기존 제품이 안 하는 이유 | 상태판은 "보면 안다"를 전제로 한다. 하지만 한국 현장의 요청은 그룹웨어 메시지·전화의 자유 서술이고(아산 원문), 상태판이 있어도 "왜 늦나, 누가 언제까지 하기로 했나"는 안 보인다. 이지케어텍의 인수인계 AI는 임상 요약 쪽이다. 세종병원의 자유 서술 분석은 배정 조건 추출용이다 |
| 진짜 에이전트다운 부분 | (1) 들어온 말을 의도로 가르기: 상태 문의 / 우선 요청("이 환자 먼저") / 약속("2시에 올려 주세요", "11시까지 비울게요") / 이의. (2) 상태 문의는 조회 의도로 바꿔 도구가 원장에서 답하고 근거 레코드 ID를 붙인다. 근거가 없으면 "기록 없음"이라고 말한다(이미 `agent/qa.py` AGT-6 원칙). (3) 우선 요청은 정책상 근거(응급, 수술 일정)가 있는지 판단해 처리 순서 규칙 입력으로만 넘긴다(배정 자체는 도구). (4) 약속은 기한·주인·상대를 뽑아 이벤트로 남기고, 기한이 다가오는데 근거 이벤트가 없으면 주인에게 한 번 묻는다. 교대 때 주인을 바꾼다(SAG-8의 `TASK_HANDED_OVER`) |
| 게이트웨이가 하는 일 | 약속 기록·변경은 자동 등급, 우선 요청으로 순서를 바꾸는 것은 정책 파일의 우선순위 규칙 안에서만, 후보 필터·SHACL은 건드리지 않음(응급실 범위 검토의 안전선과 같음) |
| 합성 데이터 시연 | 합성 문의·요청 문장 세트(병동 전달사항처럼)를 만들고, 재생 중 시각마다 질문을 던져 "근거 붙은 정답 / 기록 없음 정답 / 지어냄"을 센다. 교대를 넘기는 약속 N개를 심어 "사라진 약속 0건"을 본다 |
| 위험 | 실제 병원에선 메신저·전화 연동이 없으면 원장에 말이 안 들어온다(입력 경로 문제). 데모에서는 합성 입력이라 이 위험을 숨기지 말고 문서에 적는다. 새 입력 칸이 늘면 우회가 생긴다(`유튜브_요약_B.md` 13.6-24, PS-4). 개인정보: 자유 서술은 추출 필드만 쓴다(SEC-3) |
| 크기 | **M**. 기존: `agent/qa.py`, `agent/extract.py`, `FREE_TEXT_NOTE`·`FIELDS_EXTRACTED`, `saga/worklist.py` 인계·상향. 새로: 의도 분류 4종, 약속 이벤트(예: `COMMITMENT_MADE/KEPT/BROKEN`), 문의 평가 세트 |
| 확인할 증거 | 현직자: "하루에 병상 관련 문의 전화·메시지가 몇 건 오나, 무엇을 묻나", "전화로 한 약속이 어디에 남나". 공개: 서울아산 소식지 원문의 250건 맥락 재확인(이미 원문). 반증 조건: 문의 대부분이 상태판으로 이미 해결된다는 답 |

### 개념 C. 한국형 퇴원 당일 지휘: 다음 환자를 막는 고리 하나 짚기

| 항목 | 내용 |
|---|---|
| 한 줄 | 퇴원 환자 한 명의 심사·수납·영수증·약·교육·보호자 사슬에서 **다음 환자의 입실 창을 막는 고리 하나**를 찾아 그 주인에게만 알린다. |
| 사용자 | 병동 간호사·책임간호사, 병동원무 매니저, 원무 심사, (간접) 보호자 |
| 푸는 고통 | P2, P3 |
| 기존 제품이 안 하는 이유 | 해외 퇴원 장벽 제품은 미국 장벽(PT, MRI, 사례관리)을 안다. 한국의 "처방 수정 → 심사 재시작", "영수증 제시 뒤 약 전달", "가퇴원", "보호자 1인 상주·통합병동 상주 불가", "중앙휴게실"은 모른다(`제품전략.md` 2.3). 국내 첫 배정 자동화 보도에는 단계 지연 추적이 없다 |
| 진짜 에이전트다운 부분 | (1) 여러 지연 신호 중 **어느 것이 결정적인지** 판단: 약은 늦지만 보호자가 더 늦으면 약을 재촉해도 소용없다. 남은 시간 계산은 도구가, 고리 선택과 이유 설명은 에이전트가. (2) 보호자 메모 해석: 당일 지연 / 일자 변경 / 귀가 수단 없음. 일자 변경이면 퇴원 보류 경로와 다음 날 배정 재계산을 제안. (3) 행동 하나만 제안: 휴게실 대기 안내 문구, 심사 우선 요청, "처방이 바뀌어 심사가 다시 돌아 수납 가능 시각이 약 X분 밀림"을 원무·병동에 공유 |
| 게이트웨이가 하는 일 | 지연 공유는 자동, 휴게실 대기 전환은 정책 스위치가 켜진 병원에서만(종합 (b) 6번), 퇴원일 변경은 사람 확인(공식 확정은 사람의 책임 순간) |
| 합성 데이터 시연 | 기존 퇴실 전 단계와 지연 사유가 있다. 단계 순서를 병원 설정으로 바꾸고(종합_결정안 3.1 D), 보호자 지연을 두 갈래로(3.1 E) 나누면 "기존 방식(모든 지연을 따로 알림)" 대 "고리 하나 짚기"의 알림 수와 입실 창 놓친 건수를 비교할 수 있다 |
| 위험 | 이미 설계의 중심(SAG-5·6)이라 "새롭다"는 느낌은 A·B보다 약하다. 차별점은 "한국 절차를 안다"와 "다음 환자와 묶는다"에서만 나온다. 퇴실 시각 기록이 실제보다 늦을 수 있다(`유튜브_요약_A.md` 14.5-23) |
| 크기 | **M**. 기존: 퇴원 단계 이벤트(`DISCHARGE_RX_REVISED`, `BILLING_DONE`, `MEDICATION_READY`, `GUARDIAN_ETA_UPDATED`), 지연 사유 코드. 새로: 단계 순서 설정, "약 전달" 단계, 보호자 메모 4분류 추출, 고리 선택 도구 |
| 확인할 증거 | 현직자: 종합 (d) 질문 4·5(수납 뒤 남는 일, 휴게실 대기 사용). "보호자 사정으로 퇴원일이 바뀌는 일이 얼마나 흔한가"(`유튜브_요약_A.md` 14.6). 공개: 병동원무 매니저가 있는 병원의 퇴원 안내 |

### 개념 D. 늦게 도착하는 안전 정보 뒤처리 (격리 "아직 모름"과 연쇄 보상)

| 항목 | 내용 |
|---|---|
| 한 줄 | 격리 정보가 늦게 들어와도 **이미 한 배정·연락·청소 요청을 빠짐없이 찾아 되돌린다.** |
| 사용자 | 원무, 감염관리실, 책임간호사 |
| 푸는 고통 | P7, P9(야간 응급 격리 입원) |
| 기존 제품이 안 하는 이유 | 기존 해법은 "정보를 빨리 넣게 하기"(HIS 자동 등록, 울산대 사례)와 "정보가 있으면 청소 유형을 정하기"(Epic)다. 정보가 **늦게 왔을 때** 이미 일어난 일들의 연쇄를 찾고 보상하는 것은 사가와 추가만 하는 원장이 있어야 쉽다. 이 프로젝트에 둘 다 있다 |
| 진짜 에이전트다운 부분 | (1) 자유 서술에서 단서 보기: "CRE 과거력", "요양병원에서 전원", "검사 결과 대기", 응급실 기록의 격리 칸 공란. 이것으로 격리를 **정하지 않고** "아직 모름"으로 올려 감염관리실에 확인을 요청한다(LP-19 유지). (2) 늦은 격리 오더가 오면 영향 범위 판단: 이 환자가 들어갈 병상, 이미 연락한 내용, 같은 병실의 다른 빈 병상, 이미 나간 청소 요청 유형. 무엇부터 되돌릴지 순서와 설명은 에이전트가, 각 보상의 실행과 재검사는 게이트웨이가 |
| 게이트웨이가 하는 일 | "아직 모름"이면 다인실 확정 금지 또는 담당 검토(응급실 범위 안전선과 같음). 늦은 오더가 오면 확정 직전 재확인(GW-1)과 SHACL 재검사, 청소 유형 상향, 종말소독 전 배정 금지(GW-6) |
| 합성 데이터 시연 | 매우 좋다. 잡음 주입이 이미 있다(`events/` 늦은 인지). "검사 결과 뒤 격리 오더가 몇 시간 늦게 들어옴" 잡음을 넣고(종합 (b) 12번), 재생에서 "늦은 정보로 생긴 위반 0건, 영향 사례 누락 0건"을 증명. 종말소독 누락 0건 지표와 바로 이어진다 |
| 위험 | 단서 기반 "모름" 표시가 너무 많으면 감염관리실 전화가 오히려 늘어난다(R-41). 정밀도를 재고 임계값을 정책 파일로. 탐지 수단이 없는 진짜 누락(단서도 없음)은 못 잡는다는 한계를 문서에 적는다 |
| 크기 | **S~M**. 기존: `ISOLATION_ORDER_ADDED`가 사가 고정 트리거(`_PIN_TRIGGERS`), 재확인 게이트웨이, 잡음 주입, S2 검사기. 새로: 격리 3값, 단서 추출, 영향 범위 도구, 시나리오 3~5개 |
| 확인할 증거 | 공개: QIH 2022 원문(이미 작업자 재확인). 현직자: "격리 오더가 입원 뒤 늦게 나서 병실을 다시 옮긴 일이 한 달에 몇 번인가", "응급 입원 때 격리 칸이 비어 있으면 어떻게 하나". 반증 조건: 자동 등록이 보편화돼 늦은 정보가 드물다는 답 |

### 개념 E. 병동의 목소리: 이의 제기를 구조화하고 부하를 공정하게

| 항목 | 내용 |
|---|---|
| 한 줄 | 병동이 전화로 하던 이의와 "풀로 채우기" 같은 버티기를, **사유가 있는 이의와 보이는 부하**로 바꾼다. |
| 사용자 | 수간호사·책임간호사, 원무 배정 담당, 간호부(보고) |
| 푸는 고통 | P5 |
| 기존 제품이 안 하는 이유 | 배정 추천은 원무 쪽 도구다. 병동의 이의는 보도된 어느 시스템에도 단계로 없다. 국내 현실은 판결이 보여 주듯 "통보 → 이의 전화 → 의견 청취"이고, 서울대처럼 병상 중앙화가 노사 쟁점이 된다 |
| 진짜 에이전트다운 부분 | (1) 배정 설명: 같은 근무조 신환 수, 교대 겹침(14~15시), 간호사 수, 진료과 일치를 근거로 "왜 이 병동인가"를 쓴다. (2) 이의 해석: 자유 서술 이의를 사유 코드(임상 수용 기준 밖, 감염, 인력 상한, 단순 부하)로 분류하고 정책상 유효한지 판단해 재배정 요청 / 기록 후 진행 / 담당 검토를 권한다. (3) 기간 보고: 병동별 근무조당 신환 수의 쏠림을 보고하고 "버티기" 신호(빈 병상 급감 뒤 다음 날 대량 퇴원 등)를 사람에게 보인다(판단은 사람) |
| 게이트웨이가 하는 일 | 병동 확인 방식 정책 스위치(관문 / 통보 뒤 이의 기간 / 없음, 종합_결정안 3.1 C). 이의 기간 안 재배정은 재확인 거쳐 실행 |
| 합성 데이터 시연 | 가능. 병동 2개, 근무조 간호사 수 표(DAT-8)가 있다. 합성 이의 문장 세트와 병동 부하 쏠림 시드를 만든다 |
| 위험 | 조직 정치에 닿는다. 공정성 보고가 감시로 읽힐 수 있다. 인력 상한은 근거가 약하다(설계 가정). 현직자 검증 없이 "버티기 탐지"를 내세우면 반발 |
| 크기 | **M**. 기존: `WARD_REJECTED`, `WARD_ACCEPTANCE_ASKED`, `_ward_load`(agent/tools.py). 새로: 이의 사유 분류, 이의 기간 정책, 부하 보고 |
| 확인할 증거 | 현직자: 종합 (d) 질문 2(회신·이의 방식), "이의가 받아들여지는 사유는 무엇인가". 공개: 서울대병원 노사 합의문 원문(병상 중앙화 조항) |

### 개념 F. 재원 환자 병실 변경 대기 투명화와 차액 보호 (표시만)

| 항목 | 내용 |
|---|---|
| 한 줄 | "자리 나면 옮겨 드릴게요"라는 약속을 **보이는 줄**로 만들고, 원치 않는 상급병실 차액을 동의 없이 확정하지 못하게 한다. |
| 사용자 | 병동 간호사(반복 요구 응대), 원무, (간접) 환자·보호자 |
| 푸는 고통 | P6 |
| 기존 제품이 안 하는 이유 | 분당서울대 모바일 희망병실 변경은 입원 전 대기용이다. 아산 AI는 변경 목록을 배정 입력으로 쓴다(내부 계산). 재원 환자에게 순번과 예상 대기를 보여 주고, 차액 동의를 실행 조건으로 거는 공개 사례는 찾지 못했다 |
| 진짜 에이전트다운 부분 | (1) 변경 요청 자유 서술 해석("다인실이면 아무 데나", "창가 원함"은 받을 수 없는 조건이라 안내 필요, 서울성모 "자리지정 불가"). (2) 빈 병상이 생길 때 대기열 맨 앞 조건에 맞는지 판단해 "이동 대기 우선 가능"을 표시하고, 그 때문에 신규 입원에 줄 수 있는 병상이 줄어든다는 것을 A·추정에 반영. 순번 계산·조건 일치는 도구 |
| 게이트웨이가 하는 일 | "희망 등급과 다른 배정"(종합_결정안 3.1 F)은 차액 동의 기록이 없으면 연락 확정 금지. 이동 자체는 실행하지 않음 |
| 합성 데이터 시연 | 생성기에 "재원 환자 등급 변경 대기"를 넣어야 한다(종합 (e) 12번의 선택 사항). 표시와 추정 과대평가 감소를 비교 |
| 위험 | **GW-15(원내 전동) "설계" 경계.** 표시가 "그럼 이동도 짜 달라"는 요구를 부른다(`제품전략.md` 3.2 #12). DECISIONS에 "표시만, 제안·실행 없음"을 먼저 적어야 한다. 차액 동의는 원무 절차(상급병실 사용신청서) 확인 필요 |
| 크기 | **M** (DECISIONS 기록 선행) |
| 확인할 증거 | 현직자: 종합 (d) 질문 3(이동과 신규 중 누가 먼저, 청소 두 번). "변경 신청은 어디에 적나(종이, EMR)". 공개: 요양급여 기준 규칙의 상급병실 차액 조항 원문(`원무_병상배정_실무.md` 원문 대기 목록) |

### 개념 G. 근무 공백 브리핑: 밤에 기다려도 되는 일과 안 되는 일

| 항목 | 내용 |
|---|---|
| 한 줄 | 밤·주말에 쌓인 일을 **"지금 당직을 깨울 일"과 "아침에 먼저 할 일"**로 갈라, 다음 근무 시작에 한 장으로 건넨다. |
| 사용자 | 원무 응급지원 단위·아침 입원 파트, 나이트·데이 책임간호사 |

| 게이트웨이가 하는 일 | 안전 항목의 야간 상향은 정책 파일 대행 역할(종합 (c) AS-A7 선택지). 브리핑은 읽기 전용 |

| 위험 | 청소 시간대 근거가 약하다(보도 1건). 야간 감염관리 대행 주체가 국내 근거 0건이라 상향 대상이 설계 가정 |
| 크기 | **S~M** |
| 확인할 증거 | 현직자: 종합 (d) 질문 7(밤·주말 청소), 설문 문항 1(야간 배정 주체), 질문 12(부재 시 상위 담당) |

## 5. 현직자에게 물을 것 (이 검토에서 새로 나온 것만)

종합 (d) 12문항과 겹치지 않는 것만. 설문은 이미 발송돼 바꾸지 않으므로 후속 메시지로.

## 6. 이 검토의 한계

- 새 원문을 열지 않았다. 인용은 현장조사 파일이 원문이라고 적은 것을 옮겼다. 개념을 설계에 넣기 전에 CLAUDE.md 7번대로 핵심 출처를 작업자가 직접 연다(특히 A의 근거가 되는 병원 안내 문구, D의 QIH 2022, E의 판결).
- 빈도 근거가 약하다. 아산 250건, 격리 등록 53%, 퇴원 처방 뒤 수납 252.5분 정도만 숫자가 있고 모두 한 병원 값이다. 나머지는 블로그·영상의 존재 증거다. 그래서 각 개념에 "확인할 증거"와 반증 조건을 붙였다.
- 기존 제품의 "안 한다"는 공개 자료에서 못 찾았다는 뜻이다. 내부 기능은 있을 수 있다(특히 이지케어텍 Medical OS, 분당서울대 스누워드가이드의 향후 AI). 제품전략 R8(경쟁 기능 세부) 조사가 남아 있다.
- 실제 병원 연동(메신저, 전화, HIS)이 없는 데모에서는 B의 "입력이 원장에 들어오는가"를 증명할 수 없다. 데모 결과를 "합성 입력 기준"으로 적는다.
