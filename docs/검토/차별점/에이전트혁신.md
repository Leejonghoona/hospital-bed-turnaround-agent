## 결론 먼저

1. **사용자의 느낌이 맞다. 지금 기능 목록만 보면 대부분 이미 있다.** 첫 배정 자동화(서울아산, 길병원, 세종병원, 분당서울대), 상태판(Epic, TeleTracking, GE, 분당서울대), 자유 서술을 배정 조건으로 바꾸기(세종병원), 퇴원 예측(Epic, Qventus), 그리고 2026년에는 "병원이 직접 에이전트를 만드는 도구"(Epic Agent Factory)까지 나왔다. 기능 하나하나로는 차별점이 없다.
2. **2026년 판이 바뀐 지점은 "누가 에이전트를 검증하고, 감시하고, 끄는가"다.** Epic은 병원이 에이전트를 직접 조립하게 했고, 업계지는 "논리 검증, 표류 감시, 끌 권한"이 풀리지 않은 질문이라고 썼다(원문). 세종병원 자동 배정은 결과를 병원 전산에 자동 반영한다(원문). 국내 AI 기본법 제34조는 보건의료 영역 고영향 AI에 위험관리, 설명, 사람의 관리·감독, 문서 보관을 요구한다(원문). 서울아산은 AI 도입 승인과 도입 후 모니터링을 맡는 전담 조직을 만들었다(원문). **에이전트를 만드는 곳은 많아졌는데, 에이전트가 병상을 움직여도 되는지 증명하는 곳은 없다.**
3. **이 프로젝트가 이미 가진 것(실행 게이트웨이, 재생 평가와 홀드아웃, 뮤턴트 민감도, 실행 상태 안전 측정, 합성 병원 생성기, 원내 모델 점검)은 바로 그 빈자리에 맞는다.** 그래서 1순위 제안은 새 기능이 아니라 **포지셔닝 전환**이다: "우리 배정 AI"가 아니라 **"누구의 배정 AI든 그 앞에 서는 독립 실행 관문과, 그 관문이 안전하다는 증빙을 자동으로 만드는 체계"**.
4. **LLM이 정말로 규칙 엔진·상태판을 이기는 곳은 가운데(판단)가 아니라 가장자리(입력과 출력)다.** 입력 쪽은 전화 메모, 인계장, 음성 인계 전사처럼 전산에 안 들어오는 신호를 이벤트 후보로 바꾸는 일, 출력 쪽은 "왜 늦나, 그때 알 수 있었나"를 근거 레코드와 함께 사람 말로 풀어 주는 일이다. U8(병상 선택은 규칙, LLM은 설명)은 약점이 아니라 이 구도의 핵심이다. 가운데를 결정적으로 묶어 두었기 때문에 가장자리를 넓혀도 안전 증명이 깨지지 않는다.
5. **국내 조건이 이 구도를 돕는다.** 국내에서 병상 "청소 완료, 준비 완료"를 누가 전산에 넣는지 근거가 4번 조사에서 0건이고(저장소 기록), 병동은 전화로 통보받고 인계장에 적는다(저장소 기록, 영상 자막). 해외 상태판은 구조화된 입력(Rover 앱, EVS 앱)을 전제한다. 국내는 **신호가 말과 메모에 있다.** 동시에 국내 병원은 원내 GPU가 부족하다(서울대병원 GPU 100여 장, 직원 1만 명, 원문). 이 프로젝트의 원내 모델 점검은 "작은 원내 모델(Qwen2.5 3B, EXAONE 3.5 2.4B)이 인젝션 관문에서 떨어져도 회귀 시나리오 30/30이 지켜진다"를 이미 보였다(합성 데이터 기준 추정). **안전이 모델이 아니라 구조에서 나온다**는 것은 GPU가 부족한 국내 병원에 바로 통하는 메시지다.
6. 개념 8개를 평가했다. 순위: ① 독립 실행 관문(남의 배정 AI 앞에도) ② 자율화 증빙 묶음 자동 생성 ③ 말과 메모에서 신호 듣기(격리 불일치 경보 포함) ④ "왜 늦나, 그때 알 수 있었나" 설명 ⑤ 적대적 시나리오 공장(블라인드 홀드아웃) ⑥ 직접 수정 기록에서 숨은 규칙 찾기(2단계 온보딩의 씨앗) ⑦ 운영 결정 반사실 시험 ⑧ 채널 협상 코디네이터(**채택하지 않음 권고**).
7. **1단계 계획 변화는 작다.** ①은 기존 "주입판" 실행기와 게이트웨이를 외부 제안 입력으로 여는 일(M), ②는 이미 있는 점수판·민감도·실행 안전 결과를 묶는 보고서(S~M), ④는 이벤트 저장소의 `as_of`와 질의 응답 틀을 쓰는 일(S~M)이다. ③은 SEC-3(자유 서술은 추출 필드만)을 지키는 방식이 필요해 DECISIONS가 먼저다(M). ⑥과 ⑦은 2단계 온보딩의 앞당긴 조각이다.
8. **하지 말 것도 분명하다.** LLM이 병상을 고르게 하는 것(U8 유지), 간호사에게 묻는 메시지를 늘리는 코디네이터(현장은 "AI가 늘었지만 더 바빠졌다"고 한다, 검색 요약), 자체 현황판, 퇴원 예측 ML. 경쟁사가 가장 잘하는 곳에서 싸우지 않는다.

## 4. 개념 8개

각 개념은 같은 순서로 쓴다: 한 줄 제안 / 왜 다른가 / LLM이 하는 일과 결정적 코드가 하는 일 / 안전 이야기 / 합성 데이터 데모 / 크기(S·M·L) / 위험 / 1·2단계 계획 변화.

### 개념 1. 독립 실행 관문: 누구의 배정 AI든 그 앞에 선다

**한 줄 제안**: 이 프로젝트의 계획 에이전트만이 아니라, 병원이 이미 쓰는 자동 배정(세종병원형), HIS 공급사 에이전트, Epic Agent Factory 같은 도구로 병원이 만든 에이전트가 내는 병상 결정을 **실행 직전에 받아 재확인·재검사·확인 등급을 매기고, 감사 로그를 남기는 중립 관문**으로 판다.

**왜 다른가**
- 첫 배정 자동화는 이미 상품이고(서울아산, 길병원, 세종병원, 분당서울대), 세종병원은 결과를 HIS에 자동 반영한다(원문). 이 프로젝트가 배정 정확도로 이들을 이길 길은 없다(SPEC POS-5).
- Epic은 에이전트 제작을 병원에 넘겼고, 업계지는 검증·감시·끌 권한이 비어 있다고 썼다(원문). 공급사 스스로 만든 에이전트를 공급사가 감사하는 구조는 이해 충돌이 있다.
- 격리 등록이 53%만 돼 있던 병원(QIH 2022, 저장소 기록)에서는 어떤 배정 AI든 오더 값을 믿으면 틀린다. 확정 직전 재확인(GW-1·9)은 배정 엔진이 누구든 필요하다.
- 공개 자료에서 "배정 AI 앞의 독립 관문"을 파는 제품은 찾지 못했다(찾지 못함이 없음은 아니다).

**LLM과 결정적 코드의 몫**
- 결정적: 외부 제안 받기(어댑터), 재확인 2회, SHACL, 확인 등급, 동시 확정 차단, 멱등, 감사, 안전 예외 3단계. **전부 이미 있다.**
- LLM: 거부·교정 사유를 받는 사람(원무, 병동, 외부 엔진 담당자)에게 맞는 말로 풀어 쓰기, 외부 엔진이 낸 자유 서술 사유를 허용 필드로 추출하기. 둘 다 실행 권한이 없다.

**안전 이야기**: 관문은 LLM이 없어도 돈다(규칙 모드, NFR-4). 외부 엔진이 무엇을 내든 관문의 결정은 결정적 코드와 정책 파일이 한다. U8을 넘어 "관문 자체에는 LLM 판단이 0"이라는 문장을 쓸 수 있다.

**합성 데이터 데모**
- 외부 배정 엔진 흉내 3개를 만든다: (a) 이 프로젝트 규칙 모드와 같은 엔진, (b) 격리 오더 값만 믿는 "순진한" 엔진, (c) 일정 확률로 성별·코호트를 틀리는 "잡음" 엔진. 셋 다 같은 합성 하루를 재생하며 관문 앞에 제안을 낸다.
- 보이는 숫자: 관문이 막은 건수와 사유 분포, 통과한 배정의 실행 상태 안전 S1·S2(0건 목표, 분모와 95% 상한), 막아서 생긴 사람 확인 추가 건수(대가).
- 두 가지 배치 모드: **사전 관문**(HIS에 쓰기 전, 공급사 협조 필요)과 **사후 감시**(HIS에 이미 쓰인 배정을 이벤트로 받아 검사하고 경보만). 사후 감시는 GW-11 "고정된 배치도 계속 감시"를 넓힌 것이다.

**크기**: M. 주입판 실행기를 "외부 제안" 입력으로 일반화하고, 외부 엔진 흉내 3개와 비교표를 만든다.

**위험**
- 실제로 외부 엔진 앞에 서려면 HIS·공급사 연동이 필요하다(설계 "제외"인 실제 HIS 쓰기 연동). 데모는 합성 재생으로만 한다.
- 사후 감시는 SPEC GW-13 "시스템 밖 결정 수용"(설계)과 겹친다. GW-13은 "HIS가 이김"이고, 사후 감시는 "HIS가 이기되 안전 문제면 경보"라서 범위가 다르지만 DECISIONS에 경계를 먼저 적어야 한다.
- HIS 공급사가 같은 관문을 기능으로 넣을 수 있다(이지케어텍 방향). 그래서 개념 2(증빙)와 묶어야 남는다.

**계획 변화**: 1단계 안. 7단계(계획 에이전트) 뒤 "외부 제안 어댑터 + 비교 재생"을 작은 단계로 넣는다. 제품 서술을 "병상 턴어라운드 관제 에이전트"에서 "**병상을 움직이는 AI를 위한 실행 관문과 증빙**"으로 바꾸는 안을 03 PR/FAQ, 04 PRD에 제안한다(종합 결정안 4절 3번 "HIS에 붙는 실행 통제·평가 계층"의 한 걸음 더).

### 개념 2. 자율화 증빙 묶음: "이 단계로 올려도 된다"를 자동으로 증명한다

**한 줄 제안**: 정책 파일을 바꾸거나 진료과의 자율화 단계를 올리거나 모델을 바꿀 때마다, 재생 평가가 **한 장짜리 증빙 묶음**(무엇이 바뀌었나, 회귀·홀드아웃 결과, 뮤턴트 민감도, 실행 상태 안전과 95% 상한, 사람 부담 변화, 형식적 승인 탐지, 원내 모델 관문 결과, 남은 위험)을 만든다. 승인자는 이 묶음을 보고 서명한다.

**왜 다른가**
- 서울아산 AI혁신지원실은 "승인 근거 기록 … 도입 후 모니터링과 정기평가"를 한다(원문). 그 조직이 읽을 근거를 공급사가 만들어 주는 사례는 공개 자료에 없다.
- AI 기본법 제34조 1~5호(위험관리, 설명, 사람의 관리·감독, 문서 보관)와 항목이 맞는다(원문 조문. 이 제품이 고영향에 드는지는 확인 필요).
- Epic Almanac 수치에는 비교군이 없다(원문 기사 지적). 이 프로젝트는 기준선(규칙 모드, 기존 방식), 홀드아웃, 민감도, 신뢰 상한을 이미 낸다.
- 원내 모델을 바꿀 때 "작은 모델로 바꿔도 안전 지표가 그대로"를 같은 표로 보인다. GPU가 부족한 국내 병원(서울대 원문)에 모델 크기를 정할 근거가 된다.

**LLM과 결정적 코드의 몫**
- 결정적: 모든 숫자(점수판, 민감도, 신뢰 상한, McNemar), 무엇이 바뀌었는지(정책 파일 차이), 합격선 판정.
- LLM: 숫자를 바꾸지 않는 요약 문장(어느 시나리오가 왜 바뀌었나), 승인자 역할별 설명. 모든 문장에 근거 결과 파일 ID를 단다. LLM 장애면 표만 낸다.

**안전 이야기**: 묶음은 실행 권한이 없다. 합격선을 못 넘으면 묶음에 "승격 불가"가 찍히고 정책 로더가 그 단계를 거부한다(결정적). LLM 요약이 숫자와 어긋나면 검사기가 잡는다(요약 안의 숫자를 결과 파일과 대조).

**합성 데이터 데모**
- 시나리오: "내과 병동 자율화 2단계 승격 요청". 묶음 생성 → 합격. 이어서 "결핵 60분 하한을 끈 정책" 변경 요청 → 홀드아웃·민감도에서 실패 → 묶음이 "승격 불가"와 실패 시나리오 ID를 보인다. 세 번째로 "계획 모델을 gpt-4o-mini에서 원내 Qwen2.5 3B로" → 추출 정확도는 내려가고 인젝션 관문은 떨어지지만 회귀 30/30·실행 안전 0건은 유지 → "추출 역할은 불가, 설명 역할은 조건부" 같은 역할별 판정.
- RESULTS에 이미 있는 숫자를 다시 쓰므로 새 측정은 적다.

**크기**: S~M. 결과 파일은 이미 있고, 묶음 생성기와 합격선 표가 새로 필요하다.

**위험**
- **자율화 승격 뒤 표본 감사와 자동 강등은 SPEC EVL-6 "설계"다.** 승격 전 증빙(이 개념)은 지금 있는 것을 묶는 일이라 설계 항목이 아니지만, 운영 중 자동 강등까지 가려면 DECISIONS와 사용자 결정이 먼저다.
- 합성 데이터 증빙은 실제 병원 증빙이 아니다. 묶음 첫 줄에 "합성 데이터 기준 추정"을 박는다(CLAUDE.md 6번).
- 홀드아웃을 작업자가 써서 블라인드가 아니라는 약점(PRD 결론 먼저)을 묶음이 그대로 드러낸다. 개념 5가 이를 메운다.

**계획 변화**: 1단계 안. 평가 하네스(5단계) 결과를 쓰는 보고서로 먼저 만들고, 자율화 단계 변경을 이 묶음과 묶는 것은 DECISIONS 뒤.

### 개념 3. 말과 메모에서 신호 듣기: 묻지 않고 듣는 귀

**한 줄 제안**: 국내 병원에서 퇴원부터 입실까지의 신호(보호자 도착, 수납 완료, 청소 끝, "올려주세요", 격리 언급)는 전산보다 **전화 메모, 인계장, 원무 전달사항, 음성 인계 전사**에 먼저 있다. LLM이 이 글을 읽어 **이벤트 후보**로 바꾸고, 결정적 규칙이 후보를 비대칭으로 받아들인다: 제약을 조이는 신호(격리 의심, 보호자 지연)는 바로 경보로, 제약을 푸는 신호(청소 완료, 퇴실)는 다른 신호로 맞춰 보거나 사람이 확인한 뒤에만 사실로.

**왜 다른가**
- 해외 상태판은 구조화된 입력을 전제한다(Epic Rover, EVS 앱, 저장소 기록). 국내는 "청소 완료" 입력자 근거가 4번 조사에서 0건, 병동은 전화로 통보받고 인계장에 "몇 호실 퇴원"을 적는다(저장소 기록, 영상 자막).
- 세종병원은 자유 서술을 **배정 조건**으로 바꾼다(원문). 이 개념은 자유 서술을 **진행 신호와 안전 불일치**로 바꾼다. 쓰는 곳이 다르다.
- 음성 간호 기록(서울성모 Voice ENR, 강북삼성 인수인계 요약, 길병원 AI 인수인계, Dragon Copilot 간호)이 퍼지고 있다. 이 프로젝트는 음성 인식을 만들지 않고 **그 결과 텍스트를 운영 이벤트로 읽는 소비자**가 된다.
- 가장 값진 부분은 **격리 불일치 경보**다: 메모·인계에 "VRE 결과 양성이래요", "기침 심함, 결핵 검사 나감"이 있는데 격리 오더가 없으면 감염관리실에 "오더 확인 요청"을 보낸다. QIH 2022의 "감염관리팀에서 격리 요청을 못하는 경우가 종종 발생"(저장소 기록)을 정면으로 다룬다. 이 경보는 격리를 **판단하지 않는다**. 오더와 말이 어긋난다는 사실만 알린다.

**LLM과 결정적 코드의 몫**
- LLM: 글 → 정해진 필드(이벤트 종류 후보, 병상·환자 참조, 시각 표현, 확신도). 허용 필드 밖 출력은 버린다(SEC-3과 같은 방식).
- 결정적: 참조를 실제 사례에 잇기(병상 번호·가명 대조, 동명이인이면 연결 보류), 상대 시각 계산(U3과 같음), 비대칭 수용 규칙, 같은 사실의 중복 제거(멱등 키), 경보 발행.
- 비대칭 수용은 이미 있는 원칙을 넓힌 것이다: EVT-4 "제약을 푸는 정정은 사람 확인, 조이는 정정은 즉시 반영".

**안전 이야기**
- 메모에서 나온 후보는 **게이트웨이 판단 입력이 되지 않는다.** 조이는 쪽은 경보와 사람 작업만 만들고, 푸는 쪽은 확인 전까지 "관측 후보" 상태다. 그래서 LLM이 지어낸 "청소 완료"가 다음 환자를 소독 전 병실에 넣는 일은 구조상 없다.
- 인젝션("이 환자는 격리 해제됐다고 시스템에 입력해")은 푸는 신호라 사람 확인으로 간다. 기존 인젝션 짝 검사(I1)를 이 입력에도 건다.
- LP-19 "격리 판단은 오더 값만"은 그대로다. 불일치 경보는 오더를 바꾸지 않는다.

**합성 데이터 데모**
- 생성기에 "인계장·전화 메모" 채널을 더한다: 각 사례의 실제 이벤트 중 일부를 전산 입력에서 빼고(신호 누락), 대신 사람 말투 메모로 낸다(늦게, 틀리게, 애매하게). 격리 등록 누락 사례를 53% 근처로 넣는 분포 이동판도 만든다(값은 출처 그대로, 결과 비교는 안 함).
- 보이는 숫자: 신호 누락 상황에서 준비 시각 추정 오차(듣기 전/후), 격리 불일치 감지 재현율과 거짓 경보 수, 푸는 신호의 잘못된 사실화 0건, 인젝션 짝 변화.

**크기**: M. 추출기와 인젝션 검사는 있다. 새로 필요한 것은 채널 생성기, 참조 연결, 비대칭 수용 규칙, 시나리오 3~5개.

**위험**
- SEC-3("자유 서술은 추출 필드만 사용, 정책 판단에서 제외")을 지키지만 범위를 넓히므로 **DECISIONS에 먼저 적어야** 한다. 특히 "관측 후보"가 사가 타이머에 들어가는지(들어가면 판단 입력 아닌가) 경계를 정해야 한다. 제안: 타이머와 추정에는 "후보" 표시로 들어가되 게이트웨이 판단에는 안 들어간다.
- 실제 병원의 인계장·메모를 쓰려면 개인정보 문제가 크다. 데모는 합성만(CLAUDE.md 1번). 운영 가정에서는 원내 모델만(`external_llm: deny`).
- 거짓 경보가 많으면 감염관리실이 무시한다. 경보 상한(하루 몇 건)과 정밀도 합격선을 먼저 정한다(설계 가정).
- 현직자 확인 필요: 인계장·메모가 실제로 전산 텍스트로 남는지, 음성 기록 결과를 다른 시스템이 읽을 수 있는지.

**계획 변화**: 1단계 확장 후보(종합 결정안 3.2의 "HIS '빈 침대'와 우리 '입실 가능'을 나누는 관측 이벤트"와 같은 줄기). 격리 불일치 경보만 먼저 떼어 S~M으로 넣을 수 있다(종합 결정안 3.1 G "격리 아직 모름"과 짝).

### 개념 4. "왜 늦나, 그때 알 수 있었나": 근거 붙은 지연 설명

**한 줄 제안**: 원무가 "3병동 12번은 왜 아직 안 됐어?", 수간호사가 "오늘 입실 밀린 거 이유가 뭐야?"라고 물으면, 결정적 코드가 사례의 이벤트로 **지연이 어느 단계에서, 분포 대비 얼마나** 생겼는지 계산하고, LLM이 근거 레코드 번호를 단 짧은 설명으로 답한다. 한 걸음 더: **"10시 연기 연락 마감 때 이걸 알 수 있었나"**를 `as_of`로 다시 계산해 보인다.

**왜 다른가**
- 상태판은 "지금 상태"를 보인다(분당서울대, Epic, TeleTracking). 예측 제품은 "다음에 일어날 일"을 보인다(Decision IQ, CareIntellect). **"이미 일어난 지연의 원인 사슬"과 "그 시점에 알 수 있었는가"**를 근거 레코드와 함께 내는 기능은 공개 자료에서 못 찾았다.
- 이 기능은 발생 시각과 인지 시각을 나눠 기록한 이벤트 저장소가 있어야 가능하다. 상태 스냅숏을 받는 제품은 구조상 못 한다(FHIR 결정 기록의 논리와 같다).
- 한국형 단계(심사 → 수납 → 영수증 제시 → 퇴원약, 가퇴원, 13:30 침상 정리 일괄 시각)를 단계 이름으로 아는 설명은 해외 제품에 없다.
- 쓰임새: 아침 병상 허들, 교대 인계 요약, 주간 개선 회의(QI)의 "늦은 사례 10건" 자료.

**LLM과 결정적 코드의 몫**
- 결정적: 단계별 소요시간과 분포 대비 백분위, 임계 경로(가장 늦게 끝난 선행 단계), 지연 사유 코드(SAG-5), `as_of` 재계산, 반사실 한 줄("수납 대기가 중앙값이었다면 13:10 준비", 몬테카를로 또는 대입).
- LLM: 질문 해석(조회 의도로, AGT-6 방식), 계산 결과를 역할에 맞는 한국어 2~4문장으로. 사실은 전부 도구 결과에서 오고, 근거 ID가 없으면 "레코드 없음".

**안전 이야기**: 읽기 전용이다. 실행 권한 없음. 역할별 조회 권한(GW-7)과 사망 정보 비노출(SAG-9)을 그대로 따른다. 설명 문장 안의 숫자와 시각을 도구 결과와 대조하는 검사기를 둔다(지어내기 0건 지표).

**합성 데이터 데모**
- 합성 하루 재생 뒤 "가장 늦은 5건" 자동 브리핑. 각 건마다 "어느 단계, 몇 분, 분포 대비 P몇, 10시에 알 수 있었나(예/아니오와 근거 이벤트)".
- 평가: 정답 원인 단계는 생성기가 넣은 지연(보호자 지연, 청소 지연 등 정확 건수)으로 안다. **원인 단계 적중률**, 근거 인용 정확도(P3), 숫자 지어내기 0건, "알 수 있었나" 판정 정확도를 잰다. 생성기가 정답을 알기 때문에 라벨 비용이 거의 없다.

**크기**: S~M. 질의 응답 틀, `as_of`, 지연 사유 코드가 있다. 임계 경로 계산과 설명 검사기가 새로 필요하다.

**위험**
- 원인 사슬이 하나가 아닐 때(보호자도 늦고 청소도 늦음) 단순화가 오해를 부른다. 겹친 원인은 둘 다 보인다.
- "누구 탓" 문화로 쓰일 위험. 단계와 사유만 말하고 개인을 지목하지 않는다(청소원별 성과는 이미 범위 밖).
- 생성기가 정답을 아는 평가는 낙관적이다(가용 병상 추정과 같은 문제). 분포 이동 홀드아웃을 함께 잰다.

**계획 변화**: 1단계 안. 7단계 질의 응답(AGT-6)의 확장으로 넣는다. PRD 지표에 "원인 단계 적중률"을 더하는 안. 엔드픽처의 "사람은 책임질 순간에만"과 맞물린다: 사람이 전화로 원인을 묻는 횟수를 줄인다.

### 개념 5. 적대적 시나리오 공장: 블라인드 홀드아웃을 계속 만든다

**한 줄 제안**: 현장조사 문서의 문장(예: "보호자가 내일 못 와 토요일 퇴원", "MRSA 다인실 제자리 격리", "사망 후 빨리 비워 달라")을 LLM이 **시나리오 초안**(이벤트 순서 YAML)으로 바꾸고, 여러 사례를 섞어 낯선 조합을 만든다. 정답은 LLM이 정하지 않는다. 안전 불변식(S1·S2, 미래 정보 누수, 이중 배정)은 정답 없이도 검사되고, 기대 행동 라벨은 사람이 승인한다.

**왜 다른가**
- 지금 약점: 홀드아웃 13개는 모두 작업자가 써서 블라인드가 아니다(PRD 결론 먼저). 개념 1·2의 설득력은 홀드아웃의 독립성에 달렸다.
- 업계 에이전트 사례에는 시험 세트가 없다(Almanac 기사 지적). 시험 세트를 계속 늘리는 공장 자체가 증빙 체계의 일부다.
- 시나리오를 쓰는 LLM을 계획·설명 LLM과 **다른 계열**로 두면 같은 계열 편향을 줄인다(U6의 이중 주석 원칙과 같다).

**LLM과 결정적 코드의 몫**
- LLM: 현장 문장 → 이벤트 순서 초안, 섞기 제안, "이 시나리오가 노리는 장치" 서술.
- 결정적: 스키마 검사(`test_scenarios_schema.py`), 불변식 검사, 뮤턴트 민감도(이 시나리오가 끄면 실패하는 장치가 있나, 없으면 버림), 중복 검사, 홀드아웃 누출 검사(`test_no_scenario_leak.py`).
- 사람: 기대 행동 라벨 승인(지금 라벨 절차 그대로).

**안전 이야기**: 시험 도구라 운영 경로에 없다. 위험은 "나쁜 시나리오가 통과 기준을 낮추는 것"인데, 라벨은 사람이 승인하고 기존 승인 30개는 고정한다.

**합성 데이터 데모**: 현장조사 문장 20개 → 시나리오 초안 → 스키마·민감도 통과분만 남김 → 기존 시스템을 돌려 **새로 찾은 결함 수**를 센다(H11이 사후 처치 중 병상 차단 결함을 드러냈듯). 지표: 초안 채택률, 시나리오당 걸리는 장치 수, 새 결함 수.

**크기**: M.

**위험**: 라벨 승인 부담이 사용자에게 몰린다. 한 번에 10개 이하로 묶는다. LLM이 현장 문장을 과장해 현실에 없는 상황을 만들 수 있다. 초안마다 원 문장과 출처 등급을 단다(CLAUDE.md 7번).

**계획 변화**: 1단계 안(평가 하네스 보강). 개념 2의 증빙 묶음에 "블라인드 홀드아웃 비율"을 표시하게 된다.

### 개념 6. 직접 수정 기록에서 숨은 규칙 찾기: 2단계 온보딩의 씨앗

**한 줄 제안**: 사람이 규칙 모드의 제안을 고친 기록(직접 수정, 사유 코드, 고정, 안전 예외 "사유 입력 후 진행")과 과거 이벤트를 결정적으로 모아 **반복되는 무늬**를 찾고(예: "호흡기내과 환자는 사유 '진료과 요청'으로 7병동에 자주 옮겨진다", "토요일 13시 뒤 퇴실은 청소 시작이 다음 날 06시"), LLM이 그 무늬를 정책 파일 규칙 초안과 출처 등급 "현장 관행"으로 써서 사람에게 묻는다.

**왜 다른가**
- 2단계 온보딩 스펙은 구조·분포·규정 문서에서 설정을 만든다. **"문서에 없고 사람 손에 있는 규칙"**은 빠져 있다. 서울아산의 "50여 개 기준"처럼 배정 기준은 사람 머릿속과 공유 스프레드시트에 있다(ECU Health 전원센터도 "개인과 공유 스프레드시트에", 원문 기사).
- Epic·TeleTracking 도입은 컨설턴트가 몇 달 동안 규칙을 받아 적는 일이다(일반 관행, 근거는 검색 요약 수준). 직접 수정 로그에서 초안을 만드는 방식은 공개 자료에서 못 찾았다.
- 이 프로젝트는 직접 수정에 역할·사유 코드를 필수로 받고(GW-8·11), 출처 등급 체계(POL-1)가 있어 "현장 관행"을 따로 표시할 수 있다.

**LLM과 결정적 코드의 몫**
- 결정적: 무늬 찾기(조건별 빈도, 지지도, 기간, 예외 수), 후보 규칙을 과거 이벤트에 재생해 "이 규칙이 있었다면 직접 수정이 몇 건 줄었나, 안전 지표는 그대로인가".
- LLM: 무늬를 사람 말과 정책 YAML 초안으로, 확인 질문으로("7병동 우선은 진료과 요청 관행인가요, 일시적 사정인가요?").
- 사람: 승인. 승인 전 값은 `design_assumption`.

**안전 이야기**: 배운 규칙은 **점수(목표 함수 5항 선호)나 처리 순서에만** 들어갈 수 있고, 안전 규칙(1항)을 풀 수 없다. 지침 금지 조항은 병원 규칙이 못 바꾼다(POL-2). 그래서 "남녀 혼실이 자주 직접 수정된다" 같은 무늬는 규칙 초안이 아니라 **안전 보고**로 간다. 나쁜 관행을 학습해 굳히는 위험을 구조로 막는다.

**합성 데이터 데모**: 생성기에 "숨은 규칙" 3개를 심는다(사람 흉내가 규칙 모드 제안을 일정 규칙으로 고침). 4주 재생 뒤 무늬 찾기 → 심은 규칙 되찾기 재현율, 없는 규칙 지어내기 수, 승인 후 직접 수정 감소량, 안전 지표 변화 0. 2단계 스펙의 "설정 복원 시험"과 같은 틀이다.

**크기**: 1단계 조각(직접 수정 무늬 보고서, 결정적만) S. 규칙 초안과 재생 검증까지 L(2단계).

**위험**: 직접 수정 표본이 적으면 무늬가 우연이다. 최소 지지도와 기간을 정한다(설계 가정). 직접 수정 사유가 "기타"로만 차면 쓸모없다. 사유 코드 설계는 현직자 설문 뒤(U2와 같은 줄).

**계획 변화**: 2단계 온보딩 스펙 3절에 "8. 운영 기록에서 숨은 규칙 초안" 단계를 더하는 안(2단계 시작 때 ONB-로). 1단계에는 직접 수정 무늬 보고서만.

### 개념 7. 운영 결정 반사실 시험: "13:30 침상 정리를 11:30으로 당기면?"

**한 줄 제안**: 간호부·원무·환경관리 책임자가 운영 규칙 변경을 자연어로 물으면("주말 청소 2명이 1명이면?", "퇴원 라운지를 쓰면?", "가퇴원 시각을 17:30에서 18:30으로 늦추면?"), LLM이 이를 **운영 설정 차이(diff)**로 바꾸고, 결정적 재생과 몬테카를로가 입실 창 준비율과 연기 건수의 변화 구간을 계산하고, 안전 지표가 그대로인지 함께 보인다.

**왜 다른가**
- GE는 디지털 트윈을 표방한다(저장소 기록). 반사실 자체는 새롭지 않다.
- 다른 점은 ① 한국형 단계·운영 달력·근무조를 아는 설정 위에서 ② 같은 재생으로 **안전 지표도 함께** 보이고 ③ 질문 → 설정 차이가 사람이 읽을 수 있는 YAML로 남아 그대로 개념 2의 증빙 묶음 입력이 된다는 것.
- 솔직한 판정: **차별성은 중간**. 합성 분포 위의 반사실은 장난감처럼 보이기 쉽고, 실제 병원 분포는 2단계 온보딩이 있어야 의미가 생긴다.

**LLM과 결정적 코드의 몫**: LLM은 질문 → 설정 차이(허용 키 목록 안에서만), 결과 설명. 숫자는 전부 재생·몬테카를로. 허용 키 밖이면 "이 질문은 지금 모형으로 답할 수 없다"고 답한다.

**안전 이야기**: 시험 공간(별도 저장소)에서만 돈다. 운영 정책 파일을 바꾸지 않는다. 실제로 바꾸려면 개념 2의 묶음과 사람 승인을 거친다.

**합성 데이터 데모**: 현장조사에서 나온 운영 질문 5개(13:30 일괄 정리, 청소 2교대 공백, 퇴원 라운지, 가퇴원, 당일 오전 배정 모드)를 P10~P90 구간으로 비교한 표.

**크기**: M. 몬테카를로와 운영 설정은 있다. 설정 차이 해석과 비교 보고가 새로 필요하다.

**위험**: 생성기와 같은 구조의 과정 모형이라 결과가 낙관적이다(8단계 기록과 같은 문제). 결과 머리에 "모형 가정"을 크게 쓴다. 결과를 병원 발표 수치와 비교하지 않는다.

**계획 변화**: 1단계 끝 또는 2단계(실제 분포가 생긴 뒤). 지금은 개념 4의 "반사실 한 줄"만.

### 개념 8. 채널 협상 코디네이터: 병동·원무·응급실 사이를 메신저로 조율 (채택하지 않음 권고)

**한 줄 제안(평가용)**: 에이전트가 원내 메신저·문자로 병동에 "12번 몇 시 준비돼요?"를 묻고, 응급실과 원무 사이 대기 순서를 협상하고, 답을 모아 계획을 고친다.

**왜 매력적으로 보이나**: 해외에는 사람 대신 전화하는 음성 에이전트가 이미 있다(요양시설 입소 확인 전화, 퇴원 후 환자 전화, 검색 요약). "새 화면 대신 쓰던 채널로"는 POS-3 방향과 맞는다.

**정직한 판정: 지금은 하지 않는다.**
- 현장 구조와 안 맞는다. 병동은 배정을 **통보**받고 준비되면 "올려주세요"라고 한다(판결 1차, 영상 자막, 저장소 기록). 협상할 공식 단계가 없다. 에이전트가 묻기 시작하면 공식에 없는 단계를 새로 만드는 셈이다.
- 간호사에게 메시지가 늘어난다. "AI가 늘었지만 더 바빠졌다"(검색 요약)는 바로 이 실패다. 엔드픽처("사람은 책임질 순간에만")와 거꾸로 간다.
- 원내 메신저 자동 메시지 국내 근거가 0건이다(EMR_병상관리, 저장소 기록). 연동 대상조차 모른다.
- 협상은 LLM이 판단(누가 먼저)을 하게 만든다. U8과 목표 함수의 사전식 순서(임상 우선순위는 정책 파일)를 흔든다.
- POS-3은 SPEC에서 "설계"라 구현 대상이 아니다.

**남길 수 있는 작은 조각**: 묻는 대신 **듣기**(개념 3), 그리고 사람이 보낼 연락의 **초안 쓰기**(10시 연기 연락 대상과 사유를 결정적으로 고르고, LLM이 원무가 쓸 안내 문구 초안을 쓴다. 보내는 것은 사람과 기존 HIS 알림톡). 초안 쓰기는 개념 4의 출력 형태로 S.

**크기**: L(연동·현장 검증 포함). **위험**: 높음. **계획 변화**: 없음. 현직자 설문에서 "병동이 준비 시각을 어떻게 알리나"의 답이 나오면 다시 본다.

## 5. 순위

점수는 작업자의 판단이다(1~5, 높을수록 좋음). "에이전트다움"은 LLM이 규칙 엔진이 못 하는 일을 하는 정도, "자산"은 이미 있는 코드를 쓰는 정도, "현장 적합"은 현업 공감 원칙(CLAUDE.md 7번)에 비춘 판단이다.

| 순위 | 개념 | 차별성 | 에이전트다움 | 자산 재사용 | 안전 | 현장 적합 | 데모 비용(낮을수록 5) | 합 | 크기 |
|---|---|---|---|---|---|---|---|---|---|
| 1 | 독립 실행 관문 | 5 | 2 | 5 | 5 | 4 | 4 | 25 | M |
| 2 | 자율화 증빙 묶음 | 5 | 2 | 5 | 5 | 4 | 5 | 26 | S~M |
| 3 | 말과 메모에서 신호 듣기 | 4 | 5 | 4 | 4 | 4 | 3 | 24 | M |
| 4 | 왜 늦나, 그때 알 수 있었나 | 4 | 4 | 5 | 5 | 4 | 4 | 26 | S~M |
| 5 | 적대적 시나리오 공장 | 3 | 4 | 4 | 5 | 3 | 3 | 22 | M |
| 6 | 숨은 규칙 찾기(2단계 씨앗) | 4 | 4 | 3 | 4 | 4 | 2 | 21 | S / L |
| 7 | 반사실 시험 | 2 | 3 | 4 | 5 | 3 | 3 | 20 | M |
| 8 | 채널 협상 코디네이터 | 2 | 5 | 1 | 2 | 1 | 1 | 12 | L |

**합만으로 줄 세우지 않은 이유**: 2와 4가 합은 높지만 1을 맨 위에 둔 것은, 1이 **제품이 무엇인지**를 바꾸고 2·4·5가 그 서술을 받치는 부품이기 때문이다. 순서대로 묶으면 하나의 이야기가 된다.

> **"병상을 움직이는 AI는 누구 것이든 이 관문을 지나야 하고(1), 관문이 안전하다는 증거는 매번 자동으로 나오며(2·5), 전산에 없는 신호는 말에서 듣고(3), 늦어진 이유는 근거와 함께 말해 준다(4). 병원마다 다른 숨은 규칙은 사람 손의 기록에서 찾아 묻는다(6)."**

에이전트다움이 낮은 1·2가 위에 있는 것은 의도다. 사용자가 원한 "진짜 차별점"은 LLM을 더 많이 쓰는 데서가 아니라, **LLM을 쓰는 사람들(공급사, 병원)이 아직 못 푸는 문제를 푸는 데서** 나온다는 판단이다. 대신 3·4가 이 제품이 말로만 "에이전트"가 아니라는 것을 보인다.

## 6. 1단계·2단계 계획에 주는 변화 (제안)

### 6.1 1단계 안에서 (기존 구현 우선순위를 바꾸지 않고 뒤에 붙임)

| 순서 | 할 일 | 개념 | 크기 | 먼저 DECISIONS에 적을 것 |
|---|---|---|---|---|
| 1 | 증빙 묶음 생성기(지금 결과 파일을 묶는 보고서, 합격선 표) | 2 | S~M | 합격선과 "승격 불가" 처리. 운영 중 자동 강등(EVL-6 "설계")은 하지 않는다는 경계 |
| 2 | 지연 설명과 "그때 알 수 있었나"(임계 경로, 숫자 대조 검사기, 원인 단계 적중률) | 4 | S~M | PRD 지표 추가 여부 |
| 3 | 외부 제안 어댑터와 외부 엔진 흉내 3개 비교 재생, 사후 감시 모드 | 1 | M | GW-13("설계")과의 경계, 포지셔닝 문구 변경(03·04 기획 문서) |
| 4 | 격리 불일치 경보(조이는 쪽만) | 3 일부 | S~M | SEC-3·LP-19와의 관계, 경보 상한 |
| 5 | 시나리오 공장 첫 묶음(10개, 다른 계열 모델) | 5 | M | 라벨 승인 절차, 블라인드 표시 |
| 6 | 직접 수정 무늬 보고서(결정적만) | 6 일부 | S | 없음(읽기 전용 보고) |
| 7 | 말과 메모 채널 전체(푸는 쪽 포함, 관측 후보 상태) | 3 | M | "관측 후보"가 타이머·추정에 들어가는 범위 |

- 화면(9순위, Streamlit 목업)은 여전히 마지막이다. 다만 목업 첫 화면을 "병상 현황"이 아니라 **"오늘 관문이 막은 것과 그 이유, 늦은 사례 5건의 이유"**로 바꾸는 것을 제안한다. 현황판과 겹치지 않는 화면이다.
- 현직자 설문 답이 오면 바뀔 수 있는 것: 개념 3의 입력원(인계장이 전산 텍스트인가), 개념 8 재검토, 개념 6의 사유 코드.

### 6.2 2단계(온보딩)에서

- 온보딩 스펙 3절에 "숨은 규칙 초안"(개념 6)을 단계로 더하고, 7절 "그림자 운영 평가"의 결과를 개념 2의 증빙 묶음 형식으로 낸다. 온보딩의 끝 산출물이 "설정 파일"이 아니라 **"설정 파일 + 이 설정이 안전하다는 증빙"**이 된다.
- 개념 7(반사실)은 실제 분포가 생기는 2단계에서 가치가 커진다. 온보딩 직후 "당신 병원에서 13:30 일괄 정리를 당기면" 같은 첫 보고서로 쓴다.
- 처음 보는 가상 병원에서 외부 엔진 흉내(개념 1)를 함께 돌리면, "새 병원 + 남의 배정 AI + 우리 관문" 조합의 시험이 된다. 2단계 증명 숫자(SPEC 비전 표)에 "외부 엔진 앞 관문 통과 배정의 안전 위반 0건"을 더하는 안.

### 6.3 바꾸지 않는 것
- U8(병상 선택은 규칙, LLM은 설명), 목표 함수의 사전식 순서, `external_llm: deny`, 청소·이송 인력 배정 제외, 자체 현황판 없음, 퇴원 예측 ML 없음, 환자 자동 연락 없음.

## 7. 버린 아이디어와 이유 (짧게)

| 아이디어 | 버린 이유 |
|---|---|
| LLM이 병상을 직접 고르는 "더 똑똑한 배정" | 이미 상용(세종, 분당서울대 등). U8과 검증 가능성을 잃는다. 모델 점검의 `select` 모드로만 잰다 |
| 퇴원 가능성 예측 LLM | Epic·Qventus·GE 영역, 실데이터 없음 |
| 환자·보호자에게 직접 전화하는 음성 에이전트 | 환자 연락은 책임 순간. 해외 공급사 영역. 국내는 알림톡 체계가 이미 있다 |
| 자체 음성 인계 기록 | 서울성모·강북삼성·Dragon Copilot이 하는 일. 그 결과를 읽는 쪽에 선다(개념 3) |
| 범용 "병원 에이전트 거버넌스 플랫폼" | 너무 넓다. 병상이라는 좁은 영역에서 재생 증빙을 숫자로 보이는 것이 설득력의 원천. 넓히는 것은 1·2를 증명한 뒤 |

## 8. 이 검토의 한계
- 해외 공급사 자료는 차단돼 상당수가 검색 요약이다. 특히 Dragon Copilot, GE CareIntellect, Qventus, TeleTracking의 2026년 에이전트 기능은 원문으로 확인하지 못했다.
- "공개 자료에서 못 찾았다"는 "없다"가 아니다. 대형 공급사 내부 규칙 엔진에 실행 직전 재검사가 있을 가능성은 높다. 이 프로젝트의 차별점은 그 존재가 아니라 **재생 평가로 숫자를 내 보이는 것**에 둔다.
- AI 기본법상 병상 운영 AI가 고영향에 드는지는 시행령·고시 원문을 보지 않았다(확인 필요). 조문 원문은 한국법제연구원 국영문 법령에서 봤고 국가법령정보센터는 접속 실패.
- 점수표는 작업자 판단이다. 현직자 설문 답이 오면 "현장 적합" 열을 다시 매긴다.
- 모든 숫자는 합성 데이터 기준 추정이거나 병원·공급사 발표이며 서로 비교하지 않았다.
