목적: 병실관리AI 화면을 "실제 병원에서 쓸 수 있는 수준"으로 다시 설계하기 전에, 실제 시스템의 화면 구성, 로그인·접근 통제의 법적 기준, 업무 흐름의 화면 단위를 확인한다. 이 문서는 조사 기록이며 설계 변경이 아니다.

- 출처 표기: `[URL | 1차/보조 | 원문 확인 / 요약만 / 저장소 기존 조사 인용]`

## 핵심 결론 7줄

1. **국내 HIS의 병상 관리 화면은 공개 자료가 거의 없다.** 공개 1차 근거로 확인되는 화면 단위는 서울아산 병상 배정 담당자가 차례로 보던 "퇴원 환자 목록 → 병동 현황 → 병상 변경 환자 목록 → 입원 예정자 → 응급실 환자 목록"과, 분당서울대 스누워드가이드의 "진료과별 대기 순위, 등급별·병동별 가용 병상, 추천 순위, 가용 전환·입퇴원·전실전동 현황 한 화면"(기사)까지다. 국내 병상 상태 색상 체계는 **확인 안 됨**이다(요양병원 EMR 병실현황 색은 보험 유형).
2. **해외 대표 제품은 역할별로 화면을 나눈다.** TeleTracking 공식 도움말 기준으로 배정 담당(요청 목록 + 환자·배정 상세 + 병상 고급 검색), 병동(유닛 탭: 병상별 행, 상태 열, 퇴원 단계 막대, 병상 배정 우선순위), 청소(모바일 작업 목록: 시작·지연·중단·완료), 청소 감독(병상 상태별 목록, 경과 시간 경보색), 관제(대시보드)가 따로 있고, 상태별 색과 글자 기호가 함께 쓰인다. Epic·Oracle Health·GE도 공식 페이지에서 같은 역할 분할(배정, 병동, EVS, 관제)을 말한다.
3. **로그인·접근 통제의 법적 최저선은 원문으로 확인했다.** 사용자별 계정(공유 금지), 직종·업무별 최소 권한과 변경·말소, 권한 부여 내역 3년 보관, 로그인 실패 시 접근 제한, 일정 시간 미사용 시 자동 접속 차단(EMR 인증 해설서: 10~60분, 화면보호기는 해당 안 됨, 재접속은 최초 로그인과 같은 절차), 접속기록(식별자·일시·접속지·처리한 환자·수행업무) 저장과 점검, 민감정보 처리 시스템은 2년 이상 보관, 외부 접속은 인증서·보안토큰·OTP 등, 비밀번호 일방향 암호화.
4. **2026-12-10부터 의료법 제23조 제4항은 전자의무기록을 "열람"만 해도 접속기록을 따로 보관하게 한다**(개정 법률 원문 확인). 시행규칙 개정안은 입법예고 단계다(기사). 우리 화면에서 환자 정보를 여는 모든 동작은 감사 로그 대상으로 설계하는 것이 현실과 맞다.
5. **국내 병원의 실제 로그인 수단(사원증 태깅, 지문, 인증서, 근무부서 선택 화면)은 공개 1차 근거로 확인 안 됨**이다. 확인된 국내 정황은 "EMR 화면에 로그인한 사람 이름이 담당자로 자동 표시"(요양병원 EMR 영상), "약국 화면은 약사 아이디로 따로 로그인"(같은 채널), "전공의 근무시간이 끝나면 EMR 셧다운, 그 결과 남의 아이디를 빌려 쓰는 일"(기고)뿐이다. 해외는 로그인 때 근무 부서 선택(Houston Methodist 공지), 배지 탭과 빠른 사용자 전환(Imprivata), 근무조마다 담당 병동을 고르는 "membership" 선택과 "End session/Sign out" 구분(TeleTracking 도움말)이 1차 자료로 확인된다.
6. **하루 화면 이동의 국내 근거는 원무 쪽만 있다.** 병실 배정은 입원 당일 오전 일괄 작업이고, 진료과 요청은 전화·그룹웨어 메시지로 하루 약 250건(서울아산)이며, 병동은 배정을 통보받고 준비가 끝나면 "올려주세요"라고 전화한다. 청소 요청과 완료가 어떤 경로(전화, 메신저, 시스템)로 오는지는 저장소 누적 조사를 포함해 **국내 확인 안 됨**이다. 해외는 퇴원 처리 시 병상이 자동으로 Dirty가 되고 청소 요청이 생긴다(Epic, TeleTracking 원문).
7. **시사점**: 반드시 있어야 할 것은 로그인 + 근무 병동·역할 선택, 화면 잠금(미사용 자동 잠금)과 사용자 전환, 모든 입력에 로그인한 사람 자동 기록, 촘촘한 목록형 작업 화면(정렬·필터·경과 시간 경보색), 병상 현황판(색 + 글자 병기와 범례), 환자 표시 2지표와 고유식별정보 마스킹, 접속기록 조회 화면이다. 데모에서 흉내만 내도 되는 것은 실제 인증 수단(비밀번호 정책 전체, OTP·인증서, SSO·배지)과 권한 관리 화면 전체다. 다만 계정 공유를 전제로 한 설계(공용 "병동 계정")는 법적 최저선과 어긋나므로 흉내로도 만들지 않는다.

### 1.2 해외: TeleTracking (Capacity IQ / Capacity Management Suite)

공식 도움말 센터(help.teletracking.app)가 역할별 빠른 참조 안내서(QRG)를 공개하고 있어, 이번 조사에서 가장 구체적인 1차 자료다. 아래는 모두 원문 확인.

**제품 구성과 역할**
- "Capacity IQ® contains multiple applications … for patient placement, nursing, housekeeping, and transport." 구성: Transport(이송), EVS(병상 청소), PreAdmit("with the electronic bedboard® view … manage patient placements and bed assignments"), Patient Tracking Portal("gives nurses and unit staff members quick and comprehensive access"). "Depending on your permissions, you may have access to all or just some of the applications." [https://help.teletracking.app/en/articles/10656724-applications-overview | 1차(공급사 도움말) | 원문 확인]
- Patient Tracking Portal은 "can also replace the manual, static nursing unit whiteboards"이고, 병동이 격리 유형·식이 입력, 병상 속성, 병상 배정 우선순위("bed ahead"), 직원 배정, 메시지, 입원·전동·퇴원 처리, 퇴원·전동 마일스톤, "Re-occupy beds marked clean by mistake"를 한다. [같은 URL | 1차 | 원문 확인]

**배정 담당(Patient Placement) 화면** [https://help.teletracking.app/en/articles/9066775-patient-placement-in-preadmit-qrg-capacity-iq-preadmit | 1차 | 원문 확인]
- 로그인 뒤 "Patient Placement view". 주 소통 도구는 "Screen Alerts"(병상 요청, 메시지 수신).
- 요청 흐름: "Requesting Area creates a bed request → Patient Placement Targets the most appropriate unit → Requesting Area Activates the Ready to Move (RTM) Timer → Patient Placement Provides a Bed Assignment → … coordinate report and movement → The patient occupies the Assigned Bed in the ADT System closing out the Bed Request."
- 환자·배정 상세(Patient/Placement Details) 항목: Admit Diagnosis, Associated Physicians, Level of Care, Bed Custom Attributes, Isolation, Patient Custom Attributes, Comments, Origin Unit.
- 병상 고급 검색(Adv. Search) 열: Unit, **Priority**(병동이 정한 배정 순서), Bed(성별 색: "Blue - Male Bed, Pink - Female Bed, Gray - Either Gender"), **ST**("if a bed is occupied but that patient is in a discharge status, it will show that bed as potentially available"), Bed Size, Accom(1인·다인), Custom Attributes(예: 간호사실 근처, 음압).
- "A final bed assignment should NOT be provided by Patient Placement until the RTM is activated." 배정되면 요청·수용 양쪽 병동에 알림. 환자가 도착해 병상을 차지할 때까지 요청 목록에 남는다.
- 환자 검색은 "Visit Number is the preferred search method to ensure the correct patient record is always being used."

- ③ "누구든지 정당한 사유 없이 전자의무기록에 저장된 개인정보를 탐지하거나 누출ㆍ변조 또는 훼손하여서는 아니 된다."

**개정 의료법 제23조 제4항(시행 2026.12.10, 법률 제21776호, 2026.6.9 일부개정)** [https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=286719 | 1차 | 원문 확인]

- 후속 시행규칙 개정안(열람 시 이력관리 장비에 접속기록 보관, 12월 10일 시행 목표)은 입법예고 단계로 보도됨. 의료계는 "열람"의 범위(차트 클릭, 일부 조회, 자동 갱신 호출 등)와 보관 기간이 불명확하다고 지적 [https://dentalnews.or.kr/news/article.html?no=48293 | 보조(기사) | 원문 확인], [https://dailymedi.com/news/news_view.php?wr_id=940408 | 보조 | 요약만]. 시행규칙 최종본은 **확인 안 됨**.

- ② "전자의무기록에 추가기재ㆍ수정을 한 경우 제1항제2호에 따른 장비에 접속 기록을 별도로 보관하여야 한다."

| 화면을 오가는 실제 순서(클릭 단위) | **확인 안 됨**(내부 화면 비공개, 원무 영상 자막 못 받음: TG5b92gLLZc 삼성서울 입원파트, RgWVhQotRAQ 원무팀의 하루) | TeleTracking QRG 순서가 가장 구체적 |

### 3.2 병동이 입실 준비를 확인하는 곳

- 국내: 병동은 EMR "병실현황"에서 재원·퇴원 예정을 보고, 입원 연락을 받으면 투약 티켓·네임카드·침상 정리 뒤 "올려주세요"라고 알린다(블로그 원문, 저장소 인용). 퇴원 침상 정리와 신환 침상 준비는 병동 보조 인력의 정해진 시각 일과로도 돈다(해운대백 과업지시서 "13:30", 저장소 인용 원문). 전산 "입실 가능" 버튼은 **국내 확인 안 됨**.
- 해외: 병동이 병상 배정 우선순위(1~9)를 화면에 걸어 배정팀 전화를 줄이고(TeleTracking 원문), 입실 처리는 환자가 실제로 병동에 온 뒤 한다(Epic Unit Manager, Iowa 원문). 영국 NHS는 청소 담당이 "Inform Nurse in Charge that the room is ready"하고 둘이 서명(저장소 인용 원문).

### 3.3 청소 요청·완료 경로

- 국내: **확인 안 됨.** 저장소의 누적 조사(`EMR_병상관리.md` 3.3, `감염관리_청소_실무.md` 3절, `국내EMR_시스템.md` 5절)와 이번 검색(강동경희대 스마트병원 환경관리 선도모델 포함)에서도 전화·메신저·시스템 중 무엇인지 1차 자료가 없다. 확인된 것은 미화와 병동 보조 두 직종에 걸친다는 점, 청소 인력의 야간 공백 사례(보도) 정도다.
- 해외(1차, 원문): Epic "When a patient is discharged or transferred, the system marks the bed as dirty and creates a cleaning request", TeleTracking "As patients are discharged the beds will automatically dirty and notify EVS staff", 청소원은 모바일 작업 목록에서 시작·완료, 지연·중단은 사유 필수, 감독은 경과 시간 경보색으로 관리. TeleTracking 상태 정의에 IVR(전화) 입력 흔적이 남아 있다.

## 4. 시사점: 우리 화면에 반드시 있어야 할 것과 흉내만 낼 것

### 4.1 반드시 있어야 할 것(근거 있음)

| 항목 | 이유와 근거 |
|---|---|
| 로그인 화면 + 사용자별 계정(합성 직원 명단) | 계정 공유 금지(안전성 확보조치 기준 제5조④), "모든 사용자에게 별도 계정"(인증 12.4), "사용자별로 필요 계정"(EMR 인증 F001). 현재 저장소는 로그인 없이 승인자 ID를 입력값으로 받는다(`docs/가이드/데모_가이드.md` 66행, `docs/DECISIONS.md` 524·547·557행). 현직자에게 "누구나 아무 이름으로 승인"하는 화면은 현실과 어긋난다 |
| 근무 병동·역할 선택(로그인 직후, 근무 중 전환 가능) | 직종·업무별 최소 권한(F002, 고시 제5조①). 해외는 로그인 때 부서·병동 선택이 표준 동작(Houston Methodist, TeleTracking). 국내 화면은 확인 안 됨이므로 "설계 가정"으로 표시 |
| 미사용 자동 잠금 + 재로그인 | F004("화면보호기는 해당 안 됨", 10~60분), 고시 제6조④, 인증 6.1 "PC log out/화면보호기 설정". 잠금 해제는 최초 로그인과 같은 절차 |
| 근무조 전환(사용자 바꾸기) | 공용 병동 PC에서 교대 때 이전 사용자 세션을 끝내고 새 사용자로 들어가는 동작(TeleTracking "End Session"). 국내 실제 방식은 확인 안 됨, 설계 가정 |
| 모든 입력·승인·확인에 로그인한 사람·시각 자동 기록 | 국내 EMR도 로그인 사용자 이름이 자동으로 뜬다(자막). 의료법 제23조④(2026.12.10부터 열람 포함), 고시 제8조, F008 |
| 접속기록(열람 포함)과 조회 화면 | 개정 의료법(열람), F008 항목(ID, 일시, 접속지, 환자, 수행업무, 화면 정보 권장). 우리 감사 로그를 "열람" 이벤트까지 넓히고, 관리자 역할에 조회 화면을 둔다 |
| 촘촘한 목록형 작업 화면(역할별) | 국내 실제 업무가 "목록 순회"(아산), 해외 QRG도 목록 열 중심(상태, 상태 경과 시간, 담당, 병동, 격리 유형). 정렬·필터·페이지·경과 시간 경보색(TeleTracking 주황 1차 경보, 빨강 상향, 황갈색 지연) |
| 병상 현황판(병동 단위) | 해외 공통(유닛 탭, Bed Board, Whiteboard). 국내도 병실현황 화면이 있음(색 의미는 다름). 상태는 **색 + 글자**를 함께(TeleTracking ST 열처럼), 범례 필수. 색 체계는 국내 표준이 없으므로 "설계 가정" 표시 |
| 환자 표시 2지표 + 고유식별정보 마스킹 | 인증 1.1(병실호수는 환자 확인 지표 불가), F006(목록에서 고유식별정보 일부 마스킹). 합성 데이터라도 이름 + 등록번호를 함께 보이고, 주민번호 같은 필드는 화면에 두지 않거나 마스킹 |
| 사유 필수 입력(차단·지연·취소) | Cerner Blocked/Out of Service 사유 필수, TeleTracking 청소 취소·지연·중단 사유 필수 |
| 환자 위치 갱신과 실제 입실 구분 | Epic "NOT to be completed until the patient is physically on the unit" |

### 4.2 데모에서 흉내만 내도 되는 것

| 항목 | 이유 |
|---|---|
| 실제 인증 수단(공동인증서, OTP, 지문, 사원증 태깅, SSO) | 국내 실제 수단 자체가 확인 안 됨이고, 병원 인사·인증 시스템과 연결해야 한다. 데모는 합성 직원 계정 + 간단 비밀번호(또는 선택 목록)로 충분. 화면에 "실제 병원은 원내 인증 연동" 안내 |
| 비밀번호 정책 전체(작성 규칙, 주기 변경, 5회 실패 잠금) | F001·F003 기능 요구지만 데모 목적과 무관. 단 **저장은 일방향 해시**로 하는 것이 비용이 거의 없고 고시 제7조와 맞다 |
| 권한 관리 화면(부여·변경·말소 이력 3년) | F002·고시 제5조③. 데모는 역할 설정 파일로 대신하고, "권한 변경 이력은 실제 병원 인사 시스템" 표시 |
| 외부 접속 MFA, IP 제한 | 고시 제6조①②. 데모 범위 밖 |
| 접속기록 2년 보관·위변조 방지 | 개념만 보이고(추가만 하는 SQLite 기록이 이미 있음), 보관 기간·점검 절차는 문서로 |

### 4.3 만들면 안 되는 것

- **공용 "병동 계정"이나 역할만 고르는 로그인(이름 없이 "간호사"로 들어가기).** 개인별 계정·공유 금지가 법적 최저선이고, 현직자가 보면 바로 어긋남을 안다.
- **국내 표준처럼 보이는 병상 상태 색.** 국내 근거가 없다. 해외(TeleTracking) 색을 쓰더라도 "설계 가정, 해외 제품 참고"로 적는다.
- **청소 완료가 국내 시스템 신호로 온다는 전제의 화면.** 국내 확인 안 됨. 청소 완료 입력 주체·수단은 병원 설정(전화를 받은 병동·원무가 입력 등)으로 둔다(저장소 `EMR_병상관리.md` 4.1 제안과 같음).

### 4.4 현직자에게 물을 것(기존 질문지에 없는 것만)

1. 병동 공용 PC에서 근무 교대 때 로그인을 어떻게 넘기나(로그아웃 후 재로그인, 잠금 화면에서 다른 사람이 로그인, 사원증·지문)?
2. 로그인할 때 근무 병동이나 부서를 고르나? 지원 근무(다른 병동)일 때는?
3. 원무 병상 배정 담당은 하루에 화면을 몇 개 띄워 놓고 일하나(모니터 수, 대기 목록과 병상 현황을 한 화면에서 보나)?
4. 미사용 자동 잠금 시간은 몇 분인가? 간호사실 PC는 예외인가?
