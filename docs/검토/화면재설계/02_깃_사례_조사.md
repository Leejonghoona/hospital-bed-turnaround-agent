# 02. GitHub 사례 조사: AI 에이전트 포트폴리오는 어떻게 보여주는가

- 조사일: 2026-11-10
- 대상 프로젝트: 병실관리AI(병상 턴어라운드 관제 에이전트 데모, Python, Streamlit, 합성 데이터, 결정적 실행 게이트웨이, 평가 하네스)
- 방법: `gh api -X GET search/repositories`(페이지 1, `per_page=30`, 별 순 정렬)로 검색어 16개를 돌려 후보를 모으고, README 원문을 `raw.githubusercontent.com`에서 받아 읽음.
  - 참고: 이 세션에서는 `gh api repos/<owner>/<repo>/readme`가 권한(403)으로 막혀 있어 README는 raw URL로 받았다. 별 수와 최근 푸시일은 검색 API 결과에서 가져왔다.
- 사용한 검색어: hospital bed management agent, bed management hospital, hospital operations agent, healthcare agent streamlit, patient flow simulation, multi-agent hospital, langgraph hospital, agent evaluation harness, agentic workflow demo, LLM agent portfolio, hospital capacity forecasting streamlit, bed occupancy dashboard, nurse scheduling agent, customer service agents demo openai, human-in-the-loop approval agent dashboard, replay mode agent demo 외
- README를 읽은 저장소: 27개(아래 "전체 목록"). 그중 10개를 깊게 분석.
- 라이브 데모 접속 확인(2026-11-10, curl): GoldenHour(Render) 200, langgraph-approval-hub(Vercel) 200, claude-agent-prototype(Vercel) 200, code-blue-defense(GitHub Pages) 200. Streamlit Community Cloud 앱 3개는 303(잠든 앱이 깨우기/로그인 페이지로 넘기는 응답)이었다. 즉 Streamlit Cloud는 "첫 방문자가 깨우기 버튼을 눌러야 하는" 경우가 흔하다는 점을 감안해야 한다.

## 1. 한눈에 보는 결론

1. **잘 만든 데모는 첫 화면에서 "API 키 없이 돌아가는 모드"를 기본값으로 둔다.** GoldenHour(mock/live/replay 배지), ai-governance-risk-triage-agent(`MOCK_MODE` 기본 true), claude-agent-prototype(키 없으면 자동 replay), ai-lead-research-agent(Demo mode가 저장된 스냅숏 재생), icu-mortality-prediction(로컬 LLM이 없으면 미리 만든 예시로 자연스럽게 강등). 우리 프로젝트의 "결정적 가짜 LLM이 기본값" 원칙과 정확히 같은 방향이다.
2. **"시연 화면/실제 화면"을 가르는 실제 방식은 로그인이 아니라 (a) 모드 배지 + (b) 역할 전환기 + (c) 안내 투어 버튼**이다. 데모 계정 로그인 화면을 둔 포트폴리오 저장소는 이번 표본에서 찾지 못했다. 오히려 GoldenHour와 governance 데모는 "로그인은 없다, 역할은 표시용"이라고 한계 절에 정직하게 적는다.
3. **도메인이 가장 가까운 최고 사례는 GoldenHour**(병원 퇴원 전 보험 사전승인 데스크). "모델은 돈 계산과 자격 판단을 하지 않는다", "Action Gateway가 부작용의 유일한 통로", "해시 체인 감사 로그", "24시간 하루 재생", "70초 안내 투어(`/console?demo=1`)"까지 우리 설계(실행 게이트웨이, 결정적 도구, 재생 평가)와 구조가 거의 같다. README 구성을 그대로 본뜰 만하다.
4. 별이 많은 공식 데모(openai-cs-agents-demo 6.6k, agents-from-scratch 2.4k, temporal-ai-agent 790)는 **스크린샷 1장 + 시나리오별 "이렇게 말해 보세요" 대본 + 영상**으로 보여준다. 반면 평가 수치와 한계 고지는 개인 포트폴리오 쪽(GoldenHour, PayalThangamma, AuditPilot, icu-mortality)이 더 꼼꼼하다.

## 3. 저장소별 메모(깊게 본 것 중 핵심만)

### 3.1 GoldenHour: 우리 프로젝트의 가장 가까운 거울
- 구조가 같다: 추출은 모델, 금액·자격 계산은 순수 규칙 9개, 결정 정책은 YAML(`pack.yaml`), 부작용은 Action Gateway 하나로만, 감사는 해시 체인, 서류 누락 시 상태를 저장하고 업로드가 오면 저장 지점부터 재개.
- 보여주는 방식이 강하다:
  - 히어로 사례 3개(정상 승인 / 서류 누락 후 재개 / 프롬프트 주입 격리)를 표로 "요청 / 시스템이 한 일 / 최종 상태"로 정리.
  - 서버 시작 시 지난 24시간을 시뮬레이션 시계로 재생해 대시보드가 "빈 화면"이 아니라 하루치가 찬 상태로 열린다. "Replay the day"는 같은 하루를 3분에 다시 재생.
  - 실시간 모델 호출은 시간당 최대 6건만, 나머지는 같은 파이프라인에 결정적 모델 답을 넣은 시뮬레이터. 추적 화면에 "simulated"라고 표시.
  - 감사 화면의 "Tamper test" 버튼이 DB 한 줄을 고쳐 검증이 그 블록에서 실패하는 것을 눈으로 보여 준다.
- README 하단에 `PROGRESS.md`, `DECISIONS.md`, `DEMO_SCRIPT.md`, `CLAUDE.md`를 연결(우리 docs 구조와 같음).

### 3.2 ai-governance-risk-triage-agent: Streamlit + 합성 데이터 포트폴리오의 모범 README
- 맨 위 한 줄 "성숙도" 표기(Live public demo · Synthetic data · Transparent rubric).
- 라이브 링크 옆에 "언제, 무엇을 눌러 확인했는지" 기록.
- 지표 표의 각 숫자 옆에 "이 숫자는 어디서 나왔나(코드 위치, pytest 결과)"를 적고, 포트폴리오용 한 줄 요약("20 synthetic use cases · 5 risk tiers · 62 tests")을 따로 제공.
- "통합 매트릭스": 구성 요소별 mock / live 여부를 표로.

### 3.3 openai-cs-agents-demo: 별 6.6k 공식 데모의 단순함
- 스크린샷 한 장 + 설치 두 단계 + "데모 흐름" 대본 3개. 대본은 "사용자: …" → "어느 에이전트가 무엇을 함" → "화면에 무엇이 빨갛게 켜짐" 순서. 처음 보는 사람이 그대로 따라 하면 핵심 기능(이관, 도구, 가드레일)을 다 본다.

### 3.4 PayalThangamma / AuditPilot / icu-mortality: 평가와 한계를 보여주는 법
- 평가 결과를 숫자 블록으로 그대로 붙이고, "처음엔 100%였지만 적대적 세트에서 깨졌고 그걸로 고쳤다"는 개선 서사를 남긴다(PayalThangamma).
- "내장 평가는 회귀 기준선이지 업무 정확도의 증거가 아니다"(AuditPilot), "특정 집단 성능 저하를 숨기지 않고 보고"(icu-mortality)처럼 주장 범위를 스스로 좁힌다. 우리 규칙 6("합성 데이터 기준 추정")과 같은 태도.

### 3.5 시연/실제 모드 분리의 실제 구현 4가지
| 방식 | 사례 | 구현 |
|---|---|---|
| 모드 배지 + 자동 강등 | GoldenHour(mock/live/replay), claude-agent-prototype(키 없으면 replay), icu-mortality(로컬 LLM 없으면 미리 만든 예시) | 환경 변수와 키 유무로 결정. 화면 헤더에 현재 모드를 항상 표시 |
| 읽기 전용 데모 기본값 | langgraph-approval-hub | 공개 배포는 버튼 비활성 + 서버 403. 환경 변수로만 실제 모드 |
| 시드 사례 선택 | ai-governance(시드 20개 드롭다운), openai-cs(모의 일정 2세트), GoldenHour(히어로 사례 3개) | 첫 화면에서 예시를 고르면 바로 결과까지 진행 |
| 안내 투어 버튼 | GoldenHour(▶, `?demo=1`, 70초 자막 재생 + 역할 자동 전환), claude-agent-prototype("Try this →") | URL 파라미터나 버튼 하나로 대본 자동 재생 |

- 역할 선택: GoldenHour는 헤더의 역할 전환기(4역할)로 같은 사례를 다른 권한으로 보여 주고, 권한 밖 행동은 실제로 403을 띄워 게이트가 동작함을 증명한다. 로그인 화면은 없다(한계 절에 명시).
- 데모 계정 로그인을 첫 화면으로 둔 포트폴리오 사례는 이번 표본에서 발견하지 못했다. 로그인은 보는 사람의 10초를 잡아먹는 장벽이라 피하는 경향으로 보인다(관찰에 근거한 추정).

## 4. 10초 안에 이해시키는 공통 패턴 7가지

1. **첫 3줄 공식: 이름 → 무엇을 누구를 위해 → 사람이 어디서 책임지는지.** GoldenHour("Humans approve every denial…"), PietroBosi("Emails are drafts only and are never sent"), optimizer("LLM agents decide, skfolio optimizes, you approve"). 에이전트 프로젝트는 "자율성의 경계"를 3줄 안에 말한다.
2. **스크롤 없이 보이는 라이브 링크 또는 실행 배지.** "Live demo:" 인용 블록, Streamlit 배지, "▶ PLAY IT NOW — no install". 링크 옆에 확인 날짜를 쓰면 신뢰가 오른다(ai-governance).
3. **결과 화면 스크린샷 1장(대체 텍스트에 장면 설명)**을 제목 바로 아래. 아키텍처 그림보다 먼저. 영상이 있으면 썸네일 링크(temporal, Azure).
4. **키 없이 도는 기본 모드 + 현재 모드 표시.** mock/replay가 기본, live는 선택. 시연이 API 장애나 요금제 한도에 깨지지 않게 하고, README에 "발표는 replay가 안정적"이라고 쓴다.
5. **대표 시나리오 3개를 표나 대본으로.** "입력 → 시스템이 한 일 → 최종 상태". 정상 경로 1개 + 예외 처리 1개 + 안전 장치가 막는 장면 1개 조합이 반복된다(GoldenHour, openai-cs).
6. **숫자 하나하나에 출처를 붙인 평가 표 + 기준선 비교.** 평가 세트 크기, 기준선 대비 개선, 재현 명령, 그리고 "이 수치가 무엇을 증명하지 않는지".
7. **"이것은 무엇이 아닌가" 고지를 첫 화면과 한계 절 두 곳에.** 첫 화면엔 한 줄(합성 데이터, 의료기기 아님), 아래엔 구체적 한계와 다음 단계. 과장 수식어("Enterprise-Grade", "Projected impact 15-20%")만 있고 결과·한계가 없는 저장소(HospitalSim, Digital Twin, icuflow 일부)는 오히려 신뢰가 떨어진다.

부가 패턴: "Skills demonstrated" 표(icu-mortality), "내가 직접 만든 부분" 절(PietroBosi), 해커톤 수상 배지(DylanTombs), "하고 싶은 일 → 진입 경로" 표(optimizer).

### 5.3 첫 화면에서 "실제 화면 / 시연 화면"을 고르는 방식(실제 사례 기반 제안)

권장: **로그인 화면 없이, 첫 화면 상단에 3가지를 고정 배치**한다.

1. **모드 배지(사이드바 상단)**: `시연(결정적 LLM · 재생)` / `실제 모델` 중 현재 모드를 항상 표시. 실제 모델은 환경 변수가 있을 때만 활성, 공개 배포에서는 비활성으로 회색 처리하고 이유를 툴팁으로(GoldenHour mock/live/replay, langgraph-approval-hub 읽기 전용 기본값).
2. **"안내 투어 시작 ▶" 버튼과 `?tour=1` URL**: 대표 사례 A/B/C를 60~90초 동안 단계별 자막과 함께 자동 진행(Streamlit에서는 `st.query_params`로 투어 진입, 단계 상태는 `st.session_state`로). README의 라이브 링크를 투어 URL로 직접 걸어 두면 클릭 한 번에 핵심 장면이 보인다(GoldenHour `/console?demo=1`, claude-agent-prototype "Try this →").
3. **역할 선택기**: `병동 간호사 / 병상 배정 담당 / 감사자` 등 2~4개. 같은 사례를 역할마다 다르게 보여 주고, 권한 밖 확정 시도는 게이트웨이가 실제로 거절하는 장면을 보이게 한다. 단, README 한계 절에 "역할은 시연용 선택일 뿐 인증이 아니다"를 명시(GoldenHour, ai-governance와 같은 표현). 역할 명칭과 권한은 CLAUDE.md 규칙 7에 따라 현업 절차를 조사해 정하고, 근거가 없으면 "설계 가정"으로 표시.

추가로 첫 화면에 둘 것:
- "시나리오 불러오기" 드롭다운(회귀 시나리오 30개 중 대표 5~6개, ai-governance의 시드 20개 방식)
- "하루 재생" 슬라이더나 재생 버튼(GoldenHour "Replay the day")
- 화면 하단 고정 한 줄: "합성 데이터 · 임상 의사결정 도구 아님 · 수치는 합성 데이터 기준 추정"

피할 것(반면교사):
- 첫 화면 로그인/데모 계정 입력(이번 표본의 잘 만든 데모 중 아무도 쓰지 않음)
- 실행에 Kafka·Redis·외부 DB가 필요한 Quick Start(Hospilot)
- "Live Demo" 텍스트가 실제로는 설치 안내로 가는 링크(DylanTombs)
- 근거 없는 효과 추정치(icuflow "Projected impact")와 실제 병원명 사용(Chanith27)
