### A-2. "실제로 사람들이 에이전트 프로젝트를 어떻게 작업하는가" (위 출처에서 공통으로 보이는 순서)

1. 문제를 워크플로로 풀 수 있는지 먼저 본다. 결정적 코드로 되는 부분은 코드로 둔다(1, 8, 9, 16).
2. 가장 좋은 모델로 빨리 프로토타입을 만들고 전사본·추적을 남긴다(8, 12).
3. 전사본을 **직접 읽고** 오류를 분류(오류 분석)해 20~50개짜리 평가셋을 만든다. 사용자가 없으면 실제 제약에 근거한 합성 데이터로 만든다(2, 6, 13).
4. 채점은 결정적 코드 → 이진 LLM 채점(사람으로 보정) → 사람 검사 순으로 비용을 올린다(6, 12, 14).
5. 능력 평가로 끌어올리고, 통과한 과제는 회귀 평가로 옮겨 매 변경마다 돌린다(6, 12).
6. 1인 개발(Claude Code 등): 사양 파일 → 시험 먼저 → 기능 하나씩 → 진행 기록 파일과 작은 커밋 → 수정 권한 없는 독립 검토자 → 미리보기 환경에서 확인(5, 7, 17). 검토자 지적을 전부 고치면 과설계가 된다(7).

### B-2. 장단점

| 측면 | 장점 | 단점·위험 |
|---|---|---|
| 첫 화면에서 두 갈래 선택 | 방문자(채용 담당·심사자)는 바로 시연, 현업 검토자는 바로 운영 화면. 빈 화면 대신 "안전한 탐색" 길(NN/g Loggly 예) | 모드가 생긴다: 시연에서 본 숫자를 운영 숫자로 착각, 반대로 운영에서 시연 버튼(다음 단계)을 누르는 실수(NN/g 모드 오류) |
| 같은 앱 안 모드 전환 | 구현이 쉬움(현재 사이드바 라디오) | 모드 표시가 약하면 위험. 의료 현장 관행은 모드가 아니라 **환경 분리**(Connect Care, Emory) |
| 강제 투어 | 순서 통제 | 건너뛰고 잊는다(NN/g 2023). 다시 열 수 있어야 함 |
| 사용자 주도 투어 + 체크리스트 | 진행 표시, 원하는 장면부터 | 처음 보는 사람이 무엇부터 볼지 모를 수 있음 |

우리 프로젝트만의 사정:
- 이 앱은 **두 모드 모두 합성 데이터**다(CLAUDE.md 1번). 따라서 "실제 화면"이라는 이름은 실제 환자 데이터로 오해될 수 있어 피한다. 권장 이름: **"운영 화면(합성 병원)"** 과 **"시연 투어"**. 모든 화면에 "합성 데이터 · 실제 환자 아님" 표시는 모드와 상관없이 고정.
- 이미 `TURNAROUND_MODE=production`(운영 모드에서 개발용 서명 키로 승인한 판 거부)이 있으므로, 화면의 "운영"과 배포 설정의 "운영"을 헷갈리지 않게 화면 쪽 용어를 "운영 화면"으로 한정하고 상단 표시에 배포 설정값도 같이 보인다.
- 현재 `src/turnaround/ui/app.py`는 사이드바 `st.radio("보기", ["시연 대본", "역할 화면"])` 하나로 전환한다. 모드 표시가 라디오 하나뿐이라 NN/g 기준(시각 신호 2개 이상)에 못 미친다.

### B-3. 적용 설계안(추천 순)

**1순위. 첫 화면 두 카드 + 모드별 별도 페이지 묶음 + 이중 표시**
- 첫 화면(`st.navigation(position="hidden")`인 시작 페이지): 큰 카드 두 개.
  - "시연 투어 — 3장면, 약 5분, 다음 버튼으로 진행" (처음 오신 분께 권장 표시)
  - "운영 화면(합성 병원) — 역할을 골라 직접 써 보기"
  - 두 카드 아래 고정 문구: "모든 데이터는 합성입니다. 실제 환자·병원 정보가 아닙니다."
- 카드를 누르면 `st.session_state["mode"]`를 정하고, `st.navigation`에 **그 모드의 페이지만** 넘긴다(시연 모드에는 장면 페이지, 운영 모드에는 역할 페이지). 두 모드의 버튼이 같은 화면에 섞이지 않아 모드 오류 여지가 줄어든다.
- 모드 표시 두 가지 이상(NN/g): ① 상단 띠 색과 글(시연: 보라 띠 "시연 투어 · 대본 진행 중 · 3장면 중 2", 운영: 중립 회색 띠 "운영 화면 · 합성 병원 #0 · 원무") ② 시연 모드에서만 화면 모서리 "시연" 꼬리표와 옅은 배경색. 색은 기존 `ui/theme.py` 토큰(보라 #5B32D6 등)을 쓰고 글로도 적어 색맹 사용자도 구분.
- 전환은 상단 띠의 "처음 화면으로" 한 곳에서만, `@st.dialog`로 "시연을 끝내고 운영 화면으로 갑니다. 시연 진행은 저장되지 않습니다" 한 번 확인(확인은 이 전환에만, NN/g "드물게").
- 역할 선택: 운영 카드 안에서 역할 카드(원무·병동·감염관리실·관리자·감사·공급사)를 고른다. 로그인은 데모 범위 밖이므로 "역할 선택(로그인 아님, 데모)"으로 표기(DECISIONS의 "사람 신원 인증은 범위 밖"과 일치).
- 장점: 의료 관행(환경 분리)에 가장 가깝고, NN/g 모드 지침 충족, 현재 코드(장면·역할 렌더 함수)를 그대로 재사용. 단점: 시작 화면 한 장과 페이지 분리 작업이 필요, 시연 중 운영 화면을 곁눈질하려면 처음 화면을 거쳐야 함.

**2순위. 운영 화면 하나 + 사용자 주도 "투어 체크리스트" 겹치기**
- 첫 화면은 곧장 운영 화면(합성 병원). 오른쪽 위 "시연 투어 시작" 버튼을 누르면 사이드바에 진행 체크리스트(장면 1~3, 단계마다 "이 화면에서 볼 것")가 붙고, 투어가 운영 화면 위에서 진행된다. 투어는 언제든 다시 열 수 있다(NN/g 2023 ArcGIS 예).
- 투어가 바꾼 상태는 따로 만든 합성 병원 사본(seed 고정)에서만 돌고, 투어 종료 시 버린다(Epic 연습 환경의 "밤마다 초기화"와 같은 발상).
- 장점: 실제 화면에서 배우므로 기억에 남음(NN/g 맥락 안 학습). 단점: 한 화면에 두 상태가 겹쳐 모드 오류 위험이 1순위보다 큼, 현재 장면 대본(시험 입력을 넣어 게이트웨이 거부를 보여 주는 장면 2 등)을 운영 화면 상태와 맞추는 작업이 큼.

**3순위. 앱을 두 개로 분리(별도 주소 또는 별도 실행)**
- `streamlit run ui/demo_app.py`(시연)와 `ui/ops_app.py`(운영)를 따로 띄우고, 첫 화면은 두 링크만 있는 안내 페이지. 시연 앱은 고정 seed, 종료 시 초기화.
- 장점: 의료 현장 관행(별도 인스턴스)과 같고 섞일 여지가 가장 적음. 단점: 배포·유지가 두 배, 방문자가 두 앱을 오가기 불편, 1인 데모 프로젝트엔 과함(A절 "단순하게 시작"과 충돌).

공통 체크리스트(어느 안이든):
1. 모든 화면 상단에 모드 이름(글) + 색 띠, 시연에는 꼬리표까지 두 개 이상의 신호.
2. "합성 데이터 · 실제 환자 아님" 고정 표시, 가명 환자 표기 유지.
3. 시연 모드에서는 결과 수치 옆에 "대본 장면 값(합성 기준 추정)"을 붙여 운영 화면 지표와 혼동 방지(CLAUDE.md 6번).
4. 투어는 건너뛰기·다시 열기 가능, 진행 표시(3장면 중 몇 번째).
5. 모드 전환은 한 곳, 확인 대화상자는 그 한 번만.
6. 화면 시험: 시연 페이지 목록에 운영 승인 버튼이 없고, 운영 페이지 목록에 "다음 단계" 대본 버튼이 없음을 시험으로 고정.

## 열지 못했거나 근거로 쓰지 않은 자료

- Google(Julia Wiesinger, Patrick Marlow, Vladimir Vuskovic) "Agents" 백서(2024-09, Kaggle `https://www.kaggle.com/whitepaper-agents`): 페이지가 스크립트로만 그려져 본문을 받지 못했다. 본문 근거로 쓰지 않음.
- AWS Prescriptive Guidance "Agentic AI patterns and workflows on AWS"(Aaron Sempf, Andrew Hooker, https://docs.aws.amazon.com/prescriptive-guidance/latest/agentic-ai-patterns/introduction.html): 소개 쪽만 열었고 구체 주장(사람 승인·평가)은 확인하지 않아 표에서 뺐다.
- EMR 교육 환경의 색·배너 구분 관행: 공급사 문서를 찾지 못함(위 "설계 가정" 참고). 검색에 나온 Ideagen 커뮤니티 글은 의료 EMR이 아니고 본문 대부분이 로그인 뒤라 쓰지 않았다.
- LangChain "human-in-the-loop" 블로그 글 개별 글은 찾지 않았고 LangGraph 공식 문서(interrupts)로 대신했다.
