## 1. 점수와 총평

**4 / 10**

총평: 이벤트 흐름(퇴원 → 청소 두 갈래 → 배정 → 올려주세요 → 입실)이 끝까지 이어진다는 것은 보였다. 하지만 이 합성 병원에는 재원 환자(병상 점유)가 없다. 그래서 입실 구간 지표는 가정한 상수 15분을 그대로 돌려줄 뿐이고, 새 퇴원 단계는 퇴실 시각에서 거꾸로 계산한 장식이라 원인 역할을 하지 않는다. 지금 측정으로는 "사이클이 돈다"는 것만 말할 수 있고, "입실 대기가 짧다"거나 "에이전트가 효과를 냈다"는 말은 할 수 없다.

  - 반응형 재생(`reactive.py:91-96`)은 새 단계를 오더 재촉 이동량만큼 옮기고 퇴실 시각으로 자른다. 라운지로 퇴실이 당겨진 1,339건 중 **938건(70%)**은 영수증 확인과 약 전달이 새 퇴실 시각 한 점으로 겹친다. "약을 받고 퇴실"하는 순서가 "퇴실하는 순간 동시에"로 무너진다.
  - 앞으로 생길 문제: `184dc48`이 심사·퇴원약·수납 단계 정체 감지를 추가했다. 그런데 `reactive.py:144-145`는 모든 `remind_owner`를 처방 재촉 하나로 해석하고, `retime`은 오더가 재촉보다 늦을 때만 움직인다(54줄). 그래서 오더 뒤 단계에 대한 재촉은 구조적으로 효과가 0이다. 이 구조로 재면 E6 이후 행동 효과는 늘 0으로 나온다.
- 고칠 방법
  - 단계를 앞에서 뒤로 생성한다: 오더 → (심사 ∥ 조제) → 수납 안내 → 수납 → 영수증 → 약 전달·교육 → (보호자 도착과 합류) → 퇴실.
  - 퇴실 = `max(약 전달, 교육, 보호자) + exit_prep`로 둔다. 그다음 국내 QI 분포에 맞도록 단계 분포 모수를 보정한다(퇴실을 고정하고 역산하지 않는다).
  - `retime`도 같은 DAG로 다시 계산해서, 단계별 재촉 레버(`step=` 값별)가 그 뒤 단계로 전파되게 한다.
  - 보정 후 12시 이전 퇴실이 42~60% 안에 드는지 다시 확인한다.

### [중간] P6. "현실 프리셋 전용" 난수열이 시드와 무관하다. 시드 사이가 독립 반복이 아니다
- 근거

- 재현(`e1b.py`)
  - 1번 퇴원의 (심사 완료 − 오더)가 30시드 모두 48분이다.
  - 정규 퇴원의 오더 시각 열이 시드 0, 1, 2에서 똑같다(433, 420, 423, 460, 432분…).
  - 라운지 동의 여부도 사례 번호별로 모든 시드에서 같다.
- 영향(`e8.py`, 200시드, 시드를 섞도록 고친 사본과 비교): 12시 이전 퇴실 평균은 52.7% → 51.6%, 시드별 SD는 0.101 → 0.095다. 머리 수치에 주는 영향은 작다. 문제는 해석 쪽이다. 정규 퇴원 시각, 단계 간격, 라운지 동의 같은 성분은 30시드가 아니라 사실상 1개 표본이다. 신뢰구간이나 "모든 시드에서 같다" 같은 주장은 이 성분에 대해서는 의미가 없다.
- 고칠 방법: `Random(f"seq-{seed}-...")`처럼 시드를 넣는다. 기존 값 불변이 목적이면 시험 구성에는 손대지 않고 현실 구성에서만 시드를 넣으면 된다(현실 구성은 이번에 새로 만든 것이라 지킬 과거 값이 없다). 공통 난수(같은 시드 안에서 끔/켬 짝짓기)는 그대로 유지한다.

### [중간] P7. "수속부터 입실까지 평균 15분이 모든 시드에서 같다"는 가정값과 이산화 간격을 다시 읽은 것이다
- 근거: `demo.py:91` `_ARRIVE_AFTER = 15`, 재생 간격 `step_min = 15`, 수속 시각은 30분 단위(`generator.py:311`). 병상과 병동 준비가 수속 전에 끝나면, 입실 대기는 항상 `max(가정 이동 시간, 재생 간격)`의 배수가 된다.
- 재현(`e10.py`): 이동 시간을 10분으로 바꿔도 step 15에서는 결과가 15분이다. step을 5로 줄이면 10분이 된다. 원래 설정에서 step 5로 돌려도 15분이다. 이 지표에는 시스템 성능 정보가 없다.
- 고칠 방법
  - 입실 대기를 "수속 → 올려주세요"(시스템이 만든 대기)와 "올려주세요 → 입실"(가정된 이송)로 나눠 보고한다.
  - 이송 시간에 분포를 주거나, 아예 범위 밖이라 지표에서 뺀다.
  - 재생은 이벤트 구동(다음 사건 시각으로 점프)으로 바꾸거나, 결과에 "15분 간격 이산화"를 표기한다.

### [중간] P8. 흐름 지표(`evaluation/flow.py`)의 분모와 정의가 좋은 결과 쪽으로 치우친다

## 3. 측정을 믿을 수 있게 하려면 필요한 추가 실험

1. **점유가 있는 병원으로 다시 측정(P1·P2 해결 뒤)**
   - 시작 점유율을 80%, 90%, 95%(설계 가정 격자)로 두고 시드 50 × 여러 날을 돌린다.
   - 볼 것: 입실 대기, 병상 없음 비율, 같은 날 퇴원 병상 사용 비율.
   - 기대: 점유율이 오르면 입실 대기가 15분에서 벗어나 퇴원·청소 단계에 민감해진다. 이 기대가 맞지 않으면 모형이 여전히 둔감하다는 뜻이다.
2. **지표 변별력 시험(양성 대조)**
   - 청소 응답 중앙값을 +60분 늘리거나, 오전 수속 비중을 15%에서 50%로 올리는 식으로 "나쁜 조건"을 일부러 넣는다.
