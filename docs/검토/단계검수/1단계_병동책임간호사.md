## 1. 점수와 총평

**5 / 10**

> 퇴원 당일 단계 이름과 순서, 청소 두 갈래, "올려주세요"라는 틀은 현장 말과 맞게 잡았다. 그러나 시각을 만드는 방식이 순서만 지키고 실제 간격은 따르지 않아 "수납 안내 뒤 두 시간 뒤 수납" 같은 장면이 흔하고, 1단계 확인 재생에서는 퇴원한 병상에 다음 환자가 들어가는 장면이 한 번도 없다. 그래서 "전 구간 재생"이라고 부르기 어렵다. 그 장면이 없어서 가려진 안전 결함도 하나 있다(같은 병상의 옛 퇴원 기록을 보고 "올려주세요"를 낸다).

좋은 점(짧게):
- 단계 이름(심사 완료, 수납 안내, 영수증 확인, 퇴원약 전달)이 병동에서 실제로 쓰는 말이고, 원문 근거(서울아산 "진료비 최종심사가 끝나면 간호사가 환자분께 연락", 일산병원 "퇴원비 수납 후 간호사실에서 퇴원약 … 설명")와 큰 틀이 맞다.
- 격리 퇴실은 종말소독이 끝난 뒤에만 병원 직원 침상 정리를 부르는 순서(H34)가 맞다.
- "올려주세요"를 배정 확정과 다른 사건으로 나눈 것, 이송 인력 배정을 범위 밖에 둔 것이 맞다.
- 퇴실 시각 분포를 건드리지 않으려고 별도 난수열을 쓴 것은 비교 가능성을 지키는 좋은 선택이다.

## 2. 문제 목록

### 높음

#### H-1. 1단계 확인 재생에서 "퇴원한 병상 → 다음 환자 입실"이 0건이다
- 근거: `docs/RESULTS.md` 2026-11-10 절("그날 입원 19건 모두 … 입실까지", "수속부터 입실까지 평균 15분"), `src/turnaround/ui/demo.py:39-89`(build_demo)
- 직접 확인: 현장 프로필, 시드 0~7, 4일차 재생에서 "올려주세요" 19건이 모두 **그날 퇴원이 없는 빈 병상**으로 갔다. 그날 퇴원 병상(시드마다 3개)으로 간 것은 **0건**. 19건 모두 08:00~09:00에 이미 빈 병상에 확정됐다.
- 왜 문제인가: 이 프로젝트의 본론은 "퇴원 확정 → 퇴실 → 청소 두 갈래 → 입실 가능 → 다음 환자 입실"이다. 1단계의 새 기능(청소 두 갈래, 병실 종류별 입실 가능 기준, 퇴실 전 병상 배정)이 실제 입원 한 건도 막거나 풀어 주지 않았다. RESULTS의 "평균 15분"은 가정한 이동 시간(`_ARRIVE_AFTER = 15`)을 그대로 돌려받은 값이라 측정이 아니다. 병동 사람이 보면 "퇴원 자리에 새 환자 받는 장면이 없는데 사이클 완성이라고?"라고 묻는다.
- 현장: 내과 병동은 빈 병상이 아침부터 남아 있는 날이 드물다. 그날 입원은 대개 그날 퇴원 자리로 들어가고, 입실이 14시 이후에 몰리는 것도 그 때문이다(해운대백 QI: 퇴실 11~13시, 입원수속 15~17시 최다. 한국의료QA학회지 14(2) 2008: 입실 71.3%가 14시 이후. 출처는 `docs/검토/현장조사/병동간호_실무.md` 79~80줄, https://www.qihjournal.org/ 원문 인용).
- 고칠 방법: 1단계 확인 지표에 "그날 퇴원 병상으로 들어간 입원 수"를 넣고, 그것이 0이면 1단계 끝난 기준을 못 채운 것으로 본다. 빈 병상을 줄인 날(재원율을 높인 초기 상태)과 오전 수속 비중을 높인 날을 1단계에서 바로 돌린다(지금은 5단계로 미룸). 입실 대기 지표는 "입실 가능(두 갈래 끝) → 입실"과 "수속 → 입실"을 따로 내고, 가정 값을 그대로 돌려받는 지표는 RESULTS에 "가정값"으로 적는다.

#### H-2. "올려주세요"가 같은 병상의 **옛 퇴원 기록**을 보고 나간다(이전 환자가 아직 누워 있어도)
- 근거: `src/turnaround/saga/machine.py:449-451`
  ```python
  d = next((x for x in s.discharges.values() if x.bed_id == m.bed_id), None)
  bed_ok = d is None or d.seen(EventType.BED_MARKED_VACANT) or d.seen(EventType.BED_READY)
  ```
  병상의 **첫 번째** 퇴원 사례를 고른다. 같은 병상은 10일 동안 여러 번 퇴원한다(현실 프리셋 시드 0~7 모두 2~5회 반복 병상 있음, 예: 시드 2의 W72-R01-B1 5회).
- 재현: 전날 D0가 퇴실·청소·침상 정리·입실 가능까지 끝난 병상에, 오늘 D1이 퇴원 예정으로 아직 퇴실 전이다. A1(수속 14:00)을 이 병상에 확정하고 병동 준비를 넣은 뒤 14:05에 사가를 돌리면 `PATIENT_CALL_UP`이 14:00으로 나간다. D1은 퇴실도 안 했다.
- 현장: 이전 환자가 침상에 있는데 원무에 "올려주세요"가 가면 환자가 복도에서 기다리거나, 더 나쁘게는 청소·소독 전 침상에 눕는다. 격리 퇴실 병상이면 종말소독 전 입실이 된다. 병동 책임간호사가 가장 먼저 막는 장면이다.
- 왜 지금까지 안 보였나: H-1 때문에 확인 재생에서 퇴원 병상으로 들어간 입원이 없었다. 기존 시험(`tests/test_stage1_cycle.py:124`)도 병상당 퇴원 한 건만 쓴다.
- 고칠 방법: 그 매칭이 기다리는 "현재" 퇴원 사례(취소 안 된, 확정 시점 이후 또는 아직 입실 가능이 안 된 가장 최근 사례)를 고르는 결정적 함수로 바꾼다. `_bed_discharge`(machine.py 191줄)도 같은 "첫 번째 사례" 방식이라 함께 본다. 회귀 시험: 같은 병상에 지난 퇴원(끝남)과 오늘 퇴원(퇴실 전·청소 중·격리 소독 중) 세 경우에서 "올려주세요"가 나가지 않는지. 실행 안전 지표(S1·S2)에 "이전 환자 퇴실 전·입실 가능 전 올려주세요"를 넣는다.

#### H-3. 수납이 퇴원약 병동 도착을 기다린다: "심사·조제 병행"이 이름뿐이고, 수납 안내 뒤 수납까지 중앙 111분
- 근거: `src/turnaround/sim/generator.py:214`(`billing = med + m(d["billing"])`), 227~229줄(심사 완료를 `billing - 6분` 안쪽으로 끼워 넣고 수납 안내 = 심사 + 5분)
- 직접 확인(현실 프리셋 시드 0~7, 정상 퇴원 216건):
  | 간격 | 중앙 | P90 | 최대 |
  |---|---|---|---|
  | 오더 → 심사 완료 | 39분 | 55분 | 60분 |
  | 심사 완료 → 수납 안내 | 5분 | 5분 | 5분 |
  | **수납 안내 → 수납** | **111분** | **180분** | **302분** |
  | 퇴원약 병동 도착 → 수납 | 28.5분 | 72분 | 269분 |
- 왜 문제인가: 수납 시각은 여전히 옛 직렬 모형(약 도착 → 심사·수납)에서 나오고, 새 단계는 그 사이에 끼워 넣은 장식이다. 심사가 늘 오더 뒤 1시간 안에 끝나고, 환자는 안내를 받고 두세 시간 뒤에 수납한다. 현장에서 "계산 나왔어요" 안내를 받은 환자·보호자는 대개 바로 내려가 수납하거나 모바일·무인 수납을 한다. 수납을 막는 것은 약 도착이 아니라 **심사 완료**(그리고 처방 확정)다.
  - 이 저장소의 분포 주석도 같은 말을 한다: `src/turnaround/sim/distributions.py:27` "인천성모 심사 29 + 연락 6 + 수납 9". 즉 안내 → 수납은 약 10분 수준이다.
  - 서울아산(1차, `docs/검토/스펙현실검증.md` 94줄 인용): "퇴원일 09:00 ~ 11:00 경에 진료비 최종심사가 끝나면 간호사가 환자분께 연락을 드립니다." https://amc.seoul.kr/asan/hospitalizationtreatguide/hospitalizationTreatGuide.do
  - 충북대(1차, `병동간호_실무.md` 118줄): "진료비심사가 완료되면 퇴원창구에서 병실로 … 전화(보통 10시∼13시)", "장기환자의 경우는 진료비심사 시간이 길어지므로 퇴원시간이 지연". https://www.cbnuh.or.kr/main/sub01_06_01.do → 심사 시간은 재원 기간에 따라 길어지는데 모형은 고정 20~60분이다.
- 고칠 방법: 의존 관계를 바꾼다. 심사 완료 = max(오더(처방 확정) + 심사 소요, 처방 수정 시 재심사), 수납 안내 = 심사 완료 + 연락(수 분), 수납 = 안내 + 수납 소요(보호자·환자가 수납할 수 있는 시각 이후), 퇴원약 전달 = max(약 병동 도착, 영수증 확인). 퇴실 시각 분포를 지키려면 퇴실에서 거꾸로 맞추는 대신, 국내 QI 퇴실 분포를 **결과 검증 대상**으로 두고 단계 분포를 보정한다. 심사 소요는 재원일수에 따라 늘게 한다(설계 가정으로 표시).

#### H-4. 처방 수정의 61%가 심사 완료 **뒤**에 나는데 재심사가 없다
- 근거: `generator.py:209`(수정 = 처방 발행 + 15~60분), 227줄(심사 완료 = 오더 + 20~60분). 둘이 서로를 모른다.
- 직접 확인: 처방 수정 31건 중 19건이 심사 완료 시각 뒤에 수정됐다. 그런데 심사 완료·수납 안내 시각은 그대로다.
- 현장: 퇴원약이 바뀌면 약값이 바뀌고 원무 퇴원 계산을 다시 한다(재심사·재계산, 이미 냈으면 추가 수납이나 환불). 병동은 "처방 바뀌었으니 계산 다시 해 주세요"를 원무에 전화한다. 서울성모 퇴원처방 수정률 15~16% → 9% 개선 사례(2차, 데일리팜, `스펙현실검증.md` 96줄)가 있을 만큼 흔한 일이라, 수정 뒤 계산이 그대로인 모형은 현장 사람 눈에 바로 걸린다.
- 고칠 방법: 심사 완료 ≥ 마지막 처방 확정(수정 포함) + 심사 소요로 묶고, 수납 뒤 수정이면 "재계산" 사건을 넣거나 최소한 수납을 수정 뒤로 민다. 시험: `test_field_discharge_sequence_order`에 `rx_revised_at <= billing_review_done_at`(또는 재심사 사건 존재)을 더한다.

### 중간

#### M-1. 영수증 확인·퇴원약 전달이 "수납 → 퇴실 사이를 셋으로 나눈 자리"에 놓인다
- 근거: `generator.py:230-234`(`tail // 3`씩 띄움)
- 직접 확인: 수납 → 영수증 확인 중앙 12분, P90 56분, 최대 201분. 영수증 확인 → 약 전달, 약 전달 → 퇴실도 같은 분포(최대 201~203분).
- 현장: 영수증을 들고 간호사실에 오는 것은 수납 직후(수 분~20분)다. 그다음 약 전달·교육(10~20분), 말초정맥관 제거·팔찌 제거, 퇴실까지 짧게 이어진다. 보호자를 기다리는 시간은 이 사이에 고르게 퍼지지 않고, **수납 전**이나 **약 전달 전**(교육 받을 보호자를 기다림) 한곳에 몰린다. 일산병원(원문, `병동간호_실무.md` 120줄): "퇴원비 수납 후 간호사실에서 퇴원약, 퇴원 후 주의사항, 외래 예약일 등에 대해 설명" https://blog.naver.com/hello_health/221296932949 (병원 공식 블로그)
- 고칠 방법: 각 간격을 자기 분포(설계 가정)로 뽑고, 기다림이 생기는 지점을 "보호자 도착 대기" 사유로 명시한다.

#### M-2. 보호자가 오기 전에 수납·교육이 끝나는 퇴원이 절반 가깝다
- 근거: `generator.py:214-215, 230-234`. 수납·약 전달이 보호자 도착과 무관하게 계산된다.
- 직접 확인: 216건 중 보호자 도착 전 수납 114건(53%), 보호자 도착 전 퇴원약 전달·교육 87건(40%).

#### M-6. 병동 준비(투약 티켓·네임카드·침상)가 배정 통보 30분 뒤 무조건 끝난다

- 현장: 차팅 간호사가 기록·처방을 확인하고 "투약티켓, 네임카드, 침상정리 등을 하고" 환자를 올려 받는다(간호사 블로그 원문, `병동간호_실무.md` 66줄, https://m.blog.naver.com/100110000/221815419405). 네임카드(침상 명패)와 침상 준비는 **이전 환자가 나가고 침상이 정리된 뒤**에야 할 수 있다. 입원 처방(입원 오더)이 나와야 투약 준비도 된다. 그래서 병동 준비는 "배정 통보"가 아니라 "입실 가능 + 입원 연락(수속 임박)"에 묶여 있다.
- 고칠 방법: 병동 준비를 (a) 사전 확인(기록·처방 확인, 배정 통보 뒤 가능)과 (b) 침상 측 준비(네임카드·침상, 입실 가능 뒤에만)로 나누거나, 최소한 사람 흉내를 `max(통보, 입실 가능) + 준비 소요`로 바꾼다. H-1을 고쳐 퇴원 병상 입실이 생기면 이 문제가 바로 드러난다.

## 4. 우선순위 제안(병동 관점)

1. H-2(옛 퇴원 기록으로 "올려주세요") 즉시 수정과 회귀 시험. 안전 문제다.
2. H-1을 1단계 끝난 기준으로 되돌림: 퇴원 병상 입실이 있는 재생을 1단계에서 측정.
3. H-3·H-4: 퇴원 당일 의존 관계를 "심사 완료가 수납을 연다, 처방 수정이 심사를 다시 연다"로 바꿈.
4. M-4·M-6: 침상 정리 두 사건 분리, 병동 준비 기준점을 입실 가능 뒤로.
5. 나머지는 2단계 이후 설정 항목으로.
