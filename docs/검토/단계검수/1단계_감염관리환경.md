## (1) 점수와 총평

**5 / 10**

> 종말소독 상향·환기 대기·아포 소독 표시·게이트웨이의 종말소독 완료 확인 등 뼈대는 맞지만, 새로 넣은 "두 갈래" 흐름에서 **청소와 침상 정리의 순서 제약이 없고, `BED_READY` 하나로 두 갈래 요구가 우회되며, 늦은 격리에서는 종말소독 전 침상 정리가 그대로 인정된다.** 실행 안전 지표 S2는 이 새 경로를 하나도 검사하지 않는다.

## (2) 문제 목록

### 높음

#### P1. 일반 퇴실에서 "신환 침상 준비"가 표면·침상 청소보다 먼저 끝나도 된다 (교차 오염 순서)
- 근거: `src/turnaround/sim/generator.py:237` `prep_from = clean_done if TERMINAL else departed` → 일반 청소는 침상 정리가 퇴실 시각부터 미화 청소와 무관하게 시작한다. `src/turnaround/saga/machine.py:610` 사가도 일반 퇴실은 퇴실 즉시 침상 정리를 요청하고, `:615` 입실 가능은 `max(prep_done, clean_done)`만 본다(두 완료의 **선후**는 보지 않음). `src/turnaround/sim/distributions.py:31` `cleaning_bed_unit`은 "침대·주변 표면·커튼"으로 미화 갈래에 붙어 있다.
- 측정(현실 프리셋 30시드, 일반 청소 810건): 침상 정리 **완료**가 미화 청소 **시작** 전인 경우 다인실 511/679(75%), 1인실 70/93, 음압실 30/38. 두 작업이 겹치는 경우 다인실 138건. 즉 대부분의 사례에서 새 리넨을 깐 침대 위·옆을 그 뒤에 미화가 닦고 바닥을 민다.
- 지침·현장: 권고안 부록 4-3-2는 린넨 제거(4) → 표면(5) → 침대·매트리스(6) → 욕실(7) → 바닥(8) 뒤 **마지막에 침대 재설치(11)** 순서다. 저장소의 정답 세트 XD-019 근거 문장도 "소독 완료 전에 신환 침상 준비를 하면 새 리넨이 오염된다"고 쓴다. 이 원칙은 격리 퇴실만이 아니라 일반 퇴실에도 같다. 또 DECISIONS의 역할 분담(병원 직원: 침대·매트리스 정리, 미화: 벽·바닥·화장실)과 생성기 분포(미화 갈래 = 침대·주변 표면)가 **매트리스·난간·오버베드 테이블을 누가 소독하는지** 서로 어긋난다.
- 고칠 방법: 침상 정리를 두 하위 단계로 나눈다. `BED_STRIP`(린넨·커튼 제거, 의료기구 회수: 퇴실 직후, 미화 전 가능) → 미화/침상 단위 소독 → `BED_MAKE`(새 리넨·비품 보충: **청소 완료 뒤에만**). 입실 가능 조건을 `bed_make_done ≥ cleaning_done`로 두고, 앞선 `BED_MAKE`는 사람 확인 작업(재정리)으로 돌린다. 매트리스·침대 프레임 소독의 담당 갈래를 병원 설정(`cleaning.bed_disinfection_by: staff|housekeeping`)으로 명시한다. E4의 `request_bed_prep_first`도 일반 퇴실에서는 "벗기기만 먼저"로 범위를 줄인다.

#### P2. 늦은 격리(퇴실 뒤 격리 오더)에서 종말소독 전에 한 침상 정리가 그대로 인정된다 (H34 우회)
- 근거: `src/turnaround/saga/machine.py:610-613` 침상 정리 요청은 명령 키 `bed_prep_request` 하나라, 퇴실 때(격리 모름) `after_terminal=False`로 한 번 나가면 격리 오더가 와도 다시 나가지 않는다. `:614-615` `prep_done`이 종말소독 완료(`done`) **뒤인지 검사하지 않는다**. 종말소독 상향(`:576`)과 빈 병상 되돌림은 있으나 침상 정리 되돌림·재요청은 없다.
- 재현(다인실 W72-R04-B2, 커밋 기준 로직): 10:00 퇴실 → 10:00 침상 정리 요청(`after_terminal: False`) → 10:30 침상 정리 완료 → 10:40 VRE 격리 오더 → 10:40 종말소독 상향 요청 → 12:30 종말소독 완료 → **12:30 빈 병상 전환**. 종말소독 전에 깐 리넨·비품이 그대로 다음 환자에게 간다. 격리 퇴실이 처음부터 알려진 경우에도 직원이 요청 전에 정리를 해 버리면(`BED_PREP_DONE`이 소독 완료보다 앞) 같은 결과다.
- 지침·현장: 권고안 부록 4-3-2 C. difficile·VRE 격리실 추가 항목(사용 물품 전부 제거·교체), 표준예방지침 부록1 2-2)② 접촉주의 격리실 "커튼은 환자 퇴실 후 교환". 현장에서 늦은 양성 통보 뒤에는 이미 깐 리넨·커튼까지 걷어내고 종말소독을 다시 하는 것이 통상이다.
- 고칠 방법: 종말소독 상향 시 `BED_PREP_REVOKED`(또는 `bed_prep_request:after_terminal` 새 키)로 침상 정리를 **다시 요청**하고, 입실 가능은 "종말소독 완료 뒤의 침상 정리 완료"만 센다(`prep_done = first(BED_PREP_DONE ≥ done)`). 침상 정리 완료가 종말소독 완료보다 앞서면 사람 작업(`reason=bed_prep_before_terminal`)을 연다. 회귀 시나리오(늦은 격리 + 두 갈래)를 홀드아웃에 추가한다.

#### P3. 사람의 `BED_READY` 신호 하나로 두 갈래 요구가 통째로 우회된다
- 근거: `src/turnaround/saga/machine.py:581` `ready = d.seen(EventType.BED_READY)` → `:615`의 두 갈래 계산은 `ready is None`일 때만 돈다. `BED_READY`가 있으면 `:617-619`에서 침상 정리 완료 없이 빈 병상 전환. `src/turnaround/agent/tools.py:122`도 `BED_READY`만 있으면 병상을 지금 쓸 수 있다고 본다.
- 재현: 일반 퇴실, 10:30 미화 `CLEANING_DONE`, 10:35 `BED_READY`, `BED_PREP_DONE` 없음 → 10:35 `BED_MARKED_VACANT`. 리플레이는 `bed_ready_at = max(두 완료)`로 신호를 만들어 이 구멍을 가린다(`src/turnaround/events/replay.py:120-122`). 실제 연동(FHIR·미화 앱 "청소 완료=준비 완료")에서는 미화 쪽 완료가 곧 `BED_READY`로 들어오는 일이 흔하다.
- 지침·현장: 사용 린넨이 남은 침대가 "입실 가능"으로 원무·병동에 뜨는 것은 감염과 환자 경험 모두에서 사고다. DECISIONS "두 쪽이 끝나야 입실 가능"을 코드가 강제하지 못한다.
- 고칠 방법: `cleaning_split`이 켜지면 `BED_READY`를 입실 가능의 충분조건이 아니라 하나의 입력으로만 쓰고, 빈 병상 전환은 항상 `CLEANING_DONE`(범위에 맞는)과 `BED_PREP_DONE`(P1의 `BED_MAKE`) 둘을 요구한다. 둘 중 하나가 빠진 `BED_READY`는 사람 확인 작업으로 돌린다. 계획 도구의 준비 판단도 같은 함수로 통일한다.

#### P4. 사가는 격리 퇴실에서 청소 "종류"를 보지 않고 아무 완료 신호나 종말소독 완료로 센다. S2도 같다
- 근거: `src/turnaround/saga/machine.py:304`는 모든 `CLEANING_DONE`을 `cleaning_dones`에 넣고, `:594`는 종류와 상관없이 종말소독 요청 뒤 첫 완료를 쓴다. `src/turnaround/evaluation/safety_exec.py:80-81`도 `cleaning_type`을 검사하지 않는다. 반면 게이트웨이 `src/turnaround/gateway/gateway.py:283-284`는 `cleaning_type == "terminal"`을 요구한다(그러나 "그 사례에서 한 번이라도"이며 종말소독 요청 뒤인지는 보지 않음).
- 재현: VRE 격리 퇴실(처음부터 알려짐), `CLEANING_DONE(cleaning_type="general")` + `BED_PREP_DONE` → 11:20 빈 병상 전환. 게이트웨이가 확정은 막지만, 병동·원무 화면과 계획 도구에는 입실 가능으로 보이고 S2는 위반으로 세지 않는다.
- 지침·현장: 미화 앱에서 일반/종말 버튼을 잘못 누르는 일은 실제로 자주 있다. 감염관리실은 "격리실 종말소독 완료" 확인을 일반 완료와 분리해 받는다.
- 고칠 방법: 사가·S2·게이트웨이가 같은 판정 함수 `terminal_done_after(request)`를 쓴다(종류 = terminal, 시각 ≥ 마지막 종말소독 요청). 종류가 다른 완료가 오면 사람 작업(`reason=cleaning_type_mismatch`)을 연다. C. difficile은 완료 신호에 아포 소독제 사용 여부(`sporicidal_done`)까지 받는다(아래 P8).

#### P5. 실행 안전 지표 S2가 새 흐름(두 갈래·침상 정리 순서)을 전혀 검사하지 않는다
- 근거: `src/turnaround/evaluation/safety_exec.py:61-102`. 검사 항목은 마지막 청소 요청의 종류, 환기 대기, 비움 하한, 아포 표시, 빈 병상 전환·확정이 "완료 신호" 뒤인지뿐이다. `BED_PREP_REQUESTED`/`BED_PREP_DONE`은 한 번도 보지 않는다. 분모는 격리 퇴실만이라 일반 퇴실의 두 갈래 요구(P3)는 어떤 지표에도 없다. 합성 데이터에는 늦은 격리 + 두 갈래 경로가 없어(DECISIONS "퇴실 뒤 격리 오더의 청소 상향"도 같은 한계를 인정) P2가 0건으로 나온다. `tests/test_stage1_cycle.py`도 정상 경로 2개(일반·격리 처음부터)만 본다.
- 고칠 방법: S2에 (a) 침상 정리 요청 시각 ≥ 종말소독 완료, (b) 입실 가능에 쓰인 침상 정리 완료 ≥ 종말소독 완료, (c) 완료 신호 종류 = terminal을 더한다. 일반 퇴실에는 새 지표(S3 "입실 가능 조건 충족": 빈 병상 전환 시점에 두 갈래 완료, 침상 준비 ≥ 청소 완료)를 둔다. 하루 재생 합성 데이터에 늦은 격리(다인실 포함)와 잘못된 종류의 완료 신호, `BED_READY` 단독 신호를 일정 비율 넣어 분모를 만든다. 수정 전 코드에서 실패하는 테스트를 먼저 쓴다(P2·P3·P4 재현 시나리오 그대로).

### 중간

#### P6. 다인실 늦은 격리의 종말소독 범위가 정의되지 않았다 (같은 병실 환자, 공용 화장실)
- 근거: DECISIONS "입실 가능 기준의 청소 범위"는 격리 퇴실을 "병실 종류와 상관없이 그 병실 전체 종말소독"으로 적었다. 그러나 생성기는 격리 퇴실을 1인실·음압실에서만 만든다(`src/turnaround/sim/generator.py:62` `_ISOLATION_ROOMS`). 늦은 격리는 현실에서 **다인실에서 가장 흔히** 생기는데(입원 선별검사 결과 대기 중 일반 배정, DECISIONS "격리 정보 처리 정정"), 같은 병실에 다른 환자가 있으면 "병실 전체 종말소독"은 할 수 없다. 사가의 상향 요청(`machine.py:576`)에도 범위 필드가 없어 미화는 무엇을 해야 하는지 알 수 없다. `docs/검토/현장조사/감염관리_청소_실무.md`의 H06 메모도 같은 병실 다른 빈 병상 배정 가능 여부를 미결로 남겼다.
- 지침·현장: 권고안 부록 4-3-2 "침대 구역이 두 개 이상이면 각 침대 구역을 새 천으로 완료한 뒤 다음 침대로". CDI는 퇴원 뒤 "화장실, 좌변기 … 철저하게"(표준예방지침 CDI 장). 다인실 접촉주의 환자 퇴실 시 현장은 "그 침상 구역 종말소독 + 공용 화장실 소독(아포 대상이면 염소계) + 공용 장비"로 처리하고, 같은 병실 접촉자는 선별검사 대상이 된다.
- 고칠 방법: 종말소독 요청에 `scope: room | bed_area_plus_shared_toilet`을 넣고, 다인실 재원자가 있으면 후자로 낸다. CDI·CRE 등 병원이 정한 균은 공용 화장실 종말소독 완료 신호를 따로 요구한다. 같은 병실 다른 빈 병상의 배정 보류 여부는 병원 설정 + 현직자 확인 항목으로 둔다.

#### P7. 다인실 침상 단위 입실 가능의 전제(공용 화장실 정기 청소)가 시스템 어디에도 없다
- 근거: `config/profiles/field_default.yaml:21` `readiness_scope: {multi: bed_unit, ...}`는 `src/turnaround/gateway/profile.py:54-60`에 선언만 있고 **어떤 코드도 읽지 않는다**(`grep readiness_scope src` 결과 profile.py뿐). 범위 차이는 생성기 소요시간(`distributions.py:31`)으로만 표현되고, 완료 신호에 범위가 없어 사가는 침상 단위와 병실 전체를 구분하지 못한다.
- 지침·현장: 다인실 퇴원마다 공용 화장실까지 다시 하지 않는 것 자체는 현장과 맞고 지침과도 충돌하지 않는다. 단 권고안 표 4-3이 공용·공유 화장실을 **적어도 1일 2회**로 두므로, 그 정기 청소가 실제로 돌고 있다는 것이 전제다. 또 퇴실 환자가 설사·변실금, C. difficile 검사 대기, 눈에 보이는 오염이면 침상 단위로 끝내면 안 된다.
- 고칠 방법: `readiness_scope`를 실제로 읽어 완료 신호의 `scope`와 맞는지 검사한다(1인실에 `bed_unit` 완료가 오면 미충족). 다인실 침상 단위는 "공용 화장실 마지막 정기 청소 시각 ≤ 12시간" 같은 조건(병원 설정, 설계 가정)과 퇴실 환자 예외 조건(설사·변실금·검사 대기 → 공용 화장실 포함)을 둔다. 하지 못하면 최소한 설계 가정으로 화면에 표시한다.

#### P8. 청결도 확인(형광 마커·ATP)과 불합격 뒤 재청소·되돌림 경로가 없다
- 근거: `src/turnaround/events/models.py:106` `CLEANING_INSPECTED`("옵션")는 선언만 있고 생성기·사가·게이트웨이·S2 어디에서도 쓰지 않는다. DECISIONS와 설계 문서는 "청소 → 청결도 확인 → 불합격이면 재청소 → 추가 소독" 하위 단계를 적어 두었다.
- 지침·현장: 권고안 1.4.2.1 질 평가 절차 수립(IA), 1.4.2.2 형광 마크·ATP·환경배양 중 선택(IB). 대부분 병원은 일반 퇴실은 표본 감사로, 격리실(특히 CRE·CDI·VRE) 종말소독은 감염관리실 또는 환경관리 책임자 확인 뒤 사용 승인으로 운영한다. 확인이 사후에 불합격이면 이미 낸 입실 가능을 되돌릴 경로가 필요하다.
- 고칠 방법: 병원 설정 `cleaning.inspection: none | sample | required_for(isolation organisms)`. `required`이면 빈 병상 전환 조건에 `CLEANING_INSPECTED(result=pass)`를 더하고, `fail`이면 재청소 요청·빈 병상 되돌림·연락 전 매칭 해제(보상)를 낸다. C. difficile은 완료 신호에 아포 소독제 사용 기록을 받는다(지금은 요청에만 `sporicidal` 표시, `machine.py:566`).

#### P9. 커튼을 다인실 침상 단위 매 퇴원 항목으로 넣은 것은 지침·현장과 다르고, 격리 퇴실의 커튼 교체는 빠졌다
- 근거: DECISIONS·설계 문서의 다인실 침상 단위 "(침대·매트리스·침상 주변 표면, 리넨, 커튼)", `distributions.py:31` 주석.
- 지침·현장: 권고안 3.4.4.3 커튼은 **주기적** 교환, 눈에 보이는 오염 시 즉시. 일반 퇴원마다 교체하지 않는다(과업지시서의 "주기별 커튼 교체"와도 맞음). 반대로 표준예방지침 부록1 2-2)②는 접촉주의 격리실 커튼을 **퇴실 후 교환**으로 둔다. 지금 모델은 이 구분이 없다.
- 고칠 방법: 일반 퇴실은 "커튼 점검(오염 시 교체)", 격리 퇴실은 "커튼 제거·교체"를 종말소독 하위 항목으로 분리한다. 커튼 교체는 세탁 반출이 끼어 시간이 길어질 수 있으므로 격리 퇴실 소요시간 분포에 반영 여부를 설계 가정으로 적는다.

### 낮음

#### P10. 1인실 "화장실 포함 병실 전체"는 별도 단계 없이 기존 일반 청소 분포로만 표현된다

#### P11. 반응형 하루 재생에서 침상 정리 시각을 원래 값과 `min()`으로 묶어 종말소독보다 앞설 여지가 있다

#### P12. 늦은 격리 상향 때 이미 일반 청소를 한 미화 인력의 노출·보호구 안내가 없다
