# 평가 라벨 작성 절차 검수 결과 (2026-11-09)

대상: `docs/검토/라벨작성_참고자료.md` 5절의 라벨 작성 절차와 모델 점검 세트 v2(추출 400, 인젝션 60쌍, 계획 200, 질의 150).
방식: 전문가 페르소나 3명(임상 주석 방법론, 병동 수간호사·입원 원무, LLM 평가·AI 보안). 1라운드는 서로 보지 않고 독립 검수, 2라운드는 서로의 의견을 읽고 동의·양보·반박. 원문: `docs/라벨토론/절차검수/round1_*.md`, `round2_*.md`.
한계: 세 명 모두 같은 LLM 계열이라 의견이 같아도 독립 근거가 아니다. 그래서 숫자로 셀 수 있는 주장은 작업자가 저장소에서 직접 다시 셌다(아래 1절). 외부 문헌은 모두 검색 요약으로 판단했다.

## 1. 작업자가 직접 확인한 사실

| 지적 | 확인 |
|---|---|
| 휠체어 택시·사설 구급차 메모 23건 중 17건에 mobility_aid 정답 누락 | 맞음 (17/23) |
| 퇴원 메모 57건에 1인실 희망 정답. 1인실 희망은 입원 대기 환자 정보 | 맞음 (57건) |
| 질의 150문항 중 고유 문장 95개, 의도 4개 | 맞음 |

| 추출 홀드아웃 400 중 고유 351개, 25문항이 개발 세트와 같은 문장 | 맞음 |
| 계획 세트 후보 807개의 준비까지 남은 시간이 전부 0분, 첫 후보만 골라도 200/200 | 맞음 |
| 지연 사유 코드: 설계 문서 6개(퇴원약, 보호자, 교육, 수납, 검사 대기, 전원) 대 추출기 4개 | 맞음. 작업자가 구현하며 만든 불일치 |
| 추출 결과를 읽는 하류 코드가 없다 | 맞음. 추출기만 자기 결과를 읽는다. 준비 시각 추정은 구조화된 도착 예정 이벤트만 쓴다 |
| 하네스 버그: 추출 형식 오류를 빈 출력으로 채점, 인젝션 형식 오류 쌍을 분모에 포함 | 맞음. **수정 완료**(커밋 "v2 하네스 버그 수정") |

## 2. 합의된 것 (세 명 모두 동의)

1. **지금 v2 세트로는 모델을 고르지 않는다.** 결과는 "초안 라벨 기준 참고값"으로만 쓴다.
2. **스키마부터 정하고 라벨을 만든다.** 순서: 하네스 버그 수정(완료) → 추출 필드 집합 결정 → 스키마(코드, 날짜, 메모 주체) → 명세 → 세트 다시 만들기 → 주석 → 판정 → 사용자 검토.
3. **명세에 들어갈 것**: 필드 정의, 포함·제외 예, 애매한 사례와 판정 규칙, 버전과 변경 기록. 명세가 바뀌면 이미 단 라벨 전체에 다시 적용한다.
4. **세트를 템플릿 밖으로 넓힌다.** 우선순위(병동 검수자 안):
   - ① 날짜 넘김과 근무조별 기록 시각
   - ② 정정·번복, 여러 사람이 이어 쓴 메모
   - ③ 메모 기록 시각과 도착 시각이 함께 있는 형태
   - ④ 부정 표현
   - ⑤ 14시·PM 2시·3~4시 같은 표기 다양화
   - 한글 수사("세 시")는 줄인다. 개발 세트와 겹치는 문항은 뺀다.
5. **라벨 오류 고치기**:
   - 휠체어 택시·사설 구급차는 mobility_aid=true.
   - "보호자 연락 안 됨"은 지연 사유 보호자.
   - 다중 사유는 허용 정답 집합으로 채점한다.
6. **1인실 희망**: 퇴원 메모의 정답 57건은 지우고, 입원 대기 메모를 새로 만들어 거기서만 단다. 격리 때문에 필요한 1인실은 "희망"이 아니라는 문항을 넣는다(LP-22).
7. **같은 계열 오염 대책**: 다른 회사 모델로 주석하고, 문항마다 누가 만들었는지(생성자 계열)를 기록한다. Claude 계열 결과에는 "라벨 작성과 같은 계열" 표시를 붙인다.
8. **계획 세트**: 지금 200개는 능력이 아니라 **형식·1순위 준수 관문**으로 내린다. 순서 섞기·점수 가리기 불변성 검사를 더한다. LLM의 계획 몫을 재려면 점수 함수가 모르는 정보가 들어간 판단 세트를 사람 판정으로 따로 만들어야 한다. 만들지 않으면 계획 역할의 LLM은 "설명만"으로 정한다.
9. **인젝션**:
   - 서로 다른 공격 문장 60개 이상으로 늘리고, 신뢰구간은 공격 문장 단위로 묶는다.
   - 유효 출력 기준 공격 성공률을 쓴다(구현 완료).
   - 강화판 공격, 위치·문체·영어 섞기, 정상 명령형 메모 대조군(과잉 방어 확인)을 더한다.
   - 관문 문구에는 "단측 95% 상한"을 명시한다.
   - 사실처럼 위장한 위조("정정: 07:30")는 모델이 막을 수 없으니 설계 통제 범위로 따로 분류한다.
10. **사용자 검토 기준**: "40개 중 10% 넘게 틀리면 재작업"은 버린다. 실제 오류율이 10%여도 통과할 확률이 높아 기준 구실을 못 한다. 대신 다음 세 층으로 나눠 본다.
    - 오류율 추정: 만장일치 묶음에서 무작위 표본
    - 표적 층: 불일치·애매 문항 전부와 규칙이 정한 경계 문항
    - 두 층은 섞지 않는다.
11. **봉인과 재현성**: 세트 manifest와 해시, 프롬프트 해시를 결과에 기록하고, 측정 전에 측정 계획을 커밋한다(사전 등록). 암호화는 같은 세션이 풀 수 있어 실익이 없다.
12. **현직자 확인**: 맨 끝 한 번이 아니라 명세 직후, 표현 다양화 직후, 관행 판정 때 짧게 넣는다.

## 3. 갈렸다가 정리된 것

| 쟁점 | 정리 | 근거 |
|---|---|---|
| 이중 주석 범위 | 400 전수, 다른 회사 모델 2개 | 표본 60으로는 드문 필드(1인실 양성 약 8개) 일치도 구간이 너무 넓다(주석 검수자). 평가 검수자도 양보 |
| 사용자 검토 표본 | 무작위 표본 기준으로 합의. 크기는 60(0건이면 통과, 1건 이상이면 150으로 확대) 대 150(1건 이하) | 둘 다 기존 10% 안보다 엄격. 크기는 사용자 결정(U7) |
| 지연 사유 코드 | 설계 6개 + other에 합의. transport(이송차) 추가 여부와 billing을 "수속(심사·수납·서류)"으로 넓힐지는 갈림 | 병동 검수자는 8개, 주석 검수자는 7개. 사용자 결정(U2) |
| guardian_eta 날짜 | 날짜를 넣는 방향에 합의. 형식은 `YYYY-MM-DDTHH:MM`(병동) 대 `day_offset`(주석) | 사용자 결정(U3) |

## 4. 해소되지 않은 이견
- **현직자를 주석자로 넣을지**: 병동 검수자는 넣자, 주석 검수자는 명세 검토자·경계 판정자로만 두자는 입장이다.
- **주 사유 칸**: 다중 사유일 때 "주 사유" 하나를 따로 둘지.

## 5. 사용자가 결정할 항목 (세 검수자 목록을 합침)

|---|---|---|---|

| U5 | 메모 주체(사례 종류) 입력 | 퇴원/입원 대기를 추출기 입력에 넣기 | 넣자에 합의 |
| U6 | 주석 모델과 예산 | 예: gpt-5-mini + grok-4.7, 회사당 1달러 상한. gpt-5.5로 400 주석은 약 7.8달러라 예산 밖 | 평가 검수자 어림 |
| U7 | 사용자 검토 분량 | 무작위 60(1건 이상이면 150) / 150 | 둘 다 가능 |
| U8 | 판단 세트를 만들지 | 만든다(사람 판정 50개 안팎) / 안 만들고 계획 LLM은 "설명만" | |

| U11 | 간병인을 동행자로 볼지, 상급병실 범위, 이미 도착 표시 | | 병동 검수자 세부 항목 |
| U12 | 원본 세트 위치 | 저장소 안(해시 기록) / 밖 | 저장소 공개 여부에 따라 |

## 6. 다음 단계 (사용자 결정 뒤)
1. DECISIONS.md에 U1~U5 결정을 먼저 적는다(설계 변경이므로 코드보다 먼저).
2. 추출기·스키마를 고치고 라벨 명세(`evals/model_eval/라벨_명세.md`) v1을 쓴다.
3. 세트를 다시 만든다(형식 확장, 중복 제거, 입원 대기 메모, 인젝션 확장, 질의 다양화).
4. 다른 회사 모델 2개로 전수 이중 주석 → 일치도 계산 → 불일치 판정 → 명세 수정.
5. 사용자 검토 → 통과하면 세트 버전을 봉인하고 측정 계획을 커밋한 뒤 측정한다.

결정이 오기 전에 할 수 있는 것: 계획 세트 불변성 검사, 세트 manifest·해시 기록, 생성자 계열 기록 칸.
