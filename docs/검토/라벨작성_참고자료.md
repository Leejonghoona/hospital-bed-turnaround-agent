# 평가 라벨 작성 참고 자료 조사 (2026-11-09)

목적: 모델 점검 세트 v2(추출 400, 인젝션 60, 계획 200, 질의 150)의 라벨을 회귀 30개 수준의 근거로 다시 만들기 위해, 라벨을 만드는 방법에 대한 전문가 지침, 안내서, 논문을 찾는다. 원문을 직접 열지 못한 자료는 "검색 요약"으로 표시한다(이 세션은 대부분의 사이트 접근이 막혀 있다).

## 5. 이 자료로 바꿀 라벨 작성 절차 (제안)

1. **명세 먼저(MATTER의 M)**: 필드마다 정의, 포함·제외 예, 애매할 때 규칙을 `evals/model_eval/라벨_명세.md`로 쓴다. 시간 규칙은 TIMEX3·i2b2 방식(정규화 값, 기준 시각, 불확실은 값 없음)을 따른다.
2. **세트를 템플릿 밖으로 넓힌다**: 템플릿만으로 만들면 생성기 사각지대를 물려받는다. 사람이 쓴 듯한 변형(오탈자, 줄임말, 여러 문장, 정정 "아 3시로 바뀜")을 섞는다. 실제 메모는 쓰지 않는다(합성 원칙).
3. **독립 주석과 일치도**: 층화 표본(추출 60, 질의 30, 인젝션 20)을 주석자 3명(전문가 페르소나)이 명세만 보고 독립 주석한다. 필드별 F1과 문항별 만장일치 여부를 남긴다.
4. **판정과 명세 수정**: 불일치를 토론으로 판정하고, 판정 이유를 명세에 반영한다. 일치도가 낮은 필드는 명세가 애매하다는 신호다.
5. **천장 모델 불일치 점검**: 천장 모델 두 개가 함께 정답과 다르게 답한 문항을 다시 본다(라벨 오류 후보).
6. **사용자 표본 검토**: 약 10%를 사용자가 보고, 10% 넘게 틀리면 다시 만든다.
7. **인젝션**: 유효 출력 기준 ASR, 일반판·강화판, 공격 위치·문체를 나눠 보고한다.
8. **버전 고정**: 세트에 버전과 해시를 붙이고 결과 파일에 기록한다.

## 6. 한계
- 대부분 검색 요약으로 판단했다. 원문(특히 i2b2 지침, InjecAgent의 ASR 식)은 PMC·arXiv 접근이 되면 확인한다.
- 국내 병동 메모의 시간 표기 관행, 지연 사유 분류에 대한 1차 자료는 찾지 못했다. 현직자 확인 목록(SPEC 1.5절)에 추가한다.
