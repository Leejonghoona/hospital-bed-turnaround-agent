# 국내 병원정보시스템(EMR·OCS·HIS·원무) 현황 조사: 입원·병상·퇴원·전동·청소·격리 (2026-11-09)

목적: 특정 주장을 검증하는 것이 아니라, 국내 병원정보시스템이 실제로 어떻게 생겼는지(누가 무엇을 어느 화면에서 입력하는지)를 넓게 파악한다. CLAUDE.md 7번(현업 공감 원칙)에 따른 조사 기록이다.
선행 조사: `EMR_병상관리.md`(주장 10개 검증), `원무_병상배정_실무.md`, `감염관리_청소_실무.md`, `병동간호_실무.md`. 이 문서는 그 결과를 반복하지 않고 **공급사·제품 지형, 공공 제안요청서, 화면·상태 용어, 부서 연계, 병원 규모별 차이**를 더한다.

확인 수준 표시
- **원문**: 작업자가 파일·페이지를 직접 내려받거나 열어 해당 문장을 읽음
- **기사**: 언론 보도 본문을 읽음(병원 보도자료 인용 포함)

## 1. 한눈 요약

1. **병상·입퇴원 기능은 국내 HIS의 기본 모듈이다.** 2005년 무렵 국내 상급종합병원은 거의 모두 입원·퇴원·전동(ADT) 기능을 갖췄다(HIR 2011, 검색 요약). 공급사·공공 문서에서는 "원무(PM/PA) = 입퇴원 수속 + 병상관리 + 수납·청구"로 묶는다(이지케어텍 증권사 보고서 검색 요약, 국립병원 EMR 운영 제안요청서 "원무: 병실관리" 원문).
2. **병상 관리의 주인은 원무다. 병동은 전실·퇴원 실시·퇴원 완료 입력을 맡는다.** 원문 근거: 선린병원 계열 중환자실 운영 매뉴얼("[전동전실] 전산프로그램에서 직접 병실이동 수속", "주치의가 전산으로 '퇴원실시 확인'하면 간호사는 '식이종료'와 '퇴원완료'를 입력"), 닥터스 EMR 영상 자막("전과는 거의 원무과에서 해 줄 경우가 많고 간호부에서는 전실을 많이 한다"), 대구가톨릭대병원 "퇴원통보(의사) → 간호확정(간호사데스크) → 심사완료(심사평가팀) → 계산(원무부)".
3. **병상 배정은 지금도 사람이 판단한다. 대형병원은 자동화를 시작했다.** 서울아산(IBM과 AI 배정, 2020, 병원 소식지 원문): 담당자가 퇴원 환자 목록, 병동 현황, 병상 변경 환자, 입원 예정자, 응급실 환자 목록을 "일일이 파악", 50여 개 기준, 진료과 요청이 "전화, 내부 그룹웨어 메시지"로 하루 약 250건. 길병원(2023, 기사 원문): 센터별 입원원무 담당자가 "퇴원 예정 병상을 포함한 입원 가능 병상 현황을 일일이 확인", 하루 합산 17시간 → 자체 개발 자동 배정 10분.
4. **청소 상태를 HIS 병상 상태로 관리한다는 국내 공개 자료는 이번에도 0건이다.** 병원 매뉴얼은 퇴원 뒤 병실 청소·종말소독(TD)을 **간호 업무 목록**에 적고 전산 입력 단계는 두지 않는다(선린 매뉴얼 원문). 닥터스 병실현황 화면의 색은 **보험 유형**(산재, 의료보호, 건강보험)이지 청소 상태가 아니다(자막 원문). 전산에 남는 것은 "퇴원완료", "병실이동", "식이 변경" 같은 **환자 이벤트**다.
5. **격리 표시는 HIS 공통 모듈("감염 및 격리 알람")로 있다.** 울산대병원(900병상) 사례 원문: 감염 정보 등록 → 격리 요청 → 병동 간호 화면 알림, 퇴원 처리 시 격리 해제일 자동 입력. 개선 전에는 격리 요청·해제가 **전화**에 몰렸고, 감염 정보가 추가되면 "격리 병실 재배정이 늦어지는 경우"가 있었다.
6. **공공 차세대 HIS 제안요청서 본문(기능 요구사항 표)은 공개 경로로 거의 구할 수 없었다.** 나라장터 공고 첨부에는 입찰공고서·서약서만 있고 제안요청서 본문은 없었다(국립법무병원 2026, 원문 확인). 병원 게시판은 감리·ISP 제안요청서만 올렸다(전남대 2021, 국립중앙의료원 2023). 얻은 것은 순천향 2011 차세대 제안요청서의 원무 요구 문장, 국립병원 EMR 운영 제안요청서(2022·2023·2025)의 모듈 구성, 서남병원 2025 전자동의서 제안요청서의 "퇴원예정 정보 조회" 요구 정도다.
7. **병원 규모에 따라 시스템 지형이 다르다.** 상급종합은 자체·대형 공급사(이지케어텍 BESTCare, 삼성 DARWIN 계열, 아산 AMIS, 세브란스 U-Severance, 평화이즈 nU 등)에 관제·자동 배정이 붙고, 중소·요양병원은 패키지 EMR(닥터스, 비트, 유비케어 등)의 "병실현황" 화면에 전실 기능 정도다. 공공병원은 클라우드 공동 HIS로 이동 중이다(국립병원 9곳 MEDIRO 2024 가동, 국립중앙의료원·서울의료원 AI 클라우드 HIS 2026 착수, 보훈 6+3곳 통합 2027 목표).

## 5. 부서 간 연계 방식

| 연계 | 국내에서 확인된 방식 | 근거·확인 |
|---|---|---|
| 외래·응급실 → 원무 | 입원결정서(전산) → 원무 창구 입원 수속 → 대장 순서 | 선린 매뉴얼 원문, 아주대·서울의료원 안내 검색 요약 |
| 진료과 → 원무(배정 요청·변경·취소) | **전화, 내부 그룹웨어 메시지**. 서울아산 하루 약 250건 | 서울아산 소식지 원문 |
| 원무 → 환자 | 카카오 알림톡(서울대), ARS(서울아산), 전화·문자 | 원문 |
| 원무 ↔ 병동 | 배정 뒤 병동 통보, 병동 "올려주세요"(전화·구두). 상급 병실 이동은 원무 신청서 | 기존 조사 블로그 원문, 선린 원문 |
| 응급실·외래 → 병동 | 입원 상황 통보를 받으면 병동이 기구·침상 준비 | 선린 매뉴얼 원문 |
| 병동 → 급식실 | 전동 시 식이 자동 변경, 마감 뒤면 전화 | 선린 매뉴얼 원문 |
| 병동 → 원무·심사(퇴원) | 퇴원예고(전일) → 퇴원 실시·완료 입력 → 심사 → 수납 | 선린·대구가톨릭 원문 |
| 감염관리 ↔ 병동·원무 | 감염 및 격리 알람 모듈 + **유선 문의 다수**. 감염 정보 추가 시 격리 병실 재배정 지연 사례 | 울산대 QI 원문 |
| 병동 ↔ 미화(청소) | 전산 연계 근거 없음. 중소병원 매뉴얼은 청소·TD를 간호 업무로 적음. 대형병원은 보조 인력 정해진 시각 일과(해운대백 13:30) | 선린 원문, `EMR_병상관리.md` |
| 병원 ↔ 외부(응급의료) | 응급의료포털 종합상황판(가용 병상 공개) | 기존 조사 |

### 병원 규모별 차이

| 구분 | 시스템 | 배정 | 청소·준비 | 확인 수준 |

## 6. 이 프로젝트 설계에 주는 의미

아래는 제안이다. 이 문서 밖 파일은 고치지 않았다. 설계 변경은 `docs/DECISIONS.md`에 먼저 적는다.

### 6.1 SAG 이벤트 `BED_READY`, `BED_MARKED_VACANT`, `CLEANING_DONE`
- 국내 HIS에 실제로 있는 전산 이벤트는 **퇴원예고, 퇴원실시 확인, 퇴원완료(간호), 수납 완료, 병실이동(전실·전동), 식이종료·변경**이다. `CLEANING_DONE`과 `BED_READY`에 해당하는 표준 화면은 공개 자료로 확인되지 않는다. 합성 데이터와 어댑터에서 이 두 이벤트의 출처는 "HIS 표준 이벤트"가 아니라 **"병원별 입력 수단(전화 통보를 받은 원무·병동의 수기 입력, 별도 앱, 없음)"**으로 표시해야 한다.
- `BED_MARKED_VACANT`(빈 병상 전환)는 국내 화면에서 **"빈 침대"가 전실·배정 화면에 선택지로 뜨는 시점**에 해당한다(닥터스 "꼭 빈 침대를 선택"). 무엇이 침대를 비게 만드는지는 병원마다 다르다. 공개 근거로는 **퇴원완료(간호) 또는 수납**이 침대를 비우는 쪽이 유력하다(설계 가정). 그러면 현실 HIS는 청소 전에 침대를 "빈 침대"로 보여 줄 수 있다. 현재 코드(`saga/machine.py` 400~416행)는 `BED_READY`(격리면 `CLEANING_DONE`까지)가 와야 빈 병상으로 바꾼다. 이 방향은 안전 쪽으로 맞지만, **HIS의 "빈 침대"와 이 시스템의 "입실 가능"이 다른 개념**임을 화면·설명에 밝혀야 현직자가 혼동하지 않는다.
- 제안: 이벤트 사전에 `HIS_BED_RELEASED`(HIS상 침대 해제, 퇴원완료·수납 기준) 같은 관측 이벤트를 두고 `BED_MARKED_VACANT`(이 시스템의 판단)와 구분하는 것을 검토한다. 구현 여부는 설계 문서 범위 확인 뒤 DECISIONS에 적는다.

### 6.2 AS-A4(청소 요청·완료가 시스템 신호로 온다)
- 이번 조사도 지지 근거 0건이다. 오히려 중소병원 매뉴얼은 청소·TD를 간호 업무로 적고 입력 단계를 두지 않는다. **AS-A4 "미확인" 유지, R-25 "상" 유지**가 맞다.
- 공공 제안요청서도 청소 연계를 요구하지 않는다. 2단계 온보딩 입력에서 "청소 이벤트 기록"은 **대부분의 병원이 줄 수 없는 항목**으로 보고, 없을 때는 퇴원완료 → 다음 입실 시각 차이로 청소·준비 구간을 통째로 추정하는 경로가 필요하다(설계 가정).

### 6.3 AS-E4(사용 가능 전환 판단)
- `EMR_병상관리.md` 4.2절 제안(청소 완료 + 병동 준비, 격리면 종말소독 필수)을 유지한다. 추가 근거: 병원 매뉴얼이 **퇴원 침상 TD를 간호 업무로** 둔 병원이 있으므로, `CLEANING_DONE` 입력 주체가 "업체"가 아니라 "병동"인 병원 설정도 있어야 한다. AS-E4 문구의 "업체 완료 신호"는 "청소 담당(업체 또는 병동) 완료 신호"로 넓히는 것을 제안한다.
- 격리: 국내 HIS의 격리 정보는 **감염 및 격리 알람 모듈**이 원천이다(울산대). 격리 퇴실 여부는 이 모듈의 격리 유형·등록 여부에서 읽는 것이 현실과 맞다. 또한 "퇴원 처리 시 격리 해제일 자동 입력"이 있어 **퇴원 순간 격리 플래그가 꺼지는 HIS가 있다**. 종말소독 필요 여부를 퇴원 시점의 격리 플래그로만 판단하면 놓칠 수 있으므로, 퇴원 **직전** 격리 상태를 사례에 고정해 두는 현재 방식(사례 생성 시 isolation 속성)이 맞다. 회귀 시나리오 후보로 "퇴원과 동시에 격리 해제일이 찍힌 격리 퇴실"을 제안한다.

### 6.4 H13(병동 수용 회신 전 확정 시도 거부)
- 국내 HIS에는 병동 "수용 가능" 버튼이 확인되지 않는다. 배정은 원무가 하고 병동은 전화로 준비 완료를 알린다. 진료과 요청도 전화·그룹웨어 메시지다(아산 원문).
- H13은 `라벨검토_H06-H13.md` 지적대로 "회신을 확정 조건으로 둔 병원" 설정에서만 정답이다. 기본 설정은 **회신 없음(원무 배정 = 확정, 병동은 이의 제기만)**으로 두고, 회신 단계는 병원 설정 항목으로 켜는 것을 제안한다.

### 6.5 2단계 온보딩 입력값
병원이 실제로 줄 수 있을 가능성이 높은 것과 낮은 것:

| 입력 | 국내 HIS에 있을 가능성 | 근거 |
|---|---|---|
| 병동·호실·침대 구조, 병실 등급(특실·1인·기준), 간호간병통합 병동 여부 | 높음 | 닥터스 병실현황, 서울대 안내, 국립 제안요청서 |
| 입원결정·입원 수속·배정·입실 시각 | 높음(원무) | 선린, 아산, 길 |
| 퇴원예고·퇴원실시·퇴원완료·수납 시각 | 높음 | 선린, 대구가톨릭 |
| 전실·전동 이력(변경 전/후 병상) | 높음 | 닥터스 전실 화면, 선린 |
| 격리 등록·해제 이력과 격리 유형 | 중간(감염 모듈 보유 병원) | 울산대 |
| 청소 요청·완료 시각 | **낮음** | 0건(누적 4회 조사) |
| 병동 준비 완료·수용 회신 시각 | **낮음**(전화) | 아산, 블로그 |
| 배정 규칙(50여 개 기준) | 문서보다 담당자 머릿속. 자동 배정 병원은 규칙 테이블 있음 | 아산, 길 |

병원 유형 태그(상급종합, 종합·중소, 요양, 정신, 결핵)를 온보딩 첫 질문으로 두면 상태 집합(외출외박, 낮병동)과 기본값을 고를 수 있다.

### 6.6 현직자에게 더 물을 것(기존 질문지에 없는 것만)
1. HIS에서 침대가 "빈 침대"로 바뀌는 순간은 무엇인가(간호 퇴원완료, 수납, 실제 퇴실 입력)?
2. 퇴원 처리 때 격리 정보가 자동으로 해제되나? 그러면 종말소독 대상은 어떻게 전달되나?
3. 진료과·응급실의 배정 요청은 전화, 메신저, 전산 중 무엇이 가장 많은가?

## 9. 한계
- 공공 차세대 HIS 구축 제안요청서의 **기능 요구사항 표 본문**을 한 건도 얻지 못했다. 나라장터 새 시스템(2025~)은 공고 첨부를 번호로 받을 수 있으나 제안요청서 본문은 공고 첨부에 없었고(규격서 별도 경로로 보임), 사전규격 번호는 검색되지 않았다. 국립중앙의료원 게시판 첨부는 스크립트 다운로드라 받지 못했다. 다음 조사에서 나라장터 사전규격(R2xBD…) 번호를 찾거나 정보공개청구를 검토한다.
- 비트컴퓨터, emedit, KOCW 강의 PDF, 삼성서울 페이지는 이 환경에서 DNS·TLS 오류로 열지 못했다.
- 선린 매뉴얼은 대학 사이트에 게시된 병원 운영 매뉴얼이라 병원명·연도를 문서 안에서 확정하지 못했다. 한 병원 사례로만 쓴다.
- 대형병원 내부 화면(BESTCare, AMIS, U-Severance)의 병상 상태 목록은 비공개다. 공개 기사로는 "가용 전환 여부"까지만 확인된다.
