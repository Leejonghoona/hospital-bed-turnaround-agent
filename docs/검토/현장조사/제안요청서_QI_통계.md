## 요약

1. **제안요청서(항목 4)**: 공공 차세대 HIS의 **원무 기능 요구표는 이번에도 얻지 못했다.** 나라장터 새 시스템의 첨부 내려받기 경로는 동작하지만(공고서·서약서만 나옴), 사전규격 목록은 API 키 없이는 조회할 수 없었다. 대신 공공 **병상 정보 공유 시스템의 기능 요구표**(정신의료기관 응급병상정보 공유시스템, 2024, 한국보건의료정보원)를 원문으로 얻었다. 남·여·공용 병상 구분, 하루 4회 수동 입력, "최근 입력 일시" 표시 같은 요구가 있다.
2. **QI 수치(항목 5)**: 한국의료질향상학회(옛 한국의료QA학회) 2011·2014 가을학술대회 연제집 PDF 두 권(포스터·지면 합계 약 2,400쪽)과 QIH 2008 논문 하나를 원문으로 읽었다. **12시 이전 퇴실률 기준선이 42~60%**(4개 기관), 개선 후 77~83%였다. 퇴원 처방부터 퇴실까지 단계별 소요시간 중앙값(인천성모 2010), 입원 수속·입실 시각 분포(해운대백 2012, 동아대 2005~2007)도 나왔다.
3. **공공 통계(항목 6)**: 2020년 병상이용률은 **상급종합 93.0%, 500병상 이상 종합 85.3%, 300병상 이상 종합 77.0%**였다(제5차 국민보건의료실태조사, 원문 사본). 환자요인 보정 평균 입원일수는 **상급종합 7.1일, 종합 8일**이었다(심평원 예비평가 2018~2020 진료분, 기사 원문).
4. **생성기와 대조한 결과**: 지금 생성기의 기준선(에이전트 없음)은 **12시 이전 퇴실 16.6%, 퇴실 중앙값 13:07**로, 국내 QI 기준선(42~60%)보다 한 시간 가까이 늦다. 가장 큰 원인은 보호자 도착 예정 시각을 10:00~13:30에서 고르는 값이다. 24병상에서 하루 6건 퇴원하면 가동률 93%일 때 평균 재원 약 3.7일이다. 상급종합 평균(7일 안팎)의 **약 절반이므로 "회전이 빠른 병동"**이라는 가정을 명시해야 한다.
5. **선행 문서 정정**: `방법론.md`가 "국립해양의료원 '가퇴원 발생 최소화 및 오전퇴원율 제고'(2019)"라고 적은 과제의 출처 `nhimc.or.kr`은 **국민건강보험 일산병원** 사이트다. 2020년 12월 한국의료질향상학회에서 일산병원 송경준이 같은 제목으로 발표했다(검색 요약). 국립해양의료원이 아니다.

### 1.2 새로 얻은 원문: 정신의료기관 응급병상정보 공유시스템 구축 제안요청서 (2024)

출처: 한국보건의료정보원 입찰공고 list_no=1502, 붙임2 제안요청서 PDF(정보통신산업진흥원 보완본). https://www.khis.kr/board.es?mid=a10304000000&bid=0009&list_no=1502&act=view **원문**

병원 내부 HIS가 아니라 **기관 사이에 여유 병상을 공유하는 공공 시스템**이다. 그래도 공공 발주자가 "병상 현황"을 어떤 항목과 주기로 정의하는지 보여 준다.

- 현황 문제: "여유병상 정보의 입력은 정신의료기관 담당자가 수동으로 입력하며, 반응형 웹(PC, 모바일 등)을 통해 여유병상 정보를 입력"
- SFR-021 정신응급 여유병상정보 입력:
  - "정신응급 여유병상 : 남자 여유병상 수, 여자 여유병상 수, 공용 여유 병상 수"
  - "정신응급 여유병상정보 입력 시간 - 시스템 기본 설정 : 오전 9시 / 오후 3시 / 오후 9시 / 오전 3시"
  - "여유병상 정보 입력 시간이 도래한 경우 시스템에서 알림 기능 제공"
  - "정신의료기관의 보유병상 수(남자/여자/공용/일반) 대비 여유병상 수를 보여줄 수 있도록 함 - 여유병상 정보 최근 입력 일시를 보여주어야 함"
  - "여유병상 정보 입력 항목은 현장 실무자들의 의견을 반영하여 재검토 해야 함"
- SFR-022 입력 현황 조회: "여유병상정보 입력 설정 시간과 실제입력시간을 보여줄 수 있도록 함"
- 과업 범위 ③: "효과적인 정신의료기관 응급병상정보 입력 방안 제안", "정신의료기관 응급병상정보 입력을 자동화하여…"

**이 프로젝트에 주는 시사점**
- 공공 발주자도 병상 현황을 **성별 단위(남·여·공용)**로 센다. 생성기의 다인실 성별 지정, 배정 제약과 맞는다.
- 병상 정보는 아직 **사람이 정해진 시각에 입력하는 스냅숏**이고, 신선도("최근 입력 일시", "설정 시간 대비 실제 입력 시간")를 따로 요구한다. 대시보드의 상태값 옆에 마지막 이벤트 시각과 지연 여부를 같이 보여 주는 설계는 공공 요구 관행과 맞는다.
- 발주자 스스로 "입력 자동화"를 과업으로 냈다. HIS 이벤트에서 병상 상태를 자동으로 만드는 방향(2단계 온보딩)의 수요 근거로 쓸 수 있다(간접 근거).

## 4. 생성기 값 제안

근거 등급
- **A**: 공식 통계 원문(또는 원문 사본), 또는 서로 다른 기관 원문 3곳 이상이 같은 자릿수

### 4.3 구조 제안: 정규 퇴원과 추가 퇴원을 섞기

지금은 30건 모두 "08:30 회진 뒤 오더"로 출발한다. 국내 QI는 정규(전날 처방, 약 09:30 일괄 불출)와 추가(회진 뒤 처방, 개별 조제)를 나누고, 이 비율이 오전 퇴실률을 좌우한다고 일관되게 보고한다(4곳). 제안:
- `regular_discharge_rate` 약 0.65(등급 B, 인천성모 65%·양산부산대 정규 62.7%·제주한라 40~50%의 중간): 오더 시각은 전날 저녁으로, 약 준비는 09:30 고정에 소폭 분산.
- 나머지(추가 퇴원): 지금의 회진 뒤 경로.
- 미등록(`registered_at=None`)은 추가 퇴원의 부분 집합으로 둔다.

이는 설계 문서의 생성기 항목을 바꾸는 일이므로 `DECISIONS.md`에 먼저 적어야 한다.

| 평균 재원일수(재원 기간을 모델에 넣을 경우) | 없음 | 로그정규 **중앙값 5일, 평균 7일**(오른쪽 꼬리, 열외군 약 2.6%) | A(평균)·C(분포 모양) | 보정 평균 7.1일, 열외군 2.6%(예비평가). 중앙값은 국내 근거가 없어 가정 |

### 4.6 근거를 찾지 못한 항목(설계 가정 유지)

- 요일별 퇴원·입원 분포: 공공 자료를 찾지 못했다(D).
- 청소 소요와 지연(`cleaning_*`): 이번 자료에도 국내 측정값이 없다(백로그 18 유지, D). 단, 보라매·인천성모 사례처럼 **약제·심사는 일괄 처리 시각(09:30 불출 등)**이 있으므로, 청소도 실제로는 일괄 호출일 가능성이 있다. 현직자 질문 후보로 둔다.
- 가퇴원 비율: 건국대 "17시 30분 이후에 퇴원통보 … 9.4%"는 업무시간 뒤 퇴원의 상한 추정으로만 쓸 수 있다(C). 가퇴원 경로(백로그 16)는 여전히 설계에 없다.
