## 결론 먼저

1. **문제는 남아 있지만, 지금 문서가 그리는 하루 장면은 현장과 어긋난다.** "병상관리 담당이 전날 저녁 사전 매칭을 하고 병동에 준비 시각을 전화로 묻는다"는 장면의 두 기둥이 약해졌다. 공개 안내 14곳은 모두 **입원 당일 오전 일괄 배정**이다(원문 다수). 상태판이 있는 병원도 늘고 있다(분당서울대 2026-06 원문, 해외는 Epic 기본 기능). 남는 문제는 "배정한 병상이 **오후 입실 창(14~17시) 안에** 준비될지 아무도 미리 보장하지 못하고, 어긋나면 사람이 전화로 다시 짠다"이다.
2. **가치 제안을 "빈 병상을 먼저 알린다"에서 "당일 배정이 입실 창에 맞게 지켜지도록 미리 경고하고, 어긋나면 안전하게 다시 짠다"로 옮길 것을 권한다.** 보는 기능(상태판, 청소 앱, 퇴원 예측)은 이미 상품화됐다. 차별점은 ① 한국 절차(원무 중심 배정과 병동 이의, 심사→수납→영수증→퇴원약, 가퇴원)를 아는 사례 추적 ② 실행 직전 재확인과 규칙 재검사를 하는 실행 게이트웨이 ③ 재생 평가 체계 ④ 비정규 경로(사망 후 처치 중 배정 차단 등)로 좁혀진다.
3. **북극성(퇴실 → 준비 완료)은 현장 질문과도 맞지 않는다.** 11시 퇴실, 14~17시 입실이 규정이라면 2~3시간의 빈 시간은 구조적이고 정상이다. 아파 보이는 것은 "입실 창을 놓친 준비"와 "늦은 오후 퇴실 꼬리"다. PRD-Q1을 "입실 창 안 준비율, 준비 지연 때문에 밀리거나 연기된 입원 수"로 정할 것을 권한다(설계 가정).
4. **1단계 수정(현실과 맞추기, 새 기능 아님) 6건을 먼저 한다.** 당일 오전 배정 모드, 연기 연락 마감·입실 창 기준 시각, 병동 확인 방식 설정(관문 / 통보 뒤 이의 / 없음), 퇴실 전 단계 순서 설정과 "퇴실 = 병상 비움", 야간·휴일 가퇴원 모드, 격리 "아직 모름". 모두 원문 근거가 있고 비용은 S~M이다. 기존 승인 라벨 30개가 깨지지 않게 **기본값을 바꾸지 말고 병원 설정(프로필)으로 추가**하고, 현실형 프로필용 시나리오를 따로 둔다.
5. **1단계 확장은 4건으로 묶는다.** 청소 2단계(미화 + 병동 침상 준비 일괄 시각)와 청소 근무 시간대, 청소 구간 가시화(보고만), 병상 상태판 신호 받기(어댑터, 자체 현황판은 만들지 않음), 병실 이동 연쇄 **표시**(최적화 아님). 응급실발 입원 최소판(출시 단계 1.4)은 계획대로 둔다.
6. **하지 않을 것을 분명히 한다.** 퇴원 준비도 ML 예측(실데이터 없음, Epic·Qventus 영역), 연쇄 이동 최적화와 자동 제안(GW-15 "설계", 두 병상 사가), 응급실 대기 화면(3인 만장일치 제외), 청소·이송 인력 배정과 청소원별 성과, 알림톡 자동 발송, 자체 병상 현황판.
7. **2단계(온보딩) 입력 목록이 현장조사로 거의 정해졌다.** 병원마다 다른 값 17개(5절)는 지금 설정 키로만 받아 두고, 자동 생성은 1단계를 마친 뒤 한다.
8. **결정을 가장 크게 바꿀 조사는 셋이다.** ① 국내 HIS 병상 상태판에 "청소 중·준비 완료"가 실제로 있고 누가 언제 넣는가(공공병원 차세대 HIS 제안요청서, 공급사 매뉴얼, 설문 4·5) ② 재원 환자 병실 이동이 빈 병상을 얼마나 먼저 가져가는가 ③ 전날 가배정이 실제로 있는가. ①이 "있고 정확하다"로 나오면 이 제품은 상태판 위의 예외·실행 계층으로 더 좁혀야 하고, ②가 크면 "환자-병상 쌍" 모델 자체를 다시 봐야 한다.

### 1.2 판정

- **유지되는 것**
  - 문제의 핵심: 퇴원부터 입실까지가 원무·병동·약제·미화·병동보조·감염관리에 걸쳐 따로 돌고, 어긋나면 사람이 전화로 다시 짠다. 첫 배정 자동화 보도들은 이 뒷단을 다루지 않는다(길병원·서울아산·분당서울대 원문 어디에도 청소 완료 신호나 단계 지연 추적이 없다).
  - 안전 쪽 가치: 격리 등록 누락(F9), 사망 후 처치 중 "빨리 비워 달라" 압력(`병동간호_실무.md` 5절)은 실행 게이트웨이와 비정규 경로 처리의 근거를 오히려 강하게 만든다.
  - 사람이 남는 세 순간(공식 확정, 환자 연락, 안전 예외)의 틀.
- **약해진 것**
  - "전화로만 안다"(F7): 상태판이 있는 병원에서는 가시성 자체로 팔 수 없다.
  - "퇴실 즉시 청소 요청이 시간을 줄인다"(F6): 착수는 일괄 시각과 근무대에 묶인다.
  - 고정된 단계 순서(F4), 평일과 같은 야간 처리(F8).
- **다시 써야 하는 것**
  - 하루 장면(F1): 전날 사전 매칭 중심 → 당일 오전 배정 중심. 전날 저녁은 "미등록 퇴원 확인과 청소 예정표 공유"만 남는다(이 부분은 현장 QI의 "전날 16~20시 퇴원 예고" 기준과 맞다).
  - 병동 관문(F2): 확정 관문 → 입실 시점 관문(병원 설정).
  - 북극성(F3): 퇴실 → 준비 시간 → 입실 창 기준 지표.
  - 연쇄 이동(F5): 지금은 범위 밖으로 두되, 빈도 조사 결과에 따라 모델 재검토 조건으로 등록.

합성 기준선의 퇴실 P50 13:06, 정오 전 퇴실 17.1%는 공개 규정(11시)과 단일 병동 실측(오전 퇴원 69.2%, 2016)보다 훨씬 늦다(`병동간호_실무.md` 3절). 수치 비교는 하지 않지만, **"규정은 11시, 실제는 늦다"를 의도한 분포인지 DECISIONS에 설계 가정으로 적어야** 한다. 이 분포가 늦을수록 "병상이 늦게 빈다"는 문제가 과장돼 보인다. 현직자가 하루 재생 화면을 보고 가장 먼저 갸우뚱할 곳이다.

## 3. 기능 확장 후보와 우선순위

### 3.1 판정 규칙
- 단계 표기: **1단계 수정**(이미 주장한 범위를 현실과 맞추는 일), **1단계 확장**(새 범위지만 1단계 안), **2단계**(온보딩, 1단계를 마친 뒤), **하지 않음**.
- CLAUDE.md를 넘지 않는다: 합성 데이터만(1번), 계산·배정은 결정적 코드(2번), 청소·이송 인력 배정 금지(4번), 설계 문서의 "설계"·"제외" 항목 구현 금지(5번), 근거 없는 값은 설계 가정 표시(7번).
- 우선순위: ① 현직자가 보고 갸우뚱할 결함을 고치는가 ② 근거 수준(원문 1차 > 원문 2차 > 존재 증거 > 검색 요약) ③ 비용 ④ 차별점에 보태는가.
- 비용(이 코드베이스 기준, `src/turnaround` 약 6,900줄): **S** = 설정 키·검토 사유·시나리오 1~3개, 하루 안. **M** = 생성기 분기 + 사가 상태나 이벤트 + 시나리오 3~5개 + 테스트 수십 개, 2~4일. **L** = 새 사가 모델·새 데이터원·새 화면, 1주 이상.
- 라벨 보호: 승인된 회귀 라벨 30개는 지금 장면(전날 사전 매칭, 관문형 병동 회신)을 전제한다. 1단계 수정은 **기본값을 바꾸지 않고 "병원 프로필" 설정으로 추가**하고, 현실형 프로필 시나리오를 새로 쓴다. 기본값 전환은 설문 답 뒤 사용자 결정이다.
