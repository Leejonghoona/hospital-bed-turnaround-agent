# 조사 범위 설계: 근거 추적표, 출처 계층 점검, 조사 백로그, 반응형 공백 방지 규칙

- 작성일: 2026-11-09. 작성: 조사 방법론 검토(연구방법론 관점). 상태: 조사 계획 문서다. 설계를 바꾸지 않는다. 설계 변경은 DECISIONS에 먼저 적는다(CLAUDE.md 작업 방식).
- 왜 만들었나: 지금까지의 조사는 소유자의 질문이 들어올 때마다 그 질문만 찾는 방식이었다. 그래서 출처 계층이 통째로 빠진 일이 생겼다. 예를 들어 병원 정보시스템(EMR/HIS) 병상관리 자료는 소유자가 짚은 뒤에야 찾았다(`현장조사/사용자제공_EMR요약.md`). 검증 결과 파일로 예고된 `EMR_병상관리.md`는 아직 없다. 이 문서는 조사 범위를 설계 요소에서 거꾸로 정한다. 요소마다 필요한 근거와 지금 가진 근거, 빈칸을 한 표에 둔다.
- 읽은 자료: `CLAUDE.md`, `docs/병상턴어라운드_설계.html`(구조와 참고 자료 절), `docs/SPEC.md` v1.0, `docs/DECISIONS.md`(LP-23~29, MA-01~15), `docs/기획/05_리스크_가정_등록부.md`(AS-A1~E5, PA-01~08), `docs/기획/02_사용자_이해관계자.md` 3절 RACI, `config/policy.yaml`, `config/operations.yaml`, `src/turnaround/sim/distributions.py`, `src/turnaround/saga/machine.py`의 `SagaPolicy`, `evals/scenarios/` 43개 제목, `docs/검토/` 아래 모든 조사 문서.

## 0. 읽는 법

### 0.1 확인 수준 (현재 근거 열에 쓴다)
| 표기 | 뜻 |
|---|---|
| 1차·원문 | 법령, 정부 지침·고시, 병원 공식 안내, 판결, 공급사 기술 문서를 작업자나 조사 에이전트가 직접 열어 해당 문장을 확인함 |
| 1차·사본 | 1차 문서이나 제3자 미러로만 확인함(예: 표준예방지침 `openingnow.github.io` 사본). 공식본 대조가 남음 |
| 2차·원문 | 기사, 논문 초록, 블로그 등을 원문으로 읽음 |
| 검색 요약 | 검색 엔진 요약만 봄. 근거로 쓰지 않는다(스펙현실검증 조사 방법 원칙) |
| 존재 증거 | 개인 블로그·영상 1건. "이런 일이 실제로 있다"까지만 말한다 |
| 설계 가정 | 근거를 찾지 못해 작업자가 정한 값 |

### 0.2 공백 판정
| 판정 | 기준 |
|---|---|
| **충분** | 규범(법령·지침이 정하는 것): 1차 원문 1건 이상이고 반증이 없다. 운영 관행: 서로 다른 기관 3곳 이상의 1차·2차 원문이 같은 방향이다. 수치: 국내 측정값 2건 이상, 또는 국내 1건과 해외 측정 1건 |
| **약함** | 근거가 있으나 한 기관뿐이거나, 사본·2차·검색 요약뿐이거나, 순서·주체만 맞고 값은 가정이다 |
| **약함(반증)** | 공개 근거가 설계와 **반대 방향**을 가리킨다. 판정을 바꾸기 전에 가장 먼저 다시 본다 |
| **없음** | 설계 가정만 있다 |
| 해당 없음 | 순수 기술 설계라서 현실 근거가 필요 없다(예: 멱등 키, SHACL 재검사, 버전 충돌 차단). 아래 표에서 뺐고 1.12에 목록만 둔다 |

### 1.13 추적표 요약
- 판정 행 130개(행 단위 집계, 같은 근거를 공유하는 행 포함)의 분포: **충분 22, 약함 60(그중 반증 11), 없음 44, 해당 없음 3, "근거는 있고 설계가 비어 있음" 2**.
- 충분은 거의 모두 **감염관리 지침 계열**이다. 지침 하나(표준예방지침 2017)를 제3자 사본으로만 봤으므로, 공식본 대조 한 번이 충분 판정 15행을 한꺼번에 지킨다(백로그 1).
- 반증 11행이 가장 급하다. 사전 매칭 시점, 퇴원 당일 순서, 수용 회신, 임상 우선 처리, 1인실 희망, 사용 가능 전환, 일반실 환기 횟수가 공개 근거와 반대 방향이다.
- 없음 44행은 대부분 **수치**(타이머, SLA, 분포)와 **병원 내부 결재·당직 체계**다. 수치는 QI 발표·과업지시서·학위논문이라는 아직 훑지 않은 계층에서 나올 가능성이 있고, 결재·당직은 현직자만 답할 수 있다.

## 4. 반응형 공백 방지 규칙

### 4.1 원칙
1. **조사 범위는 질문이 아니라 설계 요소에서 정한다.** 새 요소(상태, 타이머, 규칙, 역할 칸, 알림, 정책값, 시나리오)를 넣을 때마다 1절 추적표에 행을 먼저 만든다. 행이 없는 요소는 구현하지 않는다.
2. **모든 출처 계층을 한 번씩 훑었다는 기록을 남긴다.** "찾지 못했다"는 "어느 계층을 어떤 검색어로 훑었는데 없었다"로만 쓴다.
3. **반증을 먼저 찾는다.** 설계를 지지하는 근거보다 반대 근거를 찾는 검색어를 먼저 돌린다. 반증이 1건이라도 있으면 판정은 "약함(반증)"이다.
4. **접속 실패는 근거 없음이 아니다.** 이번 조사에서도 law.go.kr, koiha.or.kr, opendata.hira.or.kr, khna.or.kr, koshic.org, scourt.go.kr가 열리지 않았다. 실패한 주소와 대체 경로(관보, 국회도서관, 협회 공지 첨부, 제3자 사본)를 적고 판정을 "미확인"으로 둔다.
5. **검색 요약과 조사 에이전트 결론은 근거가 아니다.** 설계를 바꾸기 전에 핵심 출처를 작업자가 직접 연다(CLAUDE.md 7번, 2026-11-08 사례).
6. **공개 자료가 답할 수 없는 질문은 일찍 현직자 질문으로 넘긴다.** 결재선, 당직 체계, 병원 내부 SLA는 공개되지 않는다는 것을 이미 확인했다(`현장실태_시범.md` 1절). 같은 질문을 검색으로 세 번 이상 되풀이하지 않는다.

### 4.3 주기 점검
- DECISIONS에 항목이 하나 추가될 때마다 추적표의 관련 행 판정을 다시 본다.
- 현직자 설문·인터뷰 답이 오면 3절 현직자 전용 행과 05 등록부 AS- 판정을 같은 날 고친다.
- 마일스톤(홀드아웃 실행 등)마다 1.13 요약 숫자(충분, 약함, 반증, 없음)를 다시 세어 `docs/RESULTS.md`에 남긴다. 반증 행 수가 줄지 않으면 다음 설계 확장을 멈추고 반증부터 처리한다.

### 4.4 조사 의뢰 형식
조사 에이전트에게 일을 맡길 때 질문 대신 다음을 준다: 추적표 행 번호, 필요한 근거 유형(규범·관행·수치·역할), 반드시 훑을 출처 계층 목록(4.2의 3~10), 반증 검색어 1개 이상, 멈추는 기준. 결과는 "계층별로 무엇을 찾았고 무엇이 없었나" 표로 받는다.
