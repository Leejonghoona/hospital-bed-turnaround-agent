# 예외 판단 정답 세트 v2 토론 검증 (2026-11-09)

- 대상: `evals/model_eval/exception_decisions_v2.jsonl` 250문항(초안 개정 46 + 규칙 생성 204). 결과로 만든 판: `exception_decisions_v2_1.jsonl`.
- 방식: 다중 에이전트 9개. **1라운드** 페르소나 3명이 250문항을 절반씩 나눠 독립 검토(6개). **2라운드** 지적된 문항을 세 페르소나가 서로의 의견을 보고 반박·수용해 최종 판정(3개). **합의**는 코드로 정했다: 3명 중 2명 이상 "수정"이면 채택, 2명 이상 "모르겠음"이면 현직자 질문, 2명 이상 "유지"면 유지.
- 페르소나: 현장 운영(병동 책임간호사 + 원무 병상배정 담당), 감염관리·환자안전(감염관리 간호사 + QI), 평가 설계(라벨 방법론).
- 에이전트 결론을 그대로 믿지 않는다(CLAUDE.md 7번). 아래 수정은 작업자가 문항과 생성 규칙을 다시 보고 적용했고, 테스트로 고정했다(`tests/test_exception_set.py`).

## 초안 문항 정답 변경

XD-002·007(연락 전이지만 감염관리실이 우선순위를 정하는 부족 1인실), XD-016(입실 뒤 빈 음압실로 전실 추천), XD-029·030(곧 준비될 병상을 가배정 추천안으로) → `propose_rematch`. XD-040 → `request_bed_prep_first`(입력을 약속보다 늦게 고침). XD-044는 정답 유지, 근거 문장만 고침. 나머지 초안은 허용·금지·입력만 고쳤다.

## 사용자 결정이 필요한 것 (v2.1에서는 보수적으로 두고 `field_question`에 적음)

1. **병동 통보 뒤 재매칭을 사람 승인으로 둘까?** (XD-004, XD-036) 안전 검토 1.3은 사람 승인, 정책은 auto다. 지금은 정답 `rematch_now`, 허용에 `propose_rematch`.
2. **곧 준비될(퇴원 예정) 병상도 추천안 대상인가?** (XD-029, XD-030) 지금은 그렇다고 보고 `propose_rematch`. 아니면 정답을 올림으로 바꾼다.
3. **E1 올림 역할에 병동(ward)을 넣을까?** (XD-014) 지금은 넣지 않고 허용에서 뺐다.

## 현직자 질문으로 넘긴 것

- CRE 1인실을 자동 재제안이 먼저 잡아도 되는가, 감염관리실 승인이 먼저인가(생성 CRE 문항).
- 인계 시간대에 환자 대기와 병동 수용이 부딪히면 무엇을 먼저 하나(토론의 유일한 "현직자 질문" 합의 문항).
- 심사 재오픈(추가 처방) 뒤 지연은 누구에게 올리나.
- 검체 오류로 격리를 해제하는 정정은 감염관리실이 확인하나 주치의가 확인하나(XD-034, 유지 합의지만 현장 의견 남김).

## 남은 한계

- v2.1은 토론 합의를 반영했지만 v2.1 자체를 다시 토론하지는 않았다.
- "늘 올림" 비교선이 v2.1에서 A1 0.600이다. 올림이 정답·허용인 문항이 많아서다. 선정 모델은 이 비교선을 넘어야 한다(사전 등록 2.1).
- `propose_rematch`와 E1 올림 역할 변경은 정책 파일·게이트웨이에 아직 없다(다른 세션 작업 범위).
