## 0. 요약 (결론 먼저)

1. **지금 점검표로는 모델을 고를 수 없다.** 현재 기준을 그대로 적용하면 홀드아웃에서 E2(틀린 값 2% 이하)를 통과한 모델이 **하나도 없다**(최저 gpt-4.1-mini 3.0%). P1(98%)은 39번 호출로는 통과도 탈락도 판정할 수 없다. C1은 모든 실제 모델이 30/30이라 변별력이 없다. 그런데도 "싸고 빠른 소형"으로 정해졌다. 기준이 결정에 쓰이지 않았다는 뜻이다.
2. **E1은 부풀려져 있다.** 홀드아웃 400칸 중 293칸(73.25%)이 정답이 "값 없음"이다. 아무것도 안 뽑는 모델이 E1 73%를 받는다. 가짜 LLM이 84%인 이유다. 주 지표를 **문항 전부 정확(item-exact)**과 **값이 있는 칸의 정밀도·재현율**로 바꾼다.
3. **상한 기준선이 없다.** 회사마다 최상위 모델 하나씩(gpt-5.5, Claude Opus 5.5, grok-4.7)을 재서 "이 과제의 천장"을 먼저 잡는다. 운영 후보는 천장 대비 **비열등(non-inferiority)**으로 판정한다. 천장 모델끼리 틀리는 문항은 라벨 오류 후보로 사람이 다시 본다.
4. **표본을 늘린다.** 추출 홀드아웃 100 → **400문항**(문항 단위, 문항 묶음 붓스트랩). 계획 선택 호출 13번 → **200개 결정 지점**(계획 전용 세트). 인젝션 짝 17 → **60쌍 이상**. 형식 유효율은 **실패 0건이면 150호출**이 있어야 "실패율 2% 미만"을 말할 수 있다(3의 규칙). 근거는 4절.
5. **회귀 30개는 관문으로, 능력 비교는 따로.** Anthropic 평가 글의 구분대로 회귀 세트(30개)는 100% 유지 관문이고, 모델 간 차이는 새 "능력 세트"로 잰다.
6. **결정 규칙: 관문 → 비열등 → 비용 파레토 → 동률 규칙.** 관문은 데이터 경로, 라이선스, 공급망, 안전 회귀, 형식, 인젝션. 비열등 마진은 5%p **[설계 가정]**. 남은 모델 중 연간 총비용(TCO)이 가장 낮은 것을 고른다.
7. **비용은 원내를 정당화하지 못한다. 원내는 보안 때문이다.** 이 호출량에서 외부 API는 월 약 $44~$3,900인데, 원내 GPU 1장 서버는 연 약 $22,000~$30,000 **[설계 가정 포함]**이고 그 절반이 운영 인력이다. 원내를 고르는 이유는 개인정보보호법상 국외 이전과 민감정보 문제를 피하기 위해서다. 그래서 원내 안에서는 **관문을 넘는 가장 작은 장비 등급**을 고른다.
8. **운영 1안(가설)**: 원내 단일 모델(gpt-oss-120b, 80GB GPU 1장)로 세 역할 모두. 추출 비열등을 못 넘으면 추출만 Gemma 4 26B 또는 gpt-oss-20b를 더한다. **운영 2안**: 추출은 원내, 계획·질의만 Bedrock 서울 단일 리전 Claude(가명 코드값만). **대체 경로**: 규칙 모드. 이 셋은 측정 전 가설이다. 6절의 측정으로 확정한다.
9. **계획 역할은 LLM이 규칙 모드보다 나은지부터 잰다(P4).** 나은 점이 없으면 계획 모델은 "설명만" 맡고, 관문을 넘는 가장 싼 모델 또는 규칙 모드+고정 문장 설명으로 간다.
10. **CPU 전용(GPU 없음) 원내는 1.5B·2.4B 실측으로 탈락했다.** 남은 7B는 이미 받아 둔 파일로 바로 잰다. 이걸로 "CPU만으로 되나"를 닫는다.

## 2. 현재 점검표 비판

### 2.1 후보군 구성
| 문제 | 근거 | 고칠 점 |
|---|---|---|
| 회사별 등급이 비대칭. OpenAI 소형 4개, xAI 중형 비추론 1개, Anthropic 0개, 원내는 CPU 초소형 2개 | 점검표 3절 | 회사마다 "천장/중간/소형" 한 칸씩. 원내는 장비 등급별 한 칸씩(3.1절) |
| 상한 기준선 없음 | 결과표에 gpt-5.5, Opus, grok-4.7 없음 | 천장 모델로 과제 상한과 라벨 오류를 먼저 잡는다. Anthropic 문서도 "최신 모델 수준을 넘는 목표는 세우지 말라"고 한다. 천장을 모르면 90%가 높은지 낮은지 알 수 없다 |
| 운영 후보(원내)를 거의 안 쟀다 | 설계 문서 1안(gpt-oss-20b/120b, Gemma 4 26B)이 미측정. 잰 원내 모델은 운영 후보가 아님 | 운영 후보부터 잰다. 합성 데이터라 GPU 임대나 호스팅 API로 재도 된다(정책상 허용) |
| 운영 2안 실제 모델을 안 쟀다 | 2안은 Bedrock 서울 **Sonnet 5**인데 비교 대상은 Sonnet 5.5 | 운영에 쓸 **정확한 버전**을 잰다. 대리 측정이면 그렇게 적는다 |
| 추론형/비추론형 구분이 없다 | gpt-5 계열은 기본 추론 강도로 돌았고, 지연이 4배 | 모델 ID에 추론 강도를 포함(예: `gpt-5.5@effort=low`). 역할별로 쓸 강도로 잰다 |
| 버전 고정 없음 | `gpt-4o-mini` 같은 별칭 사용 | 날짜 붙은 스냅샷 ID, 측정일, 리전, 온도, 추론 강도, 프롬프트 해시, 하네스 커밋, 가중치 SHA256, 양자화, 추론 엔진 버전을 결과 JSON에 남긴다(TRIPOD-LLM) |
| 라이선스 탈락 모델을 운영 후보처럼 표에 둠 | EXAONE 3.5 2.4B는 연구용(NC) 라이선스로 알려짐, Qwen2.5 3B도 별도 라이선스 | 관문 탈락 모델은 "참고 측정"으로 따로 표시 |

### 2.2 관문

### 2.4 통계 규칙
- "신뢰구간이 겹치면 구별 불가"는 너무 보수적이다. 짝지은 차이의 신뢰구간을 직접 본다(Miller 2024). McNemar는 맞다. 다만 여러 쌍을 비교하므로 21쌍이면 다중 비교 보정(Holm)을 붙인다.
- "구별 불가"와 "같다"는 다르다. 운영 후보 판정은 **비열등 검정**으로 한다(천장 − 후보의 차이 단측 95% 상한 < 마진).
- 홀드아웃은 같은 템플릿에서 나왔다. grok만 홀드아웃에서 크게 떨어진 것(문항 전부 정확 90% → 73%)은 분포 차이에 약한 모델을 보여준다. 홀드아웃을 **다른 작성 방식**(다른 사람 또는 다른 계열 LLM이 쓴 문장, 축약어·오타 비율 다름)으로 하나 더 만든다.
- 라벨 작성과 평가 대상이 같은 계열이면 편향이 생긴다. 추출 문장 초안은 Claude가 썼다. Claude 모델 점수에는 "같은 계열 작성 문장" 표시를 붙인다(설계 문서도 같은 이유로 Opus를 라벨 검수에 안 씀).

### 3.4 표본 크기와 통계 (검정력 근거)

| 질문 | 계산 | 필요 표본 |
|---|---|---|
| 추출 정확도를 ±3%p로 알고 싶다(정확도 90% 근처) | n = 1.96²·p(1−p)/h² | **385문항** |
| 두 모델의 5%p 차이를 검출(검정력 80%, 양측 5%). 현재 상위 모델 간 불일치 쌍 비율 ψ ≈ 0.15(예: gpt-4o-mini vs gpt-5-mini 홀드아웃 17/100) | Connor 식: n = (1.96√ψ + 0.84√(ψ−δ²))² / δ² | **약 470문항** |
| 비열등(마진 5%p, 단측 5%, 검정력 80%, ψ=0.12~0.15) | n ≈ (1.645+0.84)²·ψ / m² | **약 300~370문항** |
| 마진을 3%p로 좁히면(ψ=0.08) | 같은 식 | 약 550문항 |
| 형식 실패율 < 2%를 실패 0건으로 보이기 | n ≥ ln(0.05)/ln(0.98) | **149호출** |
| 형식 실패율 < 1% | 같음 | 299호출 |
| 인젝션 ASR < 5%를 0건으로 보이기 | 같음 | **59쌍** |
| E2 관측 1%일 때 95% 상한이 2% 아래 | 정확 이항 | 값 낸 칸 약 600개 |

→ **추출 홀드아웃 400문항**(비열등 판정에 충분, 차이 검출엔 약간 모자람), **계획 능력 세트 200 결정 지점**, **인젝션 60쌍 이상**, **질의 150문항**. 추출 개발 세트는 200으로 늘린다.

**반복 측정과 무작위성 바닥값**
- 온도를 받는 모델은 온도 0. 추론 모델(온도 없음)은 100문항 부분집합을 **3회** 돌려 문항별 평균을 쓴다(Miller 2024 권고 3).
- 바닥값 = 같은 입력 3회 사이 출력이 달라진 비율. 인젝션은 "공격 방향으로 바뀜"만 세므로 바닥값과 섞이지 않는다. 바닥값은 R1로 따로 보고한다.
- 비교는 항상 같은 문항 짝지은 차이. 여러 쌍이면 Holm 보정.
- 홀드아웃 실행 횟수를 RESULTS.md에 남긴다(평가표 원칙 유지). 프롬프트를 홀드아웃 결과로 고치지 않는다.

**라벨**: 200문장은 아직 `draft`다. 선정 전에 사용자 승인이 필요하다. 천장 모델 3개가 모두 라벨과 다르게 답한 문항은 사람이 먼저 본다. 천장 모델 답을 정답으로 쓰지는 않는다(순환).

### 3.5 최종 결정 규칙

1. **관문**: G1~G8. 하나라도 걸리면 운영 탈락. 탈락 사유(관문 ID, 측면)를 표에 남긴다.
2. **비열등**: G7에서 이미 천장 대비 마진 안. 계획은 규칙 모드 대비 P2 비열등(나빠지면 안 됨).
3. **비용 파레토**: 남은 후보를 (X1, TCO, L) 세 축에 놓고 지배당하지 않는 것만 남긴다. 그중 **TCO 최소**.
4. **동률 처리**(TCO 차이 20% 이내 **[설계 가정]**): ① 세 역할을 한 모델로 처리(운영 단순) ② 장비 수가 적음 ③ 라이선스 단순(Apache 2.0 등) ④ R1 일관성 높음 ⑤ 공급사·커뮤니티 지원(엔진 공식 지원, 업데이트 주기) ⑥ 한국 개발 모델(공공병원 지침 대응).
5. **계획 역할 특례**: P4에서 LLM이 규칙 모드보다 낫지 않으면, 계획 모델은 설명만 맡는다. 이때는 추출 모델과 같은 모델로 통일하거나 규칙 모드 + 고정 문장 설명으로 간다.
6. 결정을 DECISIONS.md에 적고, 버전이 바뀌면 1부터 다시.

## 5. 원내 장비 추정

### 5.1 처리량 추정식 (근거 있는 방식)

생성은 두 단계다. 둘을 따로 계산해야 한다.
- **입력 처리(prefill)는 연산에 묶인다.** 시간 ≈ 2 × 활성 파라미터 × 입력 토큰 / (η_c × GPU 최대 연산).
- **출력 생성(decode)은 메모리 대역폭에 묶인다.** 1개 요청 속도 상한 ≈ 유효 대역폭 / 토큰당 읽는 바이트. 토큰당 바이트 ≈ 활성 파라미터 × 파라미터당 바이트 + KV 캐시. 동시 요청을 묶으면 가중치 읽기를 나눠 쓰므로 총 처리량은 늘고 1건 속도는 그대로다(Arm 학습 자료, 검색 요약).
- **메모리** ≈ 총 파라미터 × 파라미터당 바이트 + KV 캐시(2 × 층 수 × KV 헤드 × 헤드 차원 × 바이트 × 문맥 길이 × 동시 요청) + 여유 15% **[설계 가정]**.

**CPU 실측을 GPU로 그대로 옮기면 안 된다.** CPU와 GPU는 커널 효율(η)이 다르다. 실측 CPU 숫자는 **식이 맞는지 확인**하는 데만 쓴다.
1. CPU에서 `llama-bench`로 입력 처리(pp)와 출력 생성(tg) 속도를 따로 잰다(현재 하네스는 호출 전체 지연만 있다. EXAONE 2.4B: 호출당 입력 약 440, 출력 약 54토큰에 23초).
2. 같은 CPU의 실효 메모리 대역폭을 잰다(STREAM 같은 측정 도구).
3. tg 실측 ≈ η × 대역폭 / 모델 바이트 에서 CPU η를 구해 식이 ±30% 안에 맞는지 본다 **[설계 가정]**.
4. GPU는 공개 벤치마크의 η로 계산한다. 그리고 **같은 GPU를 몇 시간 빌려 합성 데이터로 하네스를 직접 돌려** 확정한다. 합성 데이터라 외부 GPU 사용이 정책에 맞는다. 이것이 가장 근거 있는 방법이다.

**예시(gpt-oss-120b, 80GB GPU 1장)**: MXFP4 가중치 약 60GB로 80GB 1장에 들어간다(여러 2차 출처). 활성 5.1B × 약 0.53바이트 ≈ 2.7GB/토큰. H100 PCIe 대역폭 2.0TB/s(공급사 목록, 검색 요약)면 1건 상한 약 740토큰/초. 실제 단일 요청 보고는 약 30~160토큰/초(Ori, 검색 요약). 부하 처리량 보고는 GPU당 수백~수천 토큰/초(Spheron 추정 약 700, SemiAnalysis 측정 약 9,000).
**필요량**: 하루 출력 115만 토큰, 그중 절반이 오전 4시간에 몰린다고 보면 **[설계 가정]** 평균 약 40토큰/초. 추론 토큰 2.5배를 넣어도 약 100토큰/초. **80GB 1장이면 처리량은 충분하다.** 제약은 처리량이 아니라 계획 호출 1건 지연이다(출력 500 × 2.5 = 1,250토큰 ÷ 100토큰/초 ≈ 12초). 사례당 10호출이 순서대로면 약 2분이므로 5분 주기는 지킨다. 실측으로 확인한다.

**읽는 법**
- 이 호출량에서는 원내가 외부 API보다 **비싸다**. 원내를 고르는 이유는 비용이 아니라 G1(보안)이다. 이 점을 숨기지 않고 적는다.
- 원내 안에서는 장비 등급이 비용을 계단처럼 올린다. 그래서 **관문을 넘는 가장 작은 등급**을 고르는 것이 비용 측면의 근거다.
- 병원이 이미 GPU 서버를 운영하면 장비비와 인력의 일부가 공유돼 한계 비용이 크게 줄어든다. 병원별로 다시 계산한다.

## 7. 한계

- 웹 원문을 직접 연 것은 Anthropic 블로그 2개와 Claude 문서 1개뿐이다. OpenAI, arXiv, AWS, Stanford는 이 환경에서 접속이 막혀 **검색 요약으로만** 판단했다. 특히 Bedrock 서울 제공 모델과 단가, 각 라이선스 원문, GPU 가격은 다시 확인해야 한다.
- 모델 이름과 단가(gpt-5.5, grok-4.7, Claude 5.5 세대 등)는 2차 출처나 설계 문서 값이다. 공급사 가격표로 다시 확인한다.
- TCO의 서버 본체가, L40S 가격, 인력, PUE, 감가 연수, 유지보수 비율은 **설계 가정**이다. 병원 견적과 실제 운영 인력으로 바꿔야 한다.
- 비열등 마진 5%p, 형식 실패 3%, ASR 5%, 질의 5초는 **설계 가정**이다. 추출 오류가 준비 시각과 사람 확인 횟수에 주는 영향(E3, H1)을 재생 평가로 잰 뒤 다시 정한다.
- 검정력 계산의 불일치 비율(ψ)은 지금 100문항에서 본 값이다. 400문항을 만든 뒤 다시 계산한다.
- 합성 문장은 실제 병동 메모보다 좁다. 선정 결과는 "합성 데이터 기준"이고, 실제 병원 도입 시 그 병원 원내에서 가명 데이터로 재검증해야 한다(개인정보위 안내서의 배포 전 점검).
- 의료기기 해당 여부(식약처), 공공병원의 클라우드 보안인증·국정원 보안성 검토, 국내 CSP 모델 서비스는 조사하지 않았거나 2차 자료만 봤다.
