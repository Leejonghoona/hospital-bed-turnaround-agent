**한계 (정직하게)**
- 첫 병원의 질문이 많다. 새 형식 첫 병원 질문 105개(열 69, 코드 34 등)다. 가짜 LLM(어휘 사전)이 낯선 열 이름을 모르기 때문이다. 같은 열 이름이 다시 나오는 두 번째 병원부터 답 재사용 사전으로 줄어든다(RESULTS "3단계 온보딩 학습 곡선").
- 결과는 **정답으로 답하는 사람 모형** 기준이다. 사람이 틀리게 답하는 경우는 아직 재지 않았다.
- 실제 EMR 표준 입력(HL7 ADT 메시지, FHIR Encounter)은 아직 받지 않는다. 내보내기 형식은 모두 합성이다.
- 같은 공급사 병원끼리 열 이름·코드가 같다는 것은 설계 가정이다.
- 실제 모델로 `emr_f`를 매핑하는 평가는 남았다.

## 1. 목표
"어느 병원이든 데이터만 넣으면 그 병원에 맞게 스스로 세팅된다." 병원 데이터를 받아 1단계 시스템이 쓰는 설정 파일을 자동으로 만들고, 사람이 확인할 차이만 보여 준다.

## 2. 입력과 출력

|---|---|---|

## 3. 에이전트 단계
1. **구조 읽기 (결정적)**: Location 번들을 내부 배치로. 빠진 속성(음압 여부, 공기순환 횟수)은 "확인 필요" 목록에 넣는다. 지어내지 않는다.
2. **분포 맞추기 (결정적)**: 과거 이벤트에서 단계별 소요시간을 로그정규로 맞춘다(중앙값, P90). 표본 수와 신뢰구간을 함께 낸다.
3. **규정 추출 (LLM, 추출만)**: 규정 문서에서 정해진 필드(환기 대기 분, 소아 기준 연령, 검토 사유 목록 등)만 뽑는다. 문장 근거(쪽, 문단)를 붙인다. 판단은 하지 않는다.
4. **문서와 실제의 차이 (결정적, POL-3)**: 규정 값과 이벤트에서 추정한 실제 운영 값을 나란히 보여 준다. 예: "문서상 퇴실 후 환기 120분, 실제 퇴실 → 청소 시작 중앙값 40분". 어느 쪽이 맞는지 시스템이 정하지 않는다.
5. **지침 대비 검사 (결정적, POL-2)**: 병원 값이 정부 지침의 금지 조항을 어기면 설정 생성을 멈춘다(예: 결핵 방 공유 허용). 조정 허용 값은 "지침 대비 단축/연장"으로 표시만 한다.
6. **사람 확인**: 확인 필요 목록과 차이 목록을 담당자(병상관리, 감염관리)에게 보여 주고, 확인된 값만 설정 파일에 쓴다. 확인 전 값은 출처 등급 `design_assumption`으로 남는다.
7. **그림자 운영 평가**: 생성한 설정으로 과거 이벤트를 재생해 1단계 지표(안전 0건, 회귀 시나리오, 추정 포함률)를 잰다. 지킬 선을 넘으면 설정을 쓰지 않는다.

## 4. 평가 (구현 전에 정할 합격선, 설계 가정)
- **설정 복원 시험**: 설정을 알고 있는 합성 병원 20곳(구조, 분포, 규정을 바꿔 생성)에서 온보딩 결과가 원래 설정을 얼마나 되찾는지. 구조 속성 정확 일치 100%(빠진 값은 "확인 필요"로 표시되면 정답), 분포 중앙값 오차 10% 이내.
- **지어내기 0건**: 입력에 없는 값을 확인 없이 설정에 쓴 건수.
- **금지 조항 차단 100%**: 금지 조항을 어기는 규정 문서를 넣으면 반드시 멈춘다.
- **사람 확인 부담**: 병원당 확인 항목 수. 줄이는 것이 목표지만 안전 항목은 줄이지 않는다.
