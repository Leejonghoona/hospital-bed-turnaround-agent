## 0. 결론 먼저

1. **U8 확장은 CLAUDE.md 2번과 맞을 수 있다. 조건은 셋이다.** (1) LLM은 열거된 행동 중 "무엇을 할지"만 고르고, 행동의 숫자(대기 시간, 수신자, 청소 유형, 병상)는 정책과 도구가 정한다. (2) **안전을 조이는 반응(청소 상향, 매칭 보류, 감염관리실 알림, 노출 병실 임시 보류)은 LLM 선택지가 아니라 결정적 코드의 의무 행동**이다. LLM이 이를 빼거나 늦출 수 없다. (3) 안전을 푸는 행동은 목록에 아예 없다. 이 셋이 없으면 "기다림"을 고르는 것만으로 안전 조치가 늦어진다(1.2절 위해 W-01).
2. **코드에서 실제 빈틈을 하나 확인했다.** 퇴실해서 일반 청소 요청이 나간 뒤 격리 오더가 들어오면, 사가는 청소를 종말소독으로 올리지 않고, 일반 청소 완료 신호로 빈 병상 전환(`BED_MARKED_VACANT`)을 낸다(작업 폴더에서 재현, 2.5절). 확정은 게이트웨이가 막지만 빈 병상 전환은 S2 정의 위반이고, 막힌 확정을 풀 종말소독 요청도 나가지 않는다. 늦은 양성 보상을 만들기 전에 고칠 곳이다.
3. **늦은 양성 결과에서 시스템이 "시작"하는 것은 없다.** 격리 시작, 병실 이동, 동실자 검사는 사람(주치의·감염관리실·병동)이 한다. 시스템이 할 일은 이미 내려진 배정·연락·청소에 그 결과가 닿는 곳을 찾아 막고, 되돌리고, 목록을 붙여 알리는 것이다. DECISIONS G의 "이동·침상 단위 격리·같은 병실 접촉자 관리를 시작한다"는 문장은 시스템이 하는 일로 읽히므로 주어를 고쳐 쓴다.
4. **다인실 격리 퇴실의 입실 가능 기준 "병실 전체 종말소독"은 실행할 수 없는 경우가 있다.** 같은 병실에 다른 환자가 있으면 병실 전체를 소독할 수 없다. 권고안은 퇴실 후 청소를 "병실 또는 침대 공간"으로 정의하고 다인실 환자 환경을 "개인 커튼 안"으로 둔다. 다인실 격리 퇴실은 "그 침대 구역 전파경로별 퇴실 후 청소 + 커튼 제거 + 공용 화장실·공용 다빈도 표면 소독"으로 고치는 안을 권한다(3절, 설계 가정, 사용자 확인 필요).
5. **당일 오전 확정과 오후 입실 사이가 길어진다.** 지금 재확인 두 번(제안, 확정 직전)은 그 사이를 보지 않는다. "배정 확정"과 "이동 가능(올려주세요)"을 나누고, **이동 가능 직전에 같은 재확인을 한 번 더** 두는 안을 권한다(4절, 사용자 확인 필요. 설계 문서의 "두 번"을 바꾸는 일이라 DECISIONS 먼저).
6. **통보형에서 병동의 침묵을 수용으로 보면 안전 확인이 사라진다.** 이의 제기 경로와 기한, 안전 사유 이의는 기한 뒤에도 받는 규칙이 필요하다.
7. **병실 이동 연쇄 표시는 사생활과 이동 압박 위험이 있다.** 변경 신청자만, 감시 대기·접촉주의·사후 처치·고위험 환자는 빼고, "가능성"으로만, 원무 병상관리 담당에게만 보인다(5절).
8. **지금 완전 자동 비율은 과대 보고될 수 있다.** 분모가 "확정된 입원"이라 사람에게 올라가 확정되지 못한 사례가 빠진다(`human_load.py`). 분모를 모든 사례로 바꾸고, 예외 유형별 "에이전트 자체 처리 비율"과 "사후 되돌림 비율"을 짝으로 보고한다(6.1절).
9. 새 안전 지표 둘: **S5 늦은 격리 정보 처리 누락 0건**, **S6 예외 행동 안전(제약을 푼 실행, 목록 밖 실행, 오래된 정보로 한 실행 0건)**. 홀드아웃 후보 21개를 6.3절에 적었다.
10. 리스크 R-48~R-61(14건), 가정 AS-E6~AS-E15(10건)를 제안한다(7절). 사용자 확인 질문 10개는 8절, 현직자 질문 8개는 9절.

## 1. U8 확장: LLM이 예외 행동을 고르고 게이트웨이가 검사한다

### 1.1 원칙 정합성 판정

| 원칙 | 판정 | 지키는 조건 |
|---|---|---|
| CLAUDE.md 2번(배정·숫자는 도구, LLM은 판단·설명·추출) | **조건부 맞음** | 행동 선택은 "판단"이다. 다만 행동에 딸린 값은 모두 결정적으로 정한다: 재확인 시각은 P90 도구값이나 정책값, 수신자는 정책의 역할·시간대 표, 청소 유형은 게이트웨이(GW-6), 병상은 규칙 1순위(U8 기존). LLM이 숫자 인자를 내면 게이트웨이가 무시하거나 거부한다. "안내 시각을 지킬 수 있는가"(지도)도 확률 계산은 도구가 하고 LLM은 그 결과를 읽어 행동을 고른다 |
| CLAUDE.md 3번(교체 가능, 기본 가짜 LLM) | 맞음 | 가짜 LLM은 예외 유형별 규칙 기본 행동(1.5절 표)을 그대로 낸다. 그래서 규칙 모드 = 가짜 LLM = 장애 대체 경로가 같은 표를 쓴다 |
| CLAUDE.md 4번(청소·이송 인력 배정 범위 밖) | **주의** | "침상 정리를 먼저 해 달라"(지도)는 사람을 지정하지 않고 기존 예정표에 **우선 표시**를 붙이는 것으로만 한다. 특정 직원 호출, 순서 재배치, 담당 지정은 인력 배정이라 하지 않는다 |
| CLAUDE.md 5번(설계 항목 구현 안 함) | 주의 | 원내 전동(GW-15), 입실 안내 자동 발송은 "설계"다. 행동 목록에 "재원 환자 이동", "환자 연락 발송"을 넣지 않는다. 연락은 **초안까지만** |
| SEC-1(운영 LLM 원내) | 맞음 | 행동 선택 LLM은 계획 에이전트와 같은 원내 모델. 입력에 병원체 이름이 꼭 필요하지 않다. 주의 종류(접촉·비말·공기)와 사건 종류만 넣는 쪽이 최소화에 맞다 |
| SEC-2(외부 업체에는 병상·시각·청소 유형만) | 맞음, 보강 | 청소 상향·재요청 문구도 같은 필드만. 다만 **청소 직원 보호에 필요한 표시(N95 필요, 아포 소독)는 반드시 실린다**(현장 불만 "격리 정보를 공유받지 못하고 청소", 감염관리_청소_실무 3-3) |
| SEC-3(자유 서술은 추출 필드만, 정책 판단 제외) | **보강 필요** | 행동 선택 입력에서 자유 서술 원문을 빼는 것만으로는 부족하다. (1) 추출 필드는 출처 표시를 달고, 추출 필드만으로는 안전을 푸는 방향의 어떤 행동도 고를 수 없다. (2) **LLM이 쓴 근거 문장(검토 카드 설명)도 인젝션 통로**다. 기록에 없는 사실("감염관리실 승인 완료", "격리 해제됨")을 사람에게 보여 주면 사람이 속는다. 설명이 인용한 이벤트 순번을 게이트웨이가 확인하고, 확인되지 않는 주장이 있으면 규칙 근거 문장으로 바꾼다 |

| W-10 | 수신자 오류 | 야간에 감염관리실 주간 담당에게 보냄, 원무에게 임상 판단을 보냄(R-41) | LLM이 수신자를 고름 | LLM은 사유 코드만 내고, 수신자는 정책의 역할·시간대 표(SAG-8)가 정함 |
| W-11 | 비결정성 | 같은 상황에 다른 행동 → 담당 신뢰 하락 | 온도 고정 불가 모델(Claude 5 계열 기록) | 반복 일관성 측정, 불일치 유형은 규칙 기본 행동으로 고정 |
| W-12 | 되돌릴 수 없는 행동 혼입 | 연락 초안이 그대로 발송되는 연동 | 연동 설정 실수 | 발송·확정·안전 예외는 게이트웨이에 실행 경로 자체가 없음(사람 이벤트로만 들어옴) |

### 1.3 행동 목록, 행동별 게이트웨이 검사, 자율 기본값

"자율 기본값"은 1단계(지금) 기본이다. 자동 = 사람 없이 실행, 사후 보고 = 실행하고 그날 목록에 남김(되돌리기 가능), 사람 승인 = 실행 전 승인. 정당화는 "되돌릴 수 있는가, 누구에게 부담이 가는가, 틀리면 무엇이 다치는가"로 판단했다. 값은 모두 설계 가정이다.

| 행동 | 누가 고르나 | 게이트웨이 검사 | 다시 볼 사건(오래된 정보) | 자율 기본값 | 이유 |
|---|---|---|---|---|---|
| **안전 의무 반응** (청소 종말소독 상향·추가 소독 요청, 걸린 매칭 보류·재분류, 감염관리실 알림, 노출 병실 신규 배정 임시 보류) | **결정적 코드**(LLM 선택 아님) | 트리거가 오더·결과 이벤트인지, 멱등 키, 감사 | 해당 없음(조이는 방향은 즉시) | 자동, 해제는 사람 | EVT-4 "조이는 정정은 즉시". 빠지면 S2·S5 위반 |
| 기다림 + 재확인 시각 | LLM | 재확인 시각은 도구값(P90)·정책값만, 연속 상한, 마감 초과 거부, 안전 의무 반응이 미완이면 기다림만 단독 선택 거부 | 기다리는 그 사건의 완료 신호 | 자동 | 되돌릴 일이 없음. 단 상한이 없으면 W-01 |
| 청소 재요청(독촉) | LLM | 청소 요청이 있고 시작·완료 신호가 없음, 같은 요청 재요청 간격·횟수 상한, 유형은 게이트웨이가 다시 붙임(하향 불가), SEC-2 필드 | `CLEANING_STARTED`, `CLEANING_DONE`, 퇴원 취소 | 자동 | 기존 자동 등급(`send_cleaning_request`)의 연장. 미화 쪽 피로만 상한으로 막음 |
| 침상 정리 우선 표시 | LLM | 격리 퇴실 병상은 전파경로별 청소 완료 전 **거부**(새 리넨 오염), 병동별 근무조 상한, 사람 지정 금지(4번) | `BED_READY`, 청소 유형 변경 | **사후 보고** | 병동 보조 부담이 직접 늘어남. 효과 확인 전 |
| 재매칭 요청(병상은 규칙이 고름) | LLM이 "재매칭할지" | 새 매칭은 기존 검사 전부(SHACL, 확인 등급, 재확인 2회), 이득 기준값, 연락 뒤 거부(목표 함수 2항), 병동 통보 뒤면 사람 승인 | `PATIENT_CONTACTED`, `WARD_NOTIFIED`, 격리 오더, 퇴원·입원 취소 | 연락·통보 전: 사후 보고 / 통보 뒤: 사람 승인 / 연락 뒤: 불가 | 통보 뒤 바꾸면 병동 준비를 버리게 함 |
| 보상 실행(예정표·사전 매칭 해제, 시작 전 일반 청소 요청 취소) | 결정적 사가(지금대로) | **종말소독 요청 취소는 거부**(사람), 연락 뒤 해제는 담당 검토로(SAG-4) | 취소 철회, 재결정 | 자동 | 이미 구현된 결정적 경로. LLM이 건너뛸 수 없어야 함 |
| 담당자에게 올림 | LLM(사유 코드), 수신자는 정책 | 사유 코드가 목록 안, 수신자는 역할·시간대 표, 같은 사유 중복 제거 | 문제가 풀렸는지 | 자동(언제나 허용) | 안전 쪽 기본. 막으면 안 됨 |
| 병동 정보 공유(예상 시각 변경 등) | LLM | 템플릿 문구, 등급(운영), 상한, 교대 보류 | 예상 시각 재계산 | 자동 | 정보성. 피로만 관리 |
| 다음 교대 인계 | 결정적(SAG-8) | 기존 | 기존 | 자동 | 기존 |
| 환자 연락 초안 넘김 | LLM | 초안만, 발송 경로 없음, 문안의 시각·병실은 도구값, 원무 큐로 | 매칭 변경, 취소 | 초안 자동, **발송은 사람** | 되돌릴 수 없는 분기점 |
| 보호자 사정 확인 요청(퇴원일 변경 가능성) | LLM | 추출 필드 근거 순번 필수, 퇴원일 변경 확정 행동은 없음, 병동 상한 | 보호자 도착, 퇴원 결정 변경 | 사후 보고 | 퇴원일 변경은 의료진·병동 결정 |

**절대 자동으로 하지 않는 것**(행동 목록에 넣지 않는다):

1. 환자·보호자 연락 발송(초안까지만).
2. HIS 공식 확정, 입실 이동 지시.
3. 안전 규칙 예외 승인(GW-10 사전 승인·사유 입력), 직접 수정, 고정 해제.
4. 격리 시작·해제·종류 결정, 선제 격리 여부, 1인실/다인실 접촉주의 선택.
5. 재원 환자 병실 이동(전실) 실행·순서 결정.
6. 종말소독 요청 취소·하향, 환기 대기 단축, 아포 소독 표시 제거.
7. 노출 병실 임시 보류·`surveillance_hold`·병실 사용 중지의 해제.
8. 퇴원일 변경·퇴원 보류 확정, 입원 연기 결정.
9. 병동 이의 기각, 수용 거절된 병상으로의 재제안.
10. 자율 단계 승격과 정책 변경.

## 2. 늦게 온 양성 격리 결과의 보상

### 2.1 현실의 절차 (누가 무엇을)

입원 선별검사(예: CRE·VRE 배양)는 결과가 입원 뒤에 나온다. 소요일 "보통 2~3일"은 DECISIONS에 근거 확인 대상으로 적혀 있고 이번에도 확인하지 못했다(설계 가정).

| 순서 | 무엇 | 누가 | 근거 |
|---|---|---|---|
| 1 | 결과 보고, EMR 감염 정보 등록(자동 또는 수동) | 검사실 → EMR, 감염관리실 | QIH 2022(전산 등록률 개선 전 53%) |
| 2 | 격리 오더·격리 종류 결정 | 주치의 또는 감염관리실(병원 규정). 격리실 우선순위는 감염관리실무자 | 표준예방지침 부록 1 A 5.2.1 |
| 3 | **현재 자리에서 즉시 접촉주의**(커튼, 1m 이상, 차단막, 보호구, 표지) | 병동 간호사, 책임간호사 보고 | 5.3.2.4, 5.3.2.6, 현장 블로그 1-2·1-3 |
| 4 | 1인실·코호트 자리가 나면 이동. 안 나면 제자리 유지 | 병동 책임간호사 + 감염관리실 판단, 원무는 병실료(격리실료) | 5.3.2.1~5.3.2.4. CRE는 "가장 우선적으로 가능한 한 1인실"(부록 1 A 5.2.1). 이동 처리 주체는 [추정] |
| 5 | 동실자 선별검사, 결과 때까지 임시 코호트, 병실 이동 제한, **새 환자 입원 제한 필요성 검토** | 감염관리실 지시, 병동 시행 | 경기도 안내 41쪽(2023 지침 인용) 2-1·5번, 부록 1 A 8.3.4 |
| 6 | 원래 침대 구역 퇴실 후 청소(전파경로별), 접촉주의 병실 청소 빈도 증가 | 미화·병동, 감염관리 기준 | 권고안 3.4.6.1, 표준예방지침 5.3.6.1, 5.3.7.2 |
| 7 | 법정 신고(CRE 등) | 감염관리실 | 범위 밖 |
| 8 | 퇴원한 동실자 후속(재입원 시 선별 표시 등) | 감염관리실 | 근거 미확인, 설계 가정 |

### 2.2 시스템이 하는 것 / 제안하는 것 / 사람에게 남기는 것

| 구분 | 내용 |
|---|---|
| **자동(결정적, 의무)** | ① 그 환자·그 병상·같은 병실에 걸린 진행 중 제안·사전 매칭·확정 대기를 막고 담당 검토로 재분류(GW-1·9 확장). ② 퇴실했고 아직 다음 환자가 들어오지 않은 병상이면 청소 유형을 전파경로별로 **상향**하고, 이미 일반 청소가 시작·완료됐으면 **추가 소독 요청**. 빈 병상 전환과 확정은 그 완료 신호 뒤로. ③ 감염관리실 알림: 영향 목록(걸린 매칭, 연락 여부, 같은 병실 재원 환자 수와 퇴원 예정, 이미 퇴원한 동실자 수, 청소 상태). ④ (정책이 켜면) 노출 병실의 남은 빈 병상에 **새 환자 배정 임시 보류**(해제는 감염관리실). |
| **제안(사람 승인)** | 1인실·코호트 후보 병상(규칙이 계산, 이동은 사람이 결정), 재매칭 후보(규칙 2개), 환자 재연락 초안 |
| **사람에게만** | 격리 시작·종류, 병실 이동 여부와 시점, 동실자 검사 범위, 임시 보류 해제, 접촉자 퇴원 전 검사, 신고, 위양성 판정과 해제 |

격리 판단은 오더 값만 쓴다는 LP-19는 그대로다. 결과만 있고 오더가 없으면 ③ 알림만 낸다(DECISIONS "격리 정보 처리 정정"). 다만 그 환자가 그 사이 퇴실하면 청소를 어떻게 할지는 정해져 있지 않다. 8절 Q6.

### 2.3 시점별 분기

| 결과가 닿는 시점 | 시스템 동작 | 사람 |
|---|---|---|
| 입원 대기, 사전 매칭만(연락 전) | 매칭 보류, 담당 검토 재분류, 규칙이 격리 조건으로 후보 재계산 | 병상관리 담당 |
| 연락 뒤, 확정 전 | 위 + 재연락 초안(발송 안 함) | 원무 재연락 |
| 확정 뒤, 입실 전(당일 오전 배정에서 길어짐) | 입실 이동 차단(4절 세 번째 재확인), 병동·원무 통지 | 담당 검토, 병동 |
| 입실 뒤, 1인실 | 병상 운영 영향 없음. 퇴실 때 청소 유형이 자동 종말소독 | 병동·감염관리실 |
| 입실 뒤, 다인실 | 감염관리실 알림(동실자 목록 수), 같은 병실 빈 병상의 사전 매칭 보류, 임시 보류(정책), 동실자 퇴원 사례 표시 | 격리·이동·검사 전부 |
| 퇴실 뒤, 청소 요청 전·시작 전 | 청소 요청을 전파경로별로 바꿔 재발행 | - |
| 퇴실 뒤, 일반 청소 중·완료 뒤, 빈 병상 전환 전 | 추가 소독 요청, 전환·확정 차단, 걸린 사전 매칭 보류 | 미화·감염관리 |
| 퇴실 뒤, 이미 빈 병상 전환·다음 환자 배정 | 확정 전이면 차단 + 추가 소독. 확정 뒤 입실 전이면 입실 이동 차단 | 담당 검토 |
| 퇴실 뒤, 다음 환자 이미 입실 | **소독 요청을 내지 않는다**(점유 중). 감염관리실 알림 "새 환자 노출 가능". 자동 이동 없음 | 감염관리실 판단 |

### 2.4 경계 사례

| 사례 | 위험 | 권고 |
|---|---|---|
| **결과가 야간에 옴** | 감염관리실 부재, 응급 입원이 노출 병실로 감 | 병동 즉시 제자리 접촉주의는 원래 병동 권한이라 시스템과 무관. 알림은 야간 대행 역할(AS-A7, 설계 가정)과 다음 근무 시작 큐에 동시. 임시 보류가 켜져 있으면 야간 응급 배정은 그 병실을 피함(용량 손실은 R-60) |
| **환자가 이미 퇴원** | 그 병상과 동실자가 노출된 채 운영 | 2.3 표 "퇴실 뒤" 행. 퇴원 사례에는 격리 오더가 다시 붙지 않을 수 있다(진료 종료). 그래서 트리거를 "격리 오더"뿐 아니라 "퇴원 뒤 양성 결과 등록" 이벤트로도 받아야 한다. 이 이벤트가 HIS에서 오는지는 미확인(AS-E6) |
| **동실자도 오늘 퇴원** | 접촉자가 검사 없이 나감, 그 병상 청소 유형 | 퇴원은 막지 않는다(의료진 결정). 감염관리실 작업 "퇴원 전 접촉자 검사 필요 여부". 동실자 퇴실 청소 유형은 정책값(기본 일반 + 감염관리 확인 표시, 설계 가정). 그 병상에 걸린 사전 매칭은 임시 보류 대상 |
| **동실자가 이미 퇴원** | 추적 누락 | 감염관리실 알림에 "이미 퇴원한 동실자 수"만(이름은 감염관리실 화면에서 HIS로). 재입원 표시는 범위 밖 |
| **같은 병실 다른 빈 병상** | 노출 병실에 새 환자 | 임시 보류(정책) 또는 최소한 사전 매칭 보류와 담당 검토. 지침은 "입원 제한 필요성을 검토"이므로 자동 금지가 아니라 **보류 후 사람 결정**이 지침 문구에 맞다 |
| **결핵이 다인실에서 늦게 진단** | 공기 노출, 방 공유 금지(5.5.2.4), 청소 직원 노출 | 다인실 전체 노출자 관리. 환기 대기는 병실 공기순환 기준(AS-B2, 설계 가정). 알림에 "청소 완료 직원 노출 가능"을 넣어 감염관리실이 직원 노출 평가를 할 수 있게(직원 정보는 싣지 않음) |
| **C. difficile, 공용 화장실** | 아포가 공용 화장실에 남음 | 다인실이면 공용 화장실 아포 소독(권고안 1.4.2.5 5,000ppm, 조사 원문) 표시 |
| **위양성·검체 오류 정정, 격리 해제** | 제약이 풀림 | 푸는 방향은 사람 확인 뒤에만(EVT-4). 임시 보류도 자동 해제하지 않음 |
| **같은 결과가 두 번 옴(재전송)** | 보상 중복, 알림 중복 | 결과 ID 멱등 키 |
| **결과가 확정 직전 재확인과 같은 분에 옴** | 경쟁 | 인지 시각 기준. 확정 뒤 인지면 입실 이동 재확인이 잡음 |

### 2.5 코드에서 확인한 빈틈 (구현 전 고칠 것)

작업 폴더의 시험 스크립트(`test_saga.py` 도우미 재사용)로 다음을 재현했다. 퇴원 결정은 격리 없음 → 11:00 퇴실 → 11:40 VRE 격리 오더 → 12:30 일반 청소 완료 → 12:40 침상 준비.

```
11:00 cleaning_request_issued {'cleaning_type': 'general'}
12:30 ready_time_recomputed {'reason': 'cleaning_done'}
12:40 bed_marked_vacant {}
```

- 원인(`src/turnaround/saga/machine.py` 397~416행): 청소 요청은 멱등 키 `cleaning_request` 하나라 오더가 늦게 오면 다시 내지 않는다. 빈 병상 전환 조건 `done is not None or not d.isolation`은 완료 신호의 `cleaning_type`을 보지 않는다.
- 결과: 빈 병상 전환이 일반 청소로 나간다(평가표 S2 "소독 확인 전 빈 병상 전환"). 게이트웨이 `_isolation_discharge_pending`은 종말소독 완료를 보므로 확정은 막지만, 종말소독 요청이 나가지 않아 그 확정은 사람이 끼기 전까지 풀리지 않는다.
- 권고: ① 청소 상향 요청을 별도 멱등 키(`cleaning_upgrade`)로 낸다. ② 빈 병상 전환은 "알고 있는 격리 상태에 맞는 유형의 완료 신호"를 요구한다. ③ 이미 빈 병상 전환이 나간 뒤 격리를 알면 그 전환을 무효로 보는 이벤트(예: 병상 재오염 표시, HL7 상태 `K`)를 둔다. 테스트를 먼저 쓴다.
- 지금 실행 S2(0/58)는 이 경로가 합성 데이터에 없어서 잡히지 않았다. 합성 생성기에 "퇴실 뒤 격리 오더" 잡음을 넣으면 드러난다.

### 3.2 두 갈래 청소의 안전 조건

1. **입실 가능 = 모든 켜진 갈래의 완료(AND).** 병동 침상 준비 완료, 미화 완료(병원 설정으로 켜진 경우), 격리면 전파경로별 청소 완료, 환기 대기 경과. 한 신호만으로 입실 가능을 내지 않는다(R-45).
2. **격리 퇴실에서는 순서가 있다.** 신환 침상 준비(새 리넨)는 전파경로별 소독 뒤여야 한다. 먼저 깔면 새 리넨이 오염된다. 그래서 "침상 정리 먼저" 우선 표시는 격리 병상에서 거부한다(1.3절). 격리 퇴실의 리넨 제거는 병동 쪽 일이라도 보호구와 커튼 제거가 따른다(부록 4-3-2).
3. **청결도 확인 단계가 있는 병원**(청소 → 확인 → 불합격 재청소 → 추가 소독, DECISIONS 청소 항목)은 확인 합격 신호를 완료로 본다. 청소 완료 신호만으로 S2를 판정하지 않는다.
4. **완료 신호의 병상·유형 대조.** 완료 신호의 병상 번호와 청소 유형이 요청과 다르면 완료로 보지 않고 사람 작업(지금 2.5절 빈틈의 일반형).
5. **환기 대기 방식(`ventilation.mode`, 종합 15번).** "보호구 착용 후 대기 중 청소"를 켜도 입실 가능 시각은 `퇴실 + 비움 시간` 아래로 내려가지 않는다. 결핵 60분은 "재사용 전 비움"의 하한이다. 대기 중 청소는 청소 직원 N95 착용을 전제로 하므로 청소 요청에 그 표시가 반드시 실린다.
6. **미화 단계를 끈 병원**에서도 격리 퇴실 소독은 끌 수 없다(누가 하든 완료 신호는 필요).
7. 용어: 화면은 "격리 퇴실 소독(전파경로별 퇴실 후 청소)"으로 쓴다. 현직자는 일반 퇴실 청소도 "종말소독"이라 부를 수 있다(종합 16번). 코드 값 `terminal`은 그대로.

### 6.1 완전 자동 비율을 정직하게 재는 법

지금 정의(`src/turnaround/evaluation/human_load.py`): "판단 개입 없이 확정된 입원 사례 / 확정된 입원 사례". 책임 개입은 공식 확정, 병동 수용 회신, 환자 연락.

| 문제 | 영향 | 권고 |
|---|---|---|
| 분모가 확정된 사례뿐 | 사람에게 올라가 확정되지 못한 사례(병상 없음, 입원 연기)가 빠져 비율이 올라감(생존 편향) | 분모 = 모든 입원 사례. 미확정은 비자동. 따로 "확정률"을 보고 |
| 퇴원·청소 쪽 예외가 안 잡힘 | 청소 지연, 보호자 변경, 늦은 결과는 퇴원 사례에서 생김 | 단위를 둘로: 입원 사례, **예외 일화**(사례 안의 예외 하나). 예외 유형별 "에이전트 자체 처리 비율" |
| 병동 회신 = 책임 개입 | 통보형에서는 회신이 없고 이의가 생김 | 회신형의 수용 회신은 책임, **병동 이의는 판단 개입** |
| 사후 보고의 사람 손 | 사후 보고를 사람이 되돌리면 자동이 아님 | "사후 되돌림 비율"을 자동 비율과 짝으로. 되돌린 사례는 비자동 |
| 사람 작업 생성만 하고 처리 안 됨 | 처리 이벤트만 세면 부담이 숨음 | 생성된 사람 작업·알림 수(근무조·병동별)를 따로 |
| 시스템 밖 전화 | 측정 불가 | "시스템 기록 기준"으로 명시. 합성 재생의 사람 흉내 응답 규칙을 결과와 함께 공개 |
| 올림을 줄이면 비율이 오름 | 지표 맞추기 | **잘못된 자동(정답은 사람인데 자동 처리) 비율**을 함께. 안전 유형은 0건이 조건 |
| 책임 순간 정의 | 엔드픽처의 세 순간 | 책임 개입 = HIS 공식 확정, 환자 연락 발송, 안전 예외 승인(GW-10), 회신형 수용 회신. 격리 오더 같은 임상 결정은 시스템 밖이라 세지 않음 |

보고 형식(제안): 완전 자동 비율(모든 사례 분모), 책임 순간 외 개입 0인 사례 비율, 예외 유형별 자체 처리 비율 · 사후 되돌림 비율 · 잘못된 자동 비율, 근무조당 알림·작업 수. 기존 값(0~27%)은 분모를 바꿔 다시 내고 이전 값과 나란히 적는다(8절 Q7).

## 8. 사용자 확인 필요

1. **Q1. 안전 의무 반응을 LLM 선택지에서 빼고 결정적 코드로 둘까요?** 청소 상향, 매칭 보류, 감염관리실 알림, 임시 보류는 LLM이 고르지 않고 언제나 실행되며, LLM은 그 밖의 운영 행동만 고릅니다. (권고: 예)
2. **Q2. 늦은 양성 뒤 노출 병실의 남은 빈 병상에 새 환자 배정을 자동 임시 보류할까요, 알림만 할까요?** 지침은 "입원 제한 필요성을 검토"입니다. 보류하면 병상이 줄고, 알림만 하면 노출 병실에 새 환자가 갈 수 있습니다. (권고: 임시 보류 + 감염관리실 해제, 설계 가정으로 표시)
3. **Q3. 다인실 격리 퇴실 기준을 "병실 전체"에서 "그 침대 구역 + 공용 화장실·공용 표면"으로 고칠까요?** 같은 병실에 다른 환자가 있으면 병실 전체 소독은 할 수 없습니다.
4. **Q4. 이동 가능 직전에 세 번째 재확인을 둘까요?** 당일 오전 확정과 오후 입실 사이 정보 변경을 보려는 것입니다. 설계 문서의 "두 번 재확인"을 바꾸는 일입니다. 대안은 "확정 직전" 재확인을 "이동 가능 직전"으로 옮기는 것입니다.
5. **Q5. 통보형에서 병동이 기한 안에 말이 없으면 수용으로 볼까요?** 안전 사유 이의는 기한 뒤에도 받아 입실을 멈추는 것을 함께 권합니다.
6. **Q6. 양성 결과는 있는데 격리 오더가 없는 채 환자가 퇴실하면, 청소만은 격리 퇴실 소독으로 올릴까요?** 격리 판단은 오더 값만 쓴다(LP-19)는 원칙의 좁은 예외입니다. 올리지 않으면 감염관리실 알림만 남습니다.
7. **Q7. 완전 자동 비율의 분모를 "확정된 입원"에서 "모든 사례"로 바꾸고 기존 값(0~27%)을 다시 낼까요?**
8. **Q8. 이동 연쇄 표시를 누가 볼까요?** 권고는 원무 병상관리 담당 전체, 병동은 자기 병동 연쇄 수만입니다.
9. **Q9. 1.3절의 행동별 자율 기본값(특히 재매칭 사후 보고, 침상 정리 우선 표시 사후 보고)을 승인하실까요?**
10. **Q10. DECISIONS G의 "이동·침상 단위 격리·접촉자 관리를 시작한다"를 "사람이 시작한 조치에 맞춰 배정·연락·청소를 보상하고 감염관리실에 영향 목록을 올린다"로 고쳐 적을까요?**
